# План: именованные аргументы

Черновик реализации. Живёт в корне, а не в `docs/`, потому что `docs/` описывает то,
что уже работает; сюда же записаны причины решений, чтобы их не пришлось восстанавливать
по коду. Когда работа закончится, содержательная часть переедет в
[docs/functions.md](docs/functions.md), а этот файл уйдёт.

> **Состояние на 15 августа 2026: этапы 1–5 выполнены.** Именованные аргументы работают
> у функций, методов, `new` и заголовка родителя; из встроенных модулей имена объявил
> `sys.gui`, остальные остаются позиционными. Описание переехало
> в [docs/functions.md](docs/functions.md#именованные-аргументы) — здесь остаются
> причины решений и то, что сознательно не делалось.

## Зачем

Сегодня аргумент передаётся только позицией. Отсюда три следствия, каждое из которых
мешает по-своему:

* **пропуск в середине списка записать нечем.** У `def greet(name, greeting = "привет",
  punct = "!")` нельзя задать `punct`, не повторив `greeting`;
* **вызов нечитаем там, где параметров больше двух.** `gui.grid(2, 3, 4, 4)` не говорит
  ничего: какие из чисел — размер сетки, какие — зазоры;
* **язык вынужден запрещать обязательный параметр после необязательного**, и обоснование
  этого запрета прямо ссылается на отсутствие именованных аргументов
  ([docs/functions.md](docs/functions.md), `parser/TypeParser.java`).

Задача, которую документация до сих пор называла дорогой, — в том, что для раскладки
имён по позициям **имена параметров нужны у любого вызываемого**, включая встроенные
функции. Иначе своя и встроенная функции перестанут быть одинаковыми значениями,
а на этом равенстве держатся вызов и функции высшего порядка. Отсюда центральное
решение: у `FunctionValue` и `ClassValue` появляется `Signature` — полный контракт
вызова (имена, обязательность и место под будущий тип), а не одна лишь `Arity`.

Итог работы: `f(name: value)` работает для функций на wdl, классов (`new`), заголовка
родителя, встроенных классов и модуля `sys.gui`.

## Чего в этой работе нет

Типизации (`def f(x is int)`), раскрытия объекта в аргументы (`f(...opts)`),
переменного числа аргументов и обязательно-именованных параметров. Но `Signature`
вводится так, чтобы **типы добавлялись, не меняя ни одного места вызова**: параметры
собираются фабриками, а не конструктором `record`, а порядок проверок в связывателе
записан списком, четвёртым пунктом которого станет проверка типа.

## Синтаксис

```wdl
def greet(name, greeting = "привет", punct = "!") => greeting + ", " + name + punct

greet("мир")                                // как раньше
greet("мир", punct: "?")                    // пропуск в середине — ради этого всё
greet(name: "мир", greeting: "здравствуй")  // порядок свободный
new Point(y: 3, x: 1)
class Circle(r) : Shape(radius: r)
```

**Двоеточие, а не `=`.** Три причины, в порядке весомости:

1. `=` внутри выражения в языке не значит ничего, и это сознательно: присваивание —
   инструкция, поэтому `if (x = 5)` не разбирается в принципе. Именованный аргумент
   через `=` завёл бы единственное место, где `=` в позиции выражения что-то значит, —
   ровно ту форму, от которой язык отказался;
2. согласовано с ключом объекта: `{name: value}` и `f(name: value)` — один приём записи
   «имя → значение» на весь язык;
3. разбор однозначен на два токена вперёд: выражение никогда не начинается с `WORD :`.
   Двоеточие встречается после `?` в тернарнике, внутри `{}` в объекте и после заголовка
   класса — ни одна из этих позиций не является началом аргумента, откат не нужен.

Двоеточие при этом **не занимается под типы**: будущая типизация пойдёт словом `is`
(`def f(x is int)`) — так же, как она уже записана в `catch (e is IoError)`. Тогда
`:` навсегда значит «вот значение для этого имени», а `is` — «это значение такого типа».

## Правила

* **П1. Позиционные — только до первого именованного.** `greet(punct: "?", "мир")` —
  ошибка разбора. Позиция аргумента и есть его номер; после того как порядок нарушен,
  «третий по счёту» ничего не значит. Ослабить до свободного порядка можно позже,
  обратной несовместимости это не создаст.
* **П2. Одно имя дважды в одном вызове — ошибка разбора.** Оба вхождения видны
  в тексте, ждать выполнения незачем.
* **П3. Имя, уже занятое позиционным аргументом, — ошибка выполнения.** Какая позиция
  у параметра, известно только от вычисленного вызываемого.
* Именем может быть только `WORD`. Ключевые слова, которые разрешены ключом объекта,
  здесь запрещены: параметр ключевым словом называться не может.
* **Правило «обязательный после необязательного» остаётся**, но обоснование меняется:
  не «пропуск нечем записать», а «позиционный вызов должен читаться по префиксу списка
  параметров». Иначе `def f(a = 1, b)` вызывается только именованно, а `f(1)` — либо
  ошибка, либо тихая догадка, куда пошла единица.
* **Аргументы вычисляются в порядке записи в тексте**, раскладка по позициям — после.
  Побочные эффекты идут так, как читается строка.
* **Значения по умолчанию — после всех переданных, по параметрам слева направо.**
  Поэтому действующее правило «дефолт видит параметры слева» продолжает выполняться
  и при дырке: `total(100, tax: 0)` сначала считает дефолт `count`, потом видит
  уже переданный `tax`.

## Гарантия совместимости

**Вызов без единого имени идёт прежним путём** — тот же список аргументов, та же
проверка `Arity`, то же сообщение об ошибке, никакой подстановки значений по умолчанию
снаружи функции. Ни одна существующая функция и ни один тест поведения не меняются.

Это не вежливость, а необходимость: тела встроенных функций определяют «аргумент
не передан» по длине списка (`arguments.size() > 1` в `stdlib/gui/Gui.java`,
`args.size() > 1` в `gui/NativeWindow.java`, `args.has(0)` в `stdlib/Files.java`).
Подстановка дефолта снаружи на позиционном пути молча поменяла бы их поведение.

## Этап 1. `Signature` и `Arguments` — контракт вызова

Поведение языка не меняется; этап готовит место.

`value/Signature.java` — контракт вызова:

```java
public final class Signature {
    public static final class Param {          // фабрики, а не конструктор record:
        public static Param required(String name);                 // добавление типа
        public static Param optional(String name, Value constant); // позже не тронет
        public static Param lazy(String name);                     // ни один call-site
    }
    public static Signature of(Param... params);
    public static Signature positional(Arity arity);   // имена неизвестны
    public boolean namesKnown();
    public int indexOf(String name);                   // -1, если нет такого параметра
    public Arity arity();                              // выводится из состава
    public List<Param> params();
}
```

Три состояния параметра — не выдумка, все три уже есть в коде:

| Состояние | Кто такой | Кто заполняет пропуск |
|---|---|---|
| `required` | обязательный | никто, это ошибка вызова |
| `optional` | готовое значение: поля `NativeClass`, необязательные аргументы stdlib | связыватель |
| `lazy` | выражение, считается в области вызова: функции и классы на wdl | сам вызываемый |

`value/Arguments.java` — результат раскладки: значения по позициям плюс маска
«передан». Маска нужна только из-за `lazy`: у пропущенного параметра значения ещё нет,
и вычислить его может лишь сам вызываемый.

```java
public final class Arguments {                 // неизменяем, как всё в value
    public static Arguments positional(List<Value> values);   // все переданы
    public boolean has(int index);
    public Value get(int index);
    public int size();
    public List<Value> asList();               // для тех, кто про пропуски не знает
}
```

`value/FunctionValue.java` и `value/ClassValue.java` получают по два `default`-метода:

```java
default Signature signature() { return Signature.positional(arity()); }
default Value call(CallContext ctx, Arguments args, Span span) {
    return call(ctx, args.asList(), span);
}
```

**В этом вся миграция.** Реализации `FunctionValue` из приложений компилируются без
единой правки и просто не принимают имён — с честным сообщением. Пропуск до них дойти
не может: он возникает только у `lazy`-параметра, а `lazy` бывает лишь у тех, кто
объявил имена и переопределил широкий вызов.

## Этап 2. Дерево и разбор

`ast/expr/Argument.java` — новый `record`: `(String name, Span nameSpan, Expr value)`
плюс `isNamed()` и `span()`.

**Именованный аргумент — не выражение**, и это то же решение, что «присваивание —
инструкция»: `g(x: 1) + 1` осмысленно только непосредственно в списке аргументов.
Будь это `Expr`, запрет пришлось бы писать проверкой в каждом посетителе; отдельный
тип запрещает по построению.

Меняют тип с `List<Expr>` на `List<Argument>`: `ast/expr/CallExpr.java`,
`ast/expr/NewExpr.java`, `ClassDeclStmt.Superclass.arguments`.

Разбор — правка **одного** метода, `Parser.argumentList`: он общий для вызова, `new`
и заголовка родителя, поэтому единое правило достаётся всем трём бесплатно.
Распознавание — `peek()` = `WORD` и `peek(1)` = `COLON`, та же двухтокенная проверка,
что в `Parser.objectKey`. Там же диагностики П1 и П2 — обе через `diagnostics.error`,
без прерывания разбора: дерево возвращается всегда.

Дальше компилятор проведёт по всем местам сам: `parser/DefaultValues.findUse` (обход
идёт по `argument.value()`), `tools/AstDumper`, тестовый `SExprPrinter`. Форма печати
дерева — по образцу объекта (`(object ("k" 1))`):

```
greet("мир", punct: "?")  →  (call greet "мир" (punct: "?"))
```

## Этап 3. Связывание и выполнение

`runtime/Binder.java` — единственное место раскладки. Порядок проверок записан
списком в javadoc, потому что позже сюда встанет проверка типа четвёртым шагом:

1. имя → позиция (`Signature.indexOf`); нет такого параметра — ошибка;
2. позиция уже занята позиционным аргументом — ошибка (П3);
3. незаполненная позиция: `lazy` — оставить дырку в маске, `optional` — подставить
   константу, `required` — ошибка «не получен параметр»;
4. хвост из непереданных отбрасывается — список остаётся коротким, как сейчас.

**Шаги 1–3 не смотрят на значение аргумента.** Это надо охранять: как только тип начнёт
влиять на то, куда попадёт аргумент, появится разрешение перегрузок — а перегрузок
в языке быть не может, функция это значение в переменной, одно имя = одно значение.
Типы, когда появятся, будут **проверять**, но никогда не **выбирать**.

Что меняется в вызывающих:

* `runtime/Interpreter.visitCall` и `visitNew` — аргументы вычисляются в порядке записи;
  имён нет → прежний путь (`arity().accepts` и `call(List)`), имена есть → `Binder`
  и `call(ctx, Arguments, span)`. Сообщение о числе аргументов для позиционного вызова
  не меняется ни на символ;
* `runtime/UserFunction` — `signature()` из `declaration.params()`, реализация широкого
  вызова, а в теле условие `i < arguments.size()` становится `args.has(i)`. Одна строка:
  механика «дефолт вычисляется на каждом вызове, в контексте вызова» уже ровно такая,
  какая нужна;
* `runtime/WdlClass` — `signature()` из `shape.params()`, `instantiate(Arguments, …)`,
  та же замена условия в `bindParams`, а в `bindLineage` аргументы родителя
  раскладываются тем же `Binder` по сигнатуре родителя;
* `resolve/Linker.checkParentArguments` — **имена в заголовке родителя проверяются
  статически**: форма родителя здесь уже известна, поэтому опечатка в
  `: Shape(radus: r)` падает на объявлении класса, а не при создании экземпляра.
  Проверяются неизвестное имя, повтор позиции и незаполненные обязательные.

Тексты диагностики выполнения:

```
функция 'greet' не принимает параметра 'greetng'
параметр 'name' функции 'greet' задан и позиционно, и по имени
функция 'greet' не получила обязательный параметр 'name'
функция 'println' принимает аргументы только по позиции: имена её параметров не объявлены
```

Подсказки «возможно, имелся в виду 'greeting'» здесь не заводим: в проекте нет ни одной,
и если делать — то общей утилитой сразу для полей, модулей и параметров. Отдельная задача.

## Этап 4. Встроенные функции и классы, модуль `sys.gui`

* `runtime/BuiltinFunction` — новая фабрика `of(name, Signature, Body)`; старая
  `of(name, Arity, body)` остаётся и даёт позиционную сигнатуру;
* `embed/NativeClass` — `signature()` собирается из уже объявленных полей
  (`field("x")` → `required`, `field("x", value)` → `optional`). **Имена в `new`
  достаются даром всем встроенным классам сразу** — `Window`, `Button`, `File`,
  `Socket`. Для методов и фабрик — перегрузки `method(name, Signature, body)`
  и `factory(name, Signature, body)`;
* `sys.gui` — показательный модуль: функции `grid`, `flow`, `border`, `alert`,
  `confirm`, `prompt` в `stdlib/gui/Gui.java` и методы компонентов с двумя и более
  параметрами. **Тела при этом не переписываются**: константный дефолт в сигнатуре
  даёт тому же `args.size() > 1` тот же ответ, что и раньше.

Остальные модули (`sys.io`, `sys.json`, `sys.net.*`, `sys.thread`, `std`) остаются
позиционными и продолжают работать; перевод — отдельными коммитами по модулю.

## Инварианты, которые работа обязана сохранить

* `Signature` и `Arguments` неизменяемы (`List.copyOf`, копия массива на входе):
  значение-функция живёт в нескольких потоках, а изменяемого состояния, живущего дольше
  вызова, в ядре быть не должно;
* новых пакетов нет — `module-info.java` не трогается;
* `wdl-core` остаётся без внешних runtime-зависимостей (`checkNoRuntimeDependencies`);
* `Span` у `Argument` задаётся при создании, имя хранится вместе со своим `nameSpan` —
  иначе сообщение об ошибке не сможет указать на имя, а не на весь вызов.

## Проверка

```bash
./gradlew build
./gradlew :wdl-core:test --tests 'ru.wds.wdl.runtime.NamedArgumentTest'
./gradlew :wdl-cli:run --args="examples/named-args.wdl"
./gradlew :wdl-cli:run --args="--ast examples/named-args.wdl"
./gradlew :wdl-cli:run --args="examples/gui_counter.wdl"
```

Контроль совместимости: `./gradlew build` должен пройти **без правки существующих
тестов поведения**. Если такой тест потребовал изменений, значит нарушена гарантия
«позиционный вызов идёт прежним путём» — возвращаться надо к `Binder`, а не к тесту.

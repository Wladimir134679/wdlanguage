# wdl

Встраиваемый скриптовый язык для JVM. Динамическая типизация, всё — значение,
несколько взаимно изолированных интерпретаторов в одном процессе.

Собственные лексер и парсер, генераторы парсеров не используются.

## Модули

| Модуль | Назначение | Зависимости |
|---|---|---|
| `wdl-core` | лексер, парсер, AST, значения, интерпретатор | **нет, и не будет** |
| `wdl-stdlib` | стандартная библиотека: math, string, array, io | `core` |
| `wdl-api` | фасад для встраивания: `WdlEngine`, компиляция, биндинг Java | `core`, `stdlib` |
| `wdl-tools` | линтер, форматтер, дамп AST, позже LSP | `core` |
| `wdl-cli` | запуск скриптов из консоли, REPL | `api`, `tools` |

Отсутствие зависимостей у `wdl-core` — не пожелание, а проверяемое правило:
задача `checkNoRuntimeDependencies` встроена в `check` и роняет сборку при нарушении.

## Правила, на которых держится архитектура

1. **Никакой изменяемой статики в ядре.** Всё состояние — на экземпляре,
   контекст передаётся аргументом. Это то, что делает изоляцию интерпретаторов настоящей.
2. **У узлов AST нет `eval()`.** AST — данные, выполнение живёт в `runtime`.
   Скрипт компилируется один раз и запускается сколько угодно раз в разных окружениях.
3. **Одно пространство имён.** Функция — обычное значение в обычной переменной,
   иначе не будет ни замыканий, ни функций-полей.
4. **Обращение одно на все типы.** `значение.имя` — это в точности `значение["имя"]`:
   поле объекта, элемент массива, ключ словаря и поле класса — один механизм.
   См. [docs/access.md](docs/access.md).
5. **Тип языка и класс реализации — разные вещи.** Тип `object` представлен двумя
   классами: `MapValue` — карта пар, `InstanceObjectValue` — экземпляр класса, её
   наследник. Скрипт разницы не видит (`typeof` у обоих даёт `object`), а обычный
   объект не платит полями за то, что нужно только экземпляру. Правило общее: то,
   что нужно частному случаю, живёт в частном случае.
6. **`Span` в каждом токене и узле.** Позиции добавлять задним числом всегда дороже.
7. **Репозитории объявляются только в `settings.gradle.kts`.** Модуль не может
   втихую притащить себе зависимость.

## Команды

```bash
./gradlew build                  # сборка + тесты + проверка чистоты ядра
./gradlew modules                # карта модулей
./gradlew :wdl-cli:run --args="--help"
./gradlew :wdl-cli:run --args="examples/hello.wdl"                # выполнить скрипт
./gradlew :wdl-cli:run --args="examples/expressions.wdl"          # шпаргалка по выражениям
./gradlew :wdl-cli:run --args="examples/control-flow.wdl"         # ветвления и циклы
./gradlew :wdl-cli:run --args="examples/functions.wdl"            # функции и замыкания
.\gradlew :wdl-cli:run --args="examples/defaults.wdl"             # значения по умолчанию
./gradlew :wdl-cli:run --args="--ast examples/hello.wdl"          # показать дерево
./gradlew :wdl-cli:run --args="--tokens examples/lexer-check.wdl" # показать токены
./gradlew :wdl-cli:repl --console=plain     # REPL (нужен живой stdin)
./gradlew :wdl-cli:installDist   # готовый запускаемый дистрибутив
                                 # → wdl-cli/build/install/wdl/bin/wdl
```

## Состояние

Работает конвейер `исходник → токены → AST → выполнение`:

```
$ wdl examples/hello.wdl
Привет, wdl!
Итого: 360 руб.
болт по 12 руб., на складе 100 шт.
Стоимость склада: 3250 руб.
...
```

Готовы лексер (`ru.wds.wdl.lexer`), диагностика (`ru.wds.wdl.diagnostic`), значения
(`ru.wds.wdl.value`), AST (`ru.wds.wdl.ast`), парсер (`ru.wds.wdl.parser`), резолвер
(`ru.wds.wdl.resolve`) и интерпретатор (`ru.wds.wdl.runtime`). Скрипт — это присваивания,
вызовы (`println`, `print`, `typeof`, `len`), блоки, ветвления и циклы (`if`, `while`,
`for`, `for ... in`, `break`, `continue`), свои функции (`fun`, `return`,
тело-выражение `=>`, анонимные функции, значения параметров по умолчанию, замыкания)
и классы (`class`, `trait`, `new`, `this`, `super`, `with`, `is`, фабрики
`fun Имя.член(...)`). Стандартная библиотека (`wdl-stdlib`) даёт `pow`, `sqrt`, `abs`,
классы `File` и `Random` и заодно служит примером
[встраивания](docs/embedding.md); именованных аргументов и модулей ещё нет.
Подробности — в [docs/statements.md](docs/statements.md),
[docs/control-flow.md](docs/control-flow.md), [docs/functions.md](docs/functions.md),
[docs/classes.md](docs/classes.md) и [docs/expressions.md](docs/expressions.md).

Решения парсера и интерпретатора, определяющие остальное:

* **Выражения разбираются алгоритмом Пратта**, приоритеты лежат таблицей
  в `Operators` — новый оператор это одна строка, а не новый уровень методов.
* **AST — только данные**: `record`'ы в `sealed` иерархии, без `eval()` и без ссылки
  на окружение. Выполнение — посетители `ExprVisitor` и `StmtVisitor`, и таким же
  посетителем написан дамп дерева.
* **Присваивание — инструкция**, а не выражение: `if (x = 5)` не разберётся вообще.
  Составное `+=` не разворачивается при разборе, поэтому `таблица[ключ()] += 1`
  вызывает `ключ()` один раз.
* **Функция — значение с замыканием на область объявления.** Отсюда даром получаются
  рекурсия, вложенные функции и замыкания над изменяемой переменной; объявления
  верхнего уровня помечаются до выполнения, поэтому порядок функций в файле свободен.
  Значение параметра по умолчанию считается **при каждом вызове**, а не один раз при
  объявлении, — иначе один массив или объект стал бы общим для всех вызовов, как в Python.
* **`break`, `continue` и `return` — сигналы**, а не проверяемый в каждом узле код
  возврата: `return` из глубины циклов не требует от циклов ни строчки. Бесконечная
  рекурсия при этом ошибка скрипта, а не `StackOverflowError` в чужом приложении.
* **Ошибка не прерывает разбор**: дерево возвращается всегда, испорченная строка
  пропускается до следующей, а до интерпретатора такое дерево не доходит.
* **Вывод — зависимость**, а не `System.out`: `println` пишет туда, куда указал
  вызывающий (`Output` в `ExecutionContext`), по умолчанию — никуда.

Решения лексера, влияющие на грамматику:

* **Перевод строки — обычный пробел.** Токена он не порождает: форматирование на
  разбор не влияет, `fun f(a, b)⏎ return a + b` и `fun f(a, b) return a + b` — один
  и тот же код. Границы инструкций выводит парсер из грамматики. Факт переноса
  всё же сохранён — в флаге `Token.afterNewline()`, для форматтера и диагностики.
* **`;` — необязательный разделитель** и обычный токен. Нужен там, где инструкции
  стоят в одной строке, и в заголовке `for (i = 0; i < n; i++)`.
* **Ошибка не прерывает разбор.** Всё найденное копится в `Diagnostics`,
  за один запуск видно все проблемы файла.
* **Точка после числа не съедается**, если за ней не цифра: иначе не было бы
  ни `3.75.round()`, ни будущего `1..5`.
* **Цифры только ASCII**, а буквы в именах — любого алфавита: имена на кириллице разрешены.

Кодировку вывода CLI выбирает сам: кодировка терминала, если запущен в терминале,
иначе UTF-8 (запуск из IDE, перенаправление в файл). Принудительно —
`-Dwdl.console.encoding=cp866`.

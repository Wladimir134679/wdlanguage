# wdl

Встраиваемый скриптовый язык для JVM. Динамическая типизация, всё — значение,
несколько взаимно изолированных интерпретаторов в одном процессе.

Собственные лексер и парсер, генераторы парсеров не используются.

## Модули

| Модуль | Назначение | Зависимости |
|---|---|---|
| `wdl-core` | лексер, парсер, AST, значения, интерпретатор | **нет, и не будет** |
| `wdl-bridge` | встраивание: свои классы, трейты и модули для скрипта плюс мост в Java (чужой класс и готовый объект как класс и объект языка) | `core` |
| `wdl-stdlib` | стандартная библиотека `std` и встроенные модули `sys.io`, `sys.json`, `sys.net.http` | `core`, `bridge` |
| `wdl-api` | фасад для встраивания: `WdlEngine`, компиляция, биндинг Java | `core`, `stdlib` |
| `wdl-tools` | линтер, форматтер, дамп AST, позже LSP | `core` |
| `wdl-cli` | запуск скриптов из консоли, REPL | `api`, `tools` |

Отсутствие зависимостей у `wdl-core` — не пожелание, а проверяемое правило:
задача `checkNoRuntimeDependencies` встроена в `check` и роняет сборку при нарушении.

## Правила, на которых держится архитектура

1. **Никакой изменяемой статики в ядре.** Всё состояние — на экземпляре,
   контекст передаётся аргументом. Это то, что делает изоляцию интерпретаторов настоящей.
2. **У узлов AST нет `eval()`.** AST — данные, выполнение живёт в `runtime`.
   Скрипт компилируется один раз и запускается сколько угодно раз в разных окружениях.
3. **Одно пространство имён.** Функция — обычное значение в обычной переменной,
   иначе не будет ни замыканий, ни функций-полей.
4. **Обращение одно на все типы.** `значение.имя` — это в точности `значение["имя"]`:
   поле объекта, элемент массива, ключ словаря и поле класса — один механизм.
   См. [docs/access.md](docs/access.md).
5. **Тип языка и класс реализации — разные вещи.** Тип `object` представлен двумя
   классами: `MapValue` — карта пар, `InstanceObjectValue` — экземпляр класса, её
   наследник. Скрипт разницы не видит (`typeof` у обоих даёт `object`), а обычный
   объект не платит полями за то, что нужно только экземпляру. Правило общее: то,
   что нужно частному случаю, живёт в частном случае.
6. **`Span` в каждом токене и узле.** Позиции добавлять задним числом всегда дороже.
7. **Репозитории объявляются только в `settings.gradle.kts`.** Модуль не может
   втихую притащить себе зависимость.

## Команды

```bash
./gradlew build                  # сборка + тесты + проверка чистоты ядра
./gradlew modules                # карта модулей
./gradlew :wdl-cli:run --args="--help"
./gradlew :wdl-cli:run --args="examples/hello.wdl"                # выполнить скрипт
./gradlew :wdl-cli:run --args="examples/expressions.wdl"          # шпаргалка по выражениям
./gradlew :wdl-cli:run --args="examples/control-flow.wdl"         # ветвления и циклы
./gradlew :wdl-cli:run --args="examples/functions.wdl"            # функции и замыкания
.\gradlew :wdl-cli:run --args="examples/defaults.wdl"             # значения по умолчанию
./gradlew :wdl-cli:run --args="examples/named-args.wdl"           # именованные аргументы
./gradlew :wdl-cli:run --args="examples/variadic-args.wdl"        # *args, **named, раскрытие
./gradlew :wdl-cli:run --args="examples/const.wdl"                # константы
./gradlew :wdl-cli:run --args="examples/class-varargs.wdl"        # остаток в заголовке класса
./gradlew :wdl-cli:run --args="examples/properties.wdl"           # свойства: get/set, скрытое поле
./gradlew :wdl-cli:run --args="examples/decorators.wdl"           # декораторы: @[...], like
./gradlew :wdl-cli:run --args="examples/threads.wdl"              # потоки и synchronized
./gradlew :wdl-cli:run --args="examples/threads_pool.wdl"         # пул, канал, защёлка
./gradlew :wdl-cli:run --args="--metrics examples/modules/plain.wdl" # время стадий
./gradlew :wdl-cli:run --args="--ast examples/hello.wdl"          # показать дерево
./gradlew :wdl-cli:run --args="--tokens examples/lexer-check.wdl" # показать токены
./gradlew :wdl-cli:repl --console=plain     # REPL (нужен живой stdin)
./gradlew :wdl-cli:installDist   # готовый запускаемый дистрибутив
                                 # → wdl-cli/build/install/wdl/bin/wdl
```

## Состояние

Работает конвейер `исходник → токены → AST → выполнение`:

```
$ wdl examples/hello.wdl
Привет, wdl!
Итого: 360 руб.
болт по 12 руб., на складе 100 шт.
Стоимость склада: 3250 руб.
...
```

Готовы лексер (`ru.wds.wdl.lexer`), диагностика (`ru.wds.wdl.diagnostic`), значения
(`ru.wds.wdl.value`), AST (`ru.wds.wdl.ast`), парсер (`ru.wds.wdl.parser`), формы классов
(`ru.wds.wdl.resolve`) и интерпретатор (`ru.wds.wdl.runtime`). Скрипт — это присваивания,
распаковка (`x, y = *point`, `host, port, **rest = **config`, остатки `*rest`/`**rest`,
отказ от остатка `*_`, обмен `a, b = b, a` и пропуск `_`, читать который нельзя),
объявления констант (`const`), вызовы (`println`, `print`, `typeof`, `len`),
блоки, ветвления и циклы (`if`, `while`,
`for`, `for ... in` — в том числе с ключом, `for (i, tile in row)` и
`for (k, v in config)`, — `break`, `continue`), ветвление по предмету (`match` с ветками
`case`, образцами из обычных операторов, перечислением `case 1, 2, 3`, условием
`case > 90 if !throttled` и `else` — выражением и инструкцией; ветка в несколько
строк отдаёт значение словом `yield`),
принадлежность (`in`, `has`, `!in`, `!has`, `!is`) и диапазоны (`1..5` — значение,
годное для `in`, для перебора и для передачи в функцию), свои функции (`def`, `return`,
тело-выражение `=>`, анонимные функции, значения параметров по умолчанию,
именованные аргументы `f(count: 2)`, вариативные параметры `*args`/`**named`
и раскрытие `f(*array)`, параметр-дырка `def onClick(_, event)`, замыкания),
классы (`class`, `trait`, `new`, `this`, `super`, `with`, `is`, фабрики
`def Имя.член(...)`, остаток в заголовке `class Proxy(*args, **named)`,
свойства `property имя { def get() def set(value) }` со скрытым полем `field`
и требованиями трейтов через возможность),
одиннадцать дескрипторов типов в корневой области (`Number`, `String`, `Array`,
`Range`, …) —
`typeof` возвращает дескриптор, а не строку, и проверять тип значения теперь можно
через `is` наравне с проверкой класса ([docs/types.md](docs/types.md)),
перегрузку операторов (`` def `+`(right) `` и `` mirror def `/`(left) `` в классе,
трейте и `extend`; один член `` `<=>` `` на четыре сравнения и сортировку, один
`` `==` `` на равенство, один `` `in` `` на четыре записи принадлежности; унарные
`` def `-`() `` — [docs/expressions.md](docs/expressions.md)),
члены значений (`text.upper`, `a.sort()`, `213.toString()`, `box.keys`; интроспекция
`total.params`, `Circle.parent`, `Printable.requirements`; путь в обход данных
`Object.size(box)`; свои члены — `extend Array { ... }` из скрипта и `MemberRegistry`
из приложения — [docs/members.md](docs/members.md)),
декораторы (`@[выражение](аргументы)` на функции, классе и трейте; метаданные
первым аргументом, модуль `sys.meta`, встроенная `like`), ошибки и ресурсы (иерархия `Exception`, `throw`,
`try`/`catch`/`finally`, короткие формы `try?` и `try!`, `defer`, `use` с трейтом
`Closeable`, путь по скрипту в сообщении) и модули (`import lib.math`, `import lib.math as m`,
наследование и трейты через файлы, в том числе от того, что дало выражение —
`: registry["Shape"](...)`). Модуль читается тогда, когда выполняется его
`import`, — поэтому импортировать можно файл, которого при запуске ещё не было.
Состояние модуля общее и на чтение, и на запись: снаружи с ним можно ровно то же,
что можно его собственному коду, а `const` в нём остаётся `const`.
Модулем бывает и библиотека на Java: консольный запуск даёт `sys.io` (файлы),
`sys.json`, `sys.meta`, `sys.net.http`, `sys.net.socket`, `sys.gui`, `sys.thread`
и `sys.time` (весь `java.time` — семь типов, открытых мостом, без единого
написанного метода),
а приложение — свой набор, потому что состав встроенных модулей задаёт запуск,
а не язык.
Работают настоящие потоки: `sys.thread` даёт `spawn`/`join`/`interrupt`, пул
с обещаниями (`pool.map`, `pool.submit`), замок, счётчик, канал и защёлку,
а модификатор `synchronized def` склеивает несколько обращений в одно неделимое.
Обещание языка короткое: одно обращение атомарно, выражение целиком — нет
(см. [docs/threads.md](docs/threads.md)). Приложение зовёт функции скрипта
из любого числа потоков одновременно — прежнего «вызовы выстраиваются в очередь»
больше нет ни как поведения, ни как режима.
Чужой Java-класс отдаётся скрипту без описания руками: `wdl-bridge` снимает
рефлексией методы, поля и конструкторы и ставит тип в область видимости обычным
классом — `new`, точка, `is` и печать работают как у классов языка, а готовый
Java-объект заворачивается тем же мостом (`bridge.wrap(instant)`). Что именно видно,
решает схема, и по умолчанию не видно ничего, чего не открыли: `getClass` не виден
никогда, а неизвестный тип получает отказ с подсказкой, а не молчаливую обёртку
(см. [docs/java-interop.md](docs/java-interop.md)).
Стандартная библиотека (`wdl-stdlib`) даёт `pow`, `sqrt`, `abs`,
классы `File` и `Random` и заодно служит примером
[встраивания](docs/embedding.md). Модуль на Java может отдать скрипту не только
функции и классы, но и трейт-контракт (`class Echo(name) with net.Handler` —
требования проверяются на строке `class`, как у трейтов языка), а свои классы
выстраивать в иерархию. Имена, которые библиотека кладёт в область, собираются
на запуск, поэтому между запусками в одном процессе не переносится ничего.
Время стадий движок считает по просьбе: `wdl --metrics script.wdl` печатает,
во что ушёл запуск, а встраивающее приложение включает то же одной строкой сборки
(`.metrics(true)`) и получает отчёт геттерами — см. [docs/metrics.md](docs/metrics.md).
Выключенные метрики не стоят ничего.
Слова `has` и `yield` стали ключевыми — скрипт с переменной по такому имени
перестанет разбираться; обращение `obj.has(k)` при этом работает как прежде:
после точки ключевое слово читается как имя члена.
Выборочного импорта отдельных имён ещё нет, наследоваться от класса встроенного
модуля пока нельзя. У `match` нет структурного сопоставления с извлечением имён
(`case {type: "click", x, y}`), у диапазона — шага (`1..10 by 2`). У декораторов нет короткой формы `@reg` без скобок и нельзя
повесить их на анонимную функцию в позиции выражения — и то и другое аддитивно
и отложено до второй версии.

[docs/control-flow.md](docs/control-flow.md), [docs/functions.md](docs/functions.md),
[docs/classes.md](docs/classes.md), [docs/decorators.md](docs/decorators.md),
[docs/errors.md](docs/errors.md),
[docs/modules.md](docs/modules.md), [docs/threads.md](docs/threads.md),

Решения парсера и интерпретатора, определяющие остальное:

* **Выражения разбираются алгоритмом Пратта**, приоритеты лежат таблицей
  в `Operators` — новый оператор это одна строка, а не новый уровень методов.
* **AST — только данные**: `record`'ы в `sealed` иерархии, без `eval()` и без ссылки
  на окружение. Выполнение — посетители `ExprVisitor` и `StmtVisitor`, и таким же
  посетителем написан дамп дерева.
* **Присваивание — инструкция**, а не выражение: `if (x = 5)` не разберётся вообще.
  Составное `+=` не разворачивается при разборе, поэтому `таблица[ключ()] += 1`
  вызывает `ключ()` один раз.
* **Функция — значение с замыканием на область объявления.** Отсюда даром получаются
  рекурсия, вложенные функции и замыкания над изменяемой переменной. Объявление
  существует со своей строки — стадии до выполнения в языке нет, — но тело функции
  спокойно зовёт то, что объявлено ниже: имя ищется в момент вызова.
  Значение параметра по умолчанию считается **при каждом вызове**, а не один раз при
  объявлении, — иначе один массив или объект стал бы общим для всех вызовов, как в Python.
  Имена параметров — часть значения-функции, а не разбора: поэтому `f(count: 2)`
  работает и для своей функции, и для класса, и для встроенной, которая имена объявила.
* **`break`, `continue` и `return` — сигналы**, а не проверяемый в каждом узле код
  возврата: `return` из глубины циклов не требует от циклов ни строчки. Бесконечная
  рекурсия при этом ошибка скрипта, а не `StackOverflowError` в чужом приложении.
* **Ошибка не прерывает разбор**: дерево возвращается всегда, испорченная строка
  пропускается до следующей, а до интерпретатора такое дерево не доходит.
* **`import` — инструкция, а не подготовка**: файл модуля читается тогда, когда
  до этой строки дошло выполнение. Класс связывается с родителем там же, где объявлен,
  поэтому наследоваться можно от класса из модуля, которого при запуске не существовало,
  а импорт в невызванной функции не стоит ничего.
* **Вывод — зависимость**, а не `System.out`: `println` пишет туда, куда указал
  вызывающий (`Output` в `ExecutionContext`), по умолчанию — никуда.
* **Глобального замка нет.** Внутри запуска потоки работают одновременно, а
  корректность держат конкурентные структуры: области видимости, объекты, массивы,
  реестр модулей и формы классов. Обещание автору скрипта — «одно обращение атомарно,
  выражение целиком нет», и это ровно та граница, которую движок может держать
  без того, чтобы отнять параллельность.

Решения лексера, влияющие на грамматику:

* **Перевод строки — обычный пробел.** Токена он не порождает: форматирование на
  разбор не влияет, `def f(a, b)⏎ return a + b` и `def f(a, b) return a + b` — один
  и тот же код. Границы инструкций выводит парсер из грамматики. Факт переноса
  всё же сохранён — в флаге `Token.afterNewline()`, для форматтера и диагностики.
* **`;` — необязательный разделитель** и обычный токен. Нужен там, где инструкции
  стоят в одной строке, и в заголовке `for (i = 0; i < n; i++)`.
* **Ошибка не прерывает разбор.** Всё найденное копится в `Diagnostics`,
  за один запуск видно все проблемы файла.
* **Точка после числа не съедается**, если за ней не цифра: на этом держатся
  и `3.75.round()`, и диапазон `1..5` — он разбирается как `INT`, `..`, `INT`
  без единого исключения в лексере.
* **Цифры только ASCII**, а буквы в именах — любого алфавита: имена на кириллице разрешены.

Кодировку вывода CLI выбирает сам: кодировка терминала, если запущен в терминале,
иначе UTF-8 (запуск из IDE, перенаправление в файл). Принудительно —
`-Dwdl.console.encoding=cp866`.

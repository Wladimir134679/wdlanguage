# wdl

Встраиваемый скриптовый язык для JVM. Динамическая типизация, всё — значение,
несколько взаимно изолированных интерпретаторов в одном процессе.

Собственные лексер и парсер, генераторы парсеров не используются.

## Модули

| Модуль | Назначение | Зависимости |
|---|---|---|
| `wdl-core` | лексер, парсер, AST, значения, интерпретатор | **нет, и не будет** |
| `wdl-stdlib` | стандартная библиотека: math, string, array, io | `core` |
| `wdl-api` | фасад для встраивания: `WdlEngine`, компиляция, биндинг Java | `core`, `stdlib` |
| `wdl-tools` | линтер, форматтер, дамп AST, позже LSP | `core` |
| `wdl-cli` | запуск скриптов из консоли, REPL | `api`, `tools` |

Отсутствие зависимостей у `wdl-core` — не пожелание, а проверяемое правило:
задача `checkNoRuntimeDependencies` встроена в `check` и роняет сборку при нарушении.

## Правила, на которых держится архитектура

1. **Никакой изменяемой статики в ядре.** Всё состояние — на экземпляре,
   контекст передаётся аргументом. Это то, что делает изоляцию интерпретаторов настоящей.
2. **У узлов AST нет `eval()`.** AST — данные, выполнение живёт в `runtime`.
   Скрипт компилируется один раз и запускается сколько угодно раз в разных окружениях.
3. **Одно пространство имён.** Функция — обычное значение в обычной переменной,
   иначе не будет ни замыканий, ни функций-полей.
4. **`Span` в каждом токене и узле.** Позиции добавлять задним числом всегда дороже.
5. **Репозитории объявляются только в `settings.gradle.kts`.** Модуль не может
   втихую притащить себе зависимость.

## Команды

```bash
./gradlew build                  # сборка + тесты + проверка чистоты ядра
./gradlew modules                # карта модулей
./gradlew :wdl-cli:run --args="--help"
./gradlew :wdl-cli:run --args="examples/lexer-check.wdl"   # разбор примера
./gradlew :wdl-cli:run --args="examples/lexer-errors.wdl"  # диагностика ошибок
./gradlew :wdl-cli:repl --console=plain     # REPL (нужен живой stdin)
./gradlew :wdl-cli:installDist   # готовый запускаемый дистрибутив
                                 # → wdl-cli/build/install/wdl/bin/wdl
```

## Состояние

Готов лексер (`ru.wds.wdl.lexer`) и накопитель диагностики (`ru.wds.wdl.diagnostic`).
`wdl <файл>` пока доводит скрипт только до потока токенов и печатает его —
парсера и интерпретатора ещё нет. Примеры для проверки лежат в `examples/`.

Решения лексера, влияющие на грамматику:

* **Перевод строки — обычный пробел.** Токена он не порождает: форматирование на
  разбор не влияет, `fun f(a, b)⏎ return a + b` и `fun f(a, b) return a + b` — один
  и тот же код. Границы инструкций выводит парсер из грамматики. Факт переноса
  всё же сохранён — в флаге `Token.afterNewline()`, для форматтера и диагностики.
* **`;` — необязательный разделитель** и обычный токен. Нужен там, где инструкции
  стоят в одной строке, и в заголовке `for (i = 0; i < n; i++)`.
* **Ошибка не прерывает разбор.** Всё найденное копится в `Diagnostics`,
  за один запуск видно все проблемы файла.
* **Точка после числа не съедается**, если за ней не цифра: иначе не было бы
  ни `3.75.round()`, ни будущего `1..5`.
* **Цифры только ASCII**, а буквы в именах — любого алфавита: имена на кириллице разрешены.

Кодировку вывода CLI выбирает сам: кодировка терминала, если запущен в терминале,
иначе UTF-8 (запуск из IDE, перенаправление в файл). Принудительно —
`-Dwdl.console.encoding=cp866`.

## Требования

JDK 21+ (toolchain выставлен в `gradle/libs.versions.toml`), Gradle Wrapper 9.0.

# План: свойства и методы значений

Черновик проекта. Живёт в корне, а не в `docs/`, потому что `docs/` описывает то,
что уже работает. Когда работа закончится, содержательная часть переедет
в [docs/types.md](docs/types.md) и [docs/access.md](docs/access.md), а этот файл уйдёт.

> **Состояние: ничего не реализовано.** Здесь спроектировано то, что
> [docs/access.md](docs/access.md) уже обещает одной строкой в разделе «что появится
> дальше»: *«свойства встроенных типов: `"строка".длина`, `[1,2].размер` — те же
> обращения, просто контейнер отвечает на известные ему ключи сам»*.

## Зачем

Сегодня всё, что можно спросить у значения, спрашивается снаружи — функцией:
`len(x)`, `typeof(x)`, и дальше по списку, который вот-вот начнёт расти. Отсюда три
следствия, каждое из которых мешает по-своему:

* **читается наизнанку.** `len(split(trim(text), " "))` вместо `text.trim.split(" ").size` —
  порядок действий обратен порядку чтения, и с каждым шагом расстояние между открывающей
  скобкой и её содержимым растёт;
* **имена уходят в глобальную область.** `push`, `keys`, `sort`, `upper` — это два
  десятка имён, которые займут корень и которые скрипт будет случайно перекрывать
  своими переменными. Причём каждое из них ещё и должно уметь ветвиться по типу
  аргумента: `size` у строки, массива и объекта — три разных вычисления с одним именем;
* **у значения нет способа рассказать о себе.** Тестовый фреймворк на самом языке
  (`examples/testing/`) не может спросить у функции имена её параметров, хотя движок
  их знает: `Signature` есть, а дороги из скрипта к ней нет.

Задача — дать значению **членов**: `"текст".size`, `[1,2].reversed`, `obj.keys`,
`arr.push(9)`, `f.params`. И сделать это так, чтобы новый набор членов мог добавить
не только ядро, но и встраивающее приложение, и сам скрипт.

## Одно правило

**Член значения — это то же обращение по ключу.** Ни нового узла, ни нового синтаксиса,
ни второй формы записи:

```wdl
text.size          // это text["size"]
text["si" + "ze"]  // и это тоже
```

`AccessExpr` не меняется, парсер не меняется, [docs/access.md](docs/access.md) остаётся
верным дословно. Меняется одно место — `Interpreter.read`: там, где сейчас для массива,
строки и числа стоит ошибка «к значению типа … нельзя обратиться», появляется
предварительный вопрос таблице членов типа.

Из этого сразу следует то, что в других языках приходится делать отдельно:

* **метод — обычное значение.** `handler = arr.push` читает связанный метод, `handler(9)`
  кладёт в тот самый массив. Ровно как уже работает у экземпляра класса
  (`p.text` без скобок), и по той же причине: «вызова метода» в языке нет, есть
  обращение, давшее функцию, и вызов;
* **имя члена можно вычислить.** `value[name]` в цикле по списку имён — обычный код,
  а не рефлексия;
* **`?.` останется одним флагом на узле**, когда понадобится, и накроет и данные,
  и члены сразу.

## Порядок разрешения

Один порядок на все типы, сверху вниз, остановка на первом попадании:

| # | Что | Кто отвечает |
|---|---|---|
| 1 | собственные данные | ключ объекта, индекс массива и строки, имя модуля, статика класса |
| 2 | метод класса | только у экземпляра — как сейчас |
| 3 | член типа | таблица членов: свойства и методы `string`, `array`, `object`, … |
| 4 | расширения | то, что добавили приложение или скрипт |
| 5 | нечего вернуть | объект — `null`; остальные — ошибка с подсказкой |

**Данные раньше членов** — это продолжение уже принятого решения, а не новое.
У экземпляра поле перекрывает метод (`Interpreter.read`: «поле перекрывает метод,
и это не случайность»); теперь по той же причине ключ перекрывает свойство:

```wdl
box = {size: "L"}
println(box.size)      // L — это данные, их клали руками
println(len(box))      // 1 — а это размер
```

Иначе язык решал бы за автора, что его собственный ключ `size` значит меньше,
чем встроенное свойство. Цена решения честная, и её надо назвать: у объекта
и модуля свойство работает **только пока ключ не занят**, поэтому для кода, которому
нужен гарантированный ответ, есть путь через дескриптор типа — `Object.size(box)`
(см. ниже). Для строки, числа, массива и функции конфликта нет вовсе: строковый
ключ у них данными быть не может.

## Свойство или метод

Правило, по которому проходит граница, — не «дорого или дёшево» (это невозможно
проверить), а два вопроса:

> **Свойство** — если нет аргументов **и** ничего не меняется.
> **Метод** — если есть аргументы, или меняется получатель, или делается внешняя работа.

```wdl
arr.size        // свойство: спросили и всё
arr.sorted      // свойство: новый массив, исходный цел
arr.sort()      // метод: тот же массив, переставлен на месте
arr.push(9)     // метод: есть аргумент и меняет получатель
s.upper         // свойство: строка неизменяема, менять нечего
s.split(",")    // метод: есть аргумент
```

Свойство никогда не меняет получателя — на это можно опираться, читая чужой код:
цепочка `a.b.c.d` без скобок гарантированно ничего не испортила.

Второе правило — про цену, и оно вынесено в **имя**:

> **Множественное число — снимок.** `keys`, `values`, `chars`, `lines`, `entries`
> собирают новый массив за `O(n)` при каждом чтении. Единственное — `size`, `first`,
> `last`, `empty` — отвечает сразу.

Поэтому `for c in s.chars` хорошо (снимок один), а `s.chars[i]` внутри цикла по `i` —
квадратично. Это ровно тот случай, который должен ловить будущий линтер `wdl-tools`:
«свойство-снимок читается в теле цикла — вынесите в переменную». Правило именования
существует именно затем, чтобы такой линтер был возможен без списка исключений.

## Каталог

Ниже — то, чем набор открывается. Список сознательно не полон: добавить член дешевле,
чем убрать, поэтому спорное лучше отложить, чем внести.

### string

Строка неизменяема, поэтому у неё нет ни одного метода, меняющего получателя, —
всё возвращает новую строку.

| Член | Что даёт |
|---|---|
| `size` | длина, как `len` сегодня — в кодовых единицах UTF-16 |
| `empty`, `blank` | пустая; пустая или только пробелы |
| `first`, `last` | первый и последний символ; у пустой — `null` |
| `upper`, `lower`, `trim` | новая строка |
| `reversed` | наоборот |
| `chars` | массив односимвольных строк, **по кодовым точкам** |
| `codes` | массив целых — кодовые точки |
| `bytes` | массив целых — UTF-8 |
| `lines`, `words` | разбиение по переводам строк и по пробелам |
| `number` | разбор числа или `null`, если не число |
| `slice(from, to?)`, `at(i)` | подстрока; `at` с отрицательным индексом — с конца |
| `indexOf(s)`, `lastIndexOf(s)`, `contains(s)`, `starts(p)`, `ends(s)` | поиск |
| `split(sep)`, `replace(a, b)`, `repeat(n)`, `padStart(n, c?)`, `padEnd(n, c?)` | сборка |

**Про `size` и `chars` врозь.** `s[i]` и `s.size` работают в кодовых единицах: так
устроено сегодня, это `O(1)`, и менять это ради эмодзи значит сделать индексацию
линейной. `chars` и `codes`, наоборот, идут по кодовым точкам и суррогатную пару
не рвут. Разница названа здесь и будет названа в документации: два вопроса — два
ответа, а не один «правильный».

### number

| Член | Что даёт |
|---|---|
| `int`, `float` | то же число в другом представлении; `int` отбрасывает дробную часть |
| `whole` | целое ли оно на самом деле (`4.0.whole` — `true`) |
| `abs`, `sign` | модуль и знак `-1/0/1` |
| `floor`, `ceil`, `rounded` | округления, всегда целое |
| `finite`, `nan` | про особые значения |
| `hex`, `bin`, `oct` | строка представления: `255.hex` — `"ff"` |
| `char` | символ по коду: `65.char` — `"A"` |
| `clamp(lo, hi)`, `min(x)`, `max(x)` | |
| `times(f)` | вызвать `f(i)` от `0` до `n-1` — единственный член-цикл, и он окупается |

Лексер уже готов: дробная часть требует цифру **после** точки
(`Lexer`: `peek(0) == '.' && isDigit(peek(1))`), поэтому `255.hex` разбирается как
обращение, а не как сломанный литерал. Править ничего не нужно — и это стоит
записать тестом, чтобы никто не «починил» лексер обратно.

### bool и null

**Ни одного члена, и это ответ, а не пропуск.** `flag.not` не лучше `!flag`,
`flag.int` — приглашение считать логическое числом, чего язык не позволяет намеренно
([docs/types.md](docs/types.md)). Обращение к `null` остаётся ошибкой: `null.size`
обязано ломаться там, где написано, — за тем `null` и нужен.

### array

Массив изменяем, поэтому у него есть обе половины: свойства-ответы и методы-действия.

| Свойство | Что даёт |
|---|---|
| `size`, `empty` | |
| `first`, `last` | у пустого — `null`, в отличие от `a[0]`, где ошибка |
| `indices` | `[0, 1, 2]` — пока в языке нет диапазонов |
| `reversed`, `sorted`, `unique`, `flat`, `copy` | новый массив, исходный цел |
| `sum`, `min`, `max` | только для чисел; смесь типов — ошибка с указанием элемента |

| Метод | Что делает |
|---|---|
| `push(*x)`, `pop()`, `shift()`, `unshift(*x)` | концы |
| `insert(i, x)`, `removeAt(i)`, `remove(x)`, `clear()` | |
| `sort(cmp?)`, `reverse()`, `fill(x)` | на месте — глагол не врёт |
| `slice(from, to?)`, `at(i)`, `concat(other)`, `chunk(n)`, `zip(other)` | |
| `indexOf(x)`, `contains(x)`, `count(f?)`, `join(sep)` | |
| `each(f)`, `map(f)`, `filter(f)`, `reduce(f, init?)` | |
| `any(f)`, `all(f)`, `find(f)`, `findIndex(f)`, `group(f)` | |

`sorted` без аргумента сравнивает по правилам оператора `<`; `sort(cmp)` берёт функцию.
Две записи для одного — сознательно: `sorted` читается в цепочке, `sort()` на месте
не копирует миллион элементов.

### object

| Свойство | Что даёт |
|---|---|
| `size`, `empty` | |
| `keys`, `values` | снимки, в порядке вставки |
| `entries` | массив объектов `{key: …, value: …}` |
| `class` | класс экземпляра или `null` у обычной карты |

| Метод | Что делает |
|---|---|
| `has(k)`, `get(k, default)`, `put(k, v)`, `remove(k)`, `clear()` | |
| `merge(other)`, `pick(*keys)`, `without(*keys)` | |
| `each(f)`, `map(f)`, `filter(f)` | `f(key, value)` |

`entries` объектами, а не парами-массивами: `e.key` читается, `e[0]` — нет. Пока
в заголовке цикла нет разбора на части, читаемость важнее экономии на одном `MapValue`.

### function

Здесь начинается интроспекция — то, ради чего многое и затевалось.

| Член | Что даёт |
|---|---|
| `name` | имя или `""` у анонимной |
| `params` | массив `{name, required, variadic}` — прямо из `Signature` |
| `arity` | `{min, max}`; `max` — `null` у вариативной |
| `variadic` | есть ли `*args` / `**named` |
| `meta` | метаданные декораторов (`DecoratorMeta`) — то, что движок уже собирает |
| `call(*args)`, `apply(array)` | вызов разложенным списком |
| `partial(*args)` | новая функция с прикреплёнными первыми аргументами |

`f.params` — ровно то, чего не хватает тестовому фреймворку на самом языке и будущей
сборке CLI по функции. Движок это уже знает; свойство просто открывает дверь.

### class и trait

| Класс | Что даёт |
|---|---|
| `name`, `parent`, `traits` | |
| `fields` | имена заголовка по порядку |
| `methods` | имена методов плоской таблицы |
| `create(array)` | `new` разложенным списком |

| Трейт | Что даёт |
|---|---|
| `name`, `requires`, `fields` | |

У класса собственные данные — это статика (`Point.zero`), и правило «данные раньше
членов» здесь тоже работает: `Point.name = "иначе"` перекроет свойство. Что законно —
класс это значение, и запись в него уже разрешена.

### module

| Член | Что даёт |
|---|---|
| `name`, `path` | |
| `names` | что модуль объявил — снимок |
| `loaded` | загружен ли отложенный модуль |

Модуль — единственный контейнер, где отсутствующее имя даёт ошибку, а не `null`.
Порядок это сохраняет: сначала имя модуля, потом член, потом та же ошибка, что
и сегодня, — но теперь с добавкой «у модуля есть свойства name, path, names».

## Тип — тоже значение

Свойства у объекта и модуля перекрываются данными, расширять тип откуда-то надо,
а `typeof(x) == "array"` — строковое сравнение там, где язык мог бы отвечать сам.
Три задачи закрываются одной вещью: **у каждого типа появляется значение-дескриптор**,
стоящее в корневой области обычным именем:

```
String   Number   Bool   Array   Object   Function   Class   Trait   Module   Null
```

Что это даёт:

```wdl
println(x is Array)            // вместо typeof(x) == "array"
println(Object.keys(box))      // надёжный путь, даже если у box есть ключ keys
println(Array.members)         // что вообще умеет массив — список имён
println(x.type.name)           // "array"; typeof остаётся синонимом
```

**Дескриптор — это `ClassValue`, а не восьмой тип значения.** `ClassValue` —
`non-sealed` интерфейс, поэтому новая реализация (`runtime/TypeClass`) не трогает
ни `Value`, ни `ValueType`, и «список типов закрыт» остаётся правдой. Дескриптор:

* `statics()` — карта, куда положены все члены типа в виде обычных функций,
  берущих получателя первым аргументом: `Array.push(a, 9)` — это то же, что `a.push(9)`;
* `method()` — `null`: у дескриптора нет экземпляров;
* `instantiate()` — внятный отказ («`new String(...)` не бывает; для приведения
  есть `String.of(x)`»);
* ответ оператору `is` — по типу значения.

Последнее требует одной правки в `Operations.is`: сегодня он сам решает, что слева
должен стоять `InstanceObjectValue`. Решение переезжает вправо — в
`ClassValue.accepts(Value)` с реализацией по умолчанию ровно такой, как сейчас;
`TypeClass` её переопределяет. Это единственное место, где старое поведение
касается нового.

Заодно появляется `x.type` — универсальное свойство, дающее дескриптор. У объекта
и модуля его, разумеется, перекроет ключ `type`, если он есть, — общее правило.

## Расширение

Четыре уровня, от неизменяемого к самому свободному. Все четыре пишут в одну таблицу
и разрешаются одним поиском.

### 1. Ядро

Наборы `StringMembers`, `ArrayMembers`, `ObjectMembers`, … в `wdl-core/runtime/members`.
Собираются один раз на запуск рядом с `Builtins.installTo`, кладутся в таблицу запуска
неизменяемой частью. Перекрыть встроенный член нельзя — ни библиотекой, ни скриптом
(см. ниже, почему).

### 2. Приложение — на Java

Тем же построителем, каким приложение уже добавляет классы, и из того же места —
`Library.installTo`:

```java
Members.forType(ValueType.STRING)
        .property("slug", (self, ctx, span) -> StringValue.of(slug(text(self))))
        .method("hash", Arity.exactly(1), (self, ctx, args, span) -> ...)
        .installTo(scope);
```

Это ровно тот приём, что уже работает у `NativeClass`: имена и арность видны в одном
месте, опечатку ловит компилятор, рефлексия не нужна, `module-info` открывать нечего.

**Заодно — вычисляемые поля у нативных классов.** `NativeClass.Builder` получает
`.property(name, getter)`, и `sys.gui` наконец пишет `window.width` вместо
`window.getWidth()`, не заводя настоящего поля, которое пришлось бы синхронизировать
со Swing.

### 3. Скрипт — `extend`

```wdl
extend Array {
    get second => this[1]
    def middle() => this[len(this) / 2]
    def swap(i, j) {
        t = this[i]
        this[i] = this[j]
        this[j] = t
    }
}

println([1, 2, 3].second)     // 2
[1, 2, 3].swap(0, 2)
```

Решения внутри:

* **`this` — получатель**, то же слово и то же значение, что в методе класса. Второго
  имени для того же понятия язык заводить не станет;
* **`get` — свойство, `def` — метод.** Различие обязано быть явным: без него `a.middle`
  без скобок молча возвращало бы функцию, а автор ждал бы значение. `get` —
  контекстное слово, ключевым словом языка оно не становится и переменную `get`
  не ломает;
* **встроенное перекрыть нельзя.** `extend Array { get size => 0 }` — ошибка на строке
  объявления. Скрипт, переопределивший `size`, ломает не себя, а всё, что работает
  с массивами в этом запуске, включая библиотеки;
* **повторное расширение тем же именем — тоже ошибка**, с указанием, где объявлено
  первое. Тихая победа последнего — худший из возможных исходов;
* **расширение — свойство запуска, а не файла.** Объявили в модуле — работает везде
  в этом запуске (но не в соседнем интерпретаторе: таблица живёт в `Run`, статики
  нет). Лексическая видимость («расширение действует только там, где импортировано»)
  честнее, но требует таскать модуль вызова в каждое чтение по ключу и сверять его
  с таблицей на каждом обращении. Отложено осознанно — см. «Отложенное»;
* **расширять можно и класс:** `extend Point { get length => ... }` дописывает члены
  в конкретный класс, а не в тип `object`. Механизм тот же, ключ таблицы другой.

### 4. Свои классы — `get` и `set`

То же слово `get`, только внутри `class` и `trait`, — вычисляемое поле:

```wdl
class Rect(w, h) {
    get area => this.w * this.h
    get square => this.w == this.h

    set size(v) {
        this.w = v
        this.h = v
    }
}

r = new Rect(3, 4)
println(r.area)     // 12
r.size = 5          // сеттер; r.w и r.h стали 5
```

Ловушка, которую надо закрыть сразу: `r.area = 5` **без** объявленного `set` — ошибка
(«у Rect свойство area только на чтение»), а не тихое заведение поля. Иначе поле
навсегда перекрыло бы геттер по правилу «данные раньше членов», и объект оставался бы
сломанным до конца жизни — с полем `area`, которое больше не пересчитывается.

Дальше это соединяется с уже готовыми декораторами: `@[cached] get area => ...`
считает один раз на экземпляр, `@[deprecated("v2")] get width` даёт предупреждение
линтера. Ничего нового для этого не нужно — декоратор уже умеет оборачивать функцию,
а геттер и есть функция без параметров.

## Устройство в коде

```
value/Member.java          свойство или метод: sealed-пара
value/Members.java         построитель набора (используется и ядром, и приложением)
runtime/MemberTable.java   таблица запуска: ValueType -> имя -> Member, плюс классы
runtime/members/*.java     встроенные наборы по типам
```

Что важно соблюсти:

* **никакой статики.** Таблица создаётся вместе с запуском (`Run`), берётся из
  `ExecutionContext`/`CallContext`. Два интерпретатора в одном процессе не делят
  расширения — это то же правило, по которому `NativeClass` собирается на запуск,
  а не лежит в статическом поле;
* **потокобезопасность.** Встроенная часть неизменяема после сборки; часть, куда
  пишет `extend`, — конкурентная карта. Правило ядра «изменяемое состояние запуска
  потокобезопасно» ([docs/threads.md](docs/threads.md)) распространяется на неё
  без исключений;
* **связывание метода — как у класса.** Чтение `arr.push` возвращает `BuiltinFunction`,
  замкнутую на получателя, — тот же приём, что `WdlClass.bindMethod`. Значит
  `map(list.push)` работает, и объект не теряется;
* **горячий путь.** Обращение `a.size` — один поиск в `HashMap` по строке после
  промаха по данным. Этого достаточно; если метрики (`--metrics`, уже есть)
  покажут, что мало, — первым делом кэш `Member` на узле `AccessExpr`
  (форма ключа известна при разборе), а не таблица иного устройства;
* **`len` и `typeof` остаются** и определяются через членов: `len(x)` — это `x.size`
  с понятной ошибкой для типов, у которых размера нет. Ломать работающие скрипты
  ради красоты нельзя, а два способа спросить одно и то же — небольшая цена.

## Чего свойства не делают

Границу надо провести сразу, иначе она размоется сама:

* **не участвуют в переборе.** `for k in obj` идёт по ключам данных; `size` и `keys`
  там не появятся. Свойство — это ответ о значении, а не его содержимое;
* **не попадают в сериализацию.** `json.stringify(obj)` пишет данные, и только их;
* **не меняют равенство и печать.** `display()` и `==` работают как работали;
* **не создают новой стадии для метрик.** Обращение к члену — часть выполнения,
  отдельного замера не заводим;
* **не заменяют модули.** `sys.io` остаётся модулем: работа с файлами — это внешние
  эффекты, а не ответ значения о себе. Правило простое: если для действия нужен мир
  снаружи процесса — это модуль, а не член.

## Диагностика

Промах по имени — самая частая ошибка при таком наборе, поэтому текст ошибки
проектируется вместе с механизмом, а не после:

```
у массива нет члена 'lenght'
  похоже на 'length'? У массива есть: size, empty, first, last, indices, …
```

Подсказка по редакционному расстоянию — тем же приёмом, что уже работает
в `runtime/Declarations` для необъявленных переменных: считается только на пути
ошибки, на удачном пути этого кода нет.

Отдельный текст — для случая «данные перекрыли член»: если у объекта есть ключ `size`
и его прочитали, всё правильно; но если у объекта ключа `keys` нет, а вернулся `null`,
подсказать нечего — `null` законен. Поэтому у объекта промах молчит, как и сегодня,
и именно поэтому нужен `Object.keys(x)`.

## Этапы

| # | Что | Итог |
|---|---|---|
| 1 | `Member`, `Members`, `MemberTable`, ветка в `Interpreter.read`, набор `array` | `[1,2].size`, `a.push(3)` |
| 2 | наборы `string`, `number`, `object` | цепочки без скобок работают |
| 3 | дескрипторы типов, `is` через `accepts`, `x.type` | `x is Array`, `Object.keys(x)` |
| 4 | интроспекция: `function`, `class`, `trait`, `module` | `f.params`, `c.methods` |
| 5 | `get`/`set` в классах и трейтах | вычисляемые поля |
| 6 | `extend` в скрипте | расширение своими руками |
| 7 | `Members` и `NativeClass.property` для приложения | `window.width` в `sys.gui` |
| 8 | правило снимка в линтере, подсказки по именам | |

Этапы 1–2 полезны сами по себе и ничего не обещают вперёд; остальное можно
остановить на любом номере.

## Отложенное и отвергнутое

**Отдельный синтаксис для членов (`obj::keys`).** Отвергнуто: это третья форма
обращения, а весь смысл [docs/access.md](docs/access.md) в том, что форма одна.
Задачу «достучаться до члена, закрытого данными» решает `Object.keys(obj)` —
без нового оператора и без нового правила.

**Автоматическая упаковка в классы (как `Integer` в Java).** Отвергнуто: тогда
`typeof(5)` пришлось бы объяснять, а «всё — значение» перестало бы быть правдой.
Дескриптор типа — не обёртка над значением, а справочник о нём.

**Разрешить перекрывать встроенные члены.** Отвергнуто: это состояние процесса,
которое меняет поведение чужого кода. Скрипт вправе испортить себе — но не библиотеке,
которая работает с теми же массивами.

**Свойства с записью у встроенных типов** (`arr.size = 3` как усечение,
`arr.first = x`). Отложено: протокол `Member` место для сеттера предусматривает,
но в стандартном наборе его нет — `arr[0] = x` и `arr.resize(3)` говорят яснее,
а «присваивание, которое на самом деле работа» — источник сюрпризов.

**Лексическая видимость расширений** (действует там, где импортировано). Отложено
до появления жалоб: требует модуль вызова в каждом чтении по ключу, а значит и в
горячем пути. Если понадобится — `MemberTable` уже разделена на «встроенное»
и «добавленное», и вторая половина станет картой на модуль.

**Ленивые представления вместо снимков** (`s.chars` без копирования). Отложено:
изменяемый массив-представление над строкой — новая сущность в системе значений;
пока правило множественного числа и линтер закрывают тот же вопрос дешевле.

## Что здесь «эдакого»

Пять вещей, которые получаются сами собой и которых у языка сейчас нет:

1. **Интроспекция без рефлексии.** `f.params`, `f.meta`, `c.methods`, `c.fields` —
   тестовый фреймворк, сборка CLI по функции, генерация формы по классу пишутся
   на самом wdl, а движку для этого не нужно ничего нового: `Signature`
   и `DecoratorMeta` уже собраны.
2. **`x is Array` вместо строкового сравнения.** Проверка типа перестаёт быть
   сравнением строк — и опечатка `"aray"` перестаёт быть тихим `false`.
3. **Вычисляемые поля у нативных классов.** `window.width`, `socket.open`,
   `file.size` — то, что сегодня приходится делать методами `getX()`, потому что
   поле нативного класса умеет только хранить.
4. **`@[cached] get`** — декораторы и свойства встречаются, и мемоизация становится
   одной строкой над геттером, а не ручным полем-кэшем в каждом классе.
5. **Линтер, который знает цену.** Правило «множественное число — снимок» —
   не стилистика, а то, что даёт `wdl-tools` право сказать «`s.chars` в теле цикла».
   Соглашение об именах, из которого следует проверка, дороже соглашения,
   из которого не следует ничего.

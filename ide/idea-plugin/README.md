# Плагин IntelliJ IDEA для wdl

Тонкий плагин: он не знает про язык ничего и только запускает языковой сервер
`wdl-lsp`. Подсветка, ошибки, дополнение, переход к объявлению, поиск употреблений
и структура файла приходят по протоколу — из `wdl-tools`, того же кода, которым
пользуются `wdl --catalog` и (в будущем) редактор внутри приложения.

## Требования

* **Платная IDE JetBrains** — IntelliJ IDEA Ultimate, PyCharm Professional и другие.
  Клиента LSP в Community-сборках нет вовсе: это API платформы, доступное только
  в коммерческих продуктах. Отсюда `com.intellij.modules.ultimate` в `plugin.xml`.
* IntelliJ IDEA **2025.3** или новее (`sinceBuild = 253`). Более ранние сборки
  тоже умеют LSP, но API платформы там менялось; понижать планку стоит,
  только проверив на конкретной версии.
* JDK 21 — тот же, что у самого языка.

## Сборка

Сборка отдельная: корневой `./gradlew build` её не трогает и дистрибутив IDE
не качает. Обёртка Gradle берётся из корня репозитория.

```bash
./gradlew :wdl-lsp:installDist            # сначала сам сервер
./gradlew -p ide/idea-plugin buildPlugin  # затем плагин
```

Готовый архив — `ide/idea-plugin/build/distributions/wdl-idea-plugin-0.1.0.zip`;
ставится через **Settings → Plugins → ⚙ → Install Plugin from Disk**.

Запустить IDE с плагином, ничего не устанавливая:

```bash
./gradlew -p ide/idea-plugin runIde
```

Первая сборка скачивает дистрибутив IDE (около двух гигабайт) — это нормально
и происходит один раз.

## Где плагин ищет сервер

По порядку, от явного к угаданному:

1. системное свойство `-Dwdl.lsp.home=<каталог>`;
2. переменная окружения `WDL_LSP_HOME=<каталог>`;
3. `wdl-lsp/build/install/wdl-lsp/bin/wdl-lsp` внутри открытого проекта —
   это работает само, когда открыт сам репозиторий wdl;
4. `wdl-lsp` в `PATH`.

Не нашёлся — файл остаётся обычным текстом, а в журнал IDE (`Help → Show Log`)
пишется строка о том, чего не хватило. Окно с ошибкой на каждый открытый файл
было бы хуже.

Сервер намеренно не лежит внутри плагина: он часть дистрибутива wdl и обязан быть
той же версии, что и движок, которым скрипт будет выполнен. Плагин со своей копией
однажды подскажет имя, которого в запуске уже нет.

## Что уже работает и чего ещё нет

Работает: диагностика, дополнение имён (включая встроенные, `std` и модули `sys.*`),
подсказка по наведению, переход к объявлению внутри файла, поиск употреблений,
структура файла, семантическая подсветка.

Ещё нет: форматирования, переименования, инспекций, перехода между файлами
по `import` и членов после точки (кроме имён модуля). Сервер их и не обещает —
возможность объявляется только после того, как сделана.

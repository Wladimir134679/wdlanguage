### Импорты

Импорты в скрипте служат для того, чтобы добавлять классы, переменные, функции сторонние из других файлов\источников.
Есть именованные импорты, и развернутые. 

> Сделано. Что получилось — в [docs/modules.md](docs/modules.md), рабочие примеры на
> все случаи — в [`examples/modules/`](examples/modules). Отличий от задуманного пять,
> и вот почему:
>
> * **Путь считается от каталога того файла, где написан `import`**, а не от рабочей
>   директории процесса. Иначе модуль в подкаталоге не мог бы сослаться на соседа
>   по короткому имени, а набор файлов нельзя было бы перенести целиком: путь у него
>   получался бы тот же, что и у главного скрипта. Ведущий `/` означает «от корня
>   запуска» — ровно как и задумывалось.
> * **Модуль выполняется один раз за запуск.** «При импорте происходит выполнение
>   другого скрипта» — но выполнять его на каждом импорте значило бы переразбирать файл
>   при каждом вызове функции с `import` внутри, а два импорта одного модуля давали бы
>   **два разных класса**, и `x is m.Point` лгало бы при правильном скрипте.
> * **Модуль — отдельный тип, а не объект.** `typeof` даёт `module`, обращение
>   к несуществующему имени — ошибка, а не `null`: состав модуля задан его файлом,
>   и опечатку в `m.add` надо называть сразу.
> * **Модуль изменять нельзя.** Значение у всех, кто его импортировал, общее, и запись
>   из одного места меняла бы чужой файл всем сразу.
> * **Тип из модуля виден только ниже своего `import`.** Свои классы можно объявлять
>   в любом порядке, а импортированные — нет: импорт выполняется, и выше него модуля
>   ещё нет. Отсюда же единственное исключение из «объявления помечаются заранее»:
>   класс, которому нужен родитель или трейт из модуля, появляется на своей строке.
>   Наследоваться и подмешивать при этом можно обеими записями — `class Circle : Shape`
>   после развёрнутого импорта и `class Circle : m.Shape` после именованного.
>
> Остальное — как в задумке: обе формы, импорт в любой области (включая тело функции)
> с исчезновением на выходе, обе записи пути и `new m.TestClass()`.
>
> **Дополнено потом: загрузка ленивая.** Файл модуля читается тогда, когда выполняется
> его `import`, — ни разбор скрипта, ни разбор модуля чужих файлов не открывают.
> Поэтому импортировать можно то, чего в момент запуска ещё нет: сгенерированный код,
> плагин, скрипт из базы. Ради этого класс связывается с родителем и трейтами
> при выполнении своего объявления, там же проверяются требования трейтов
> и число аргументов родителю. Подробности и цена — в
> [Ленивая загрузка модулей.md](Ленивая%20загрузка%20модулей.md).

При импорте происходит выполнение другого скрипта, на который ссылается код, всё что в корне хранится,
в локальном скоупе будет использовано дальше.

Именованные - весь скоуп оборачивается как будто это объект, и у него через точку можно вызывать переменные,
функции, классы, создать оттуда классы

Развернутые - модуль разворачивается, и весь контекст оттуда внедряется и накладывается в текущий,
переменные и функции как будто тут были объявлены

Импорт можно вызывать в любом месте кода, внутри функций - и всё что было внутри импорта будет внутри скоупа
функции, после выхода из функции, всё забывается от импорта

Поиск скриптов, исходников, файлов происходит из рабочей директории выполняемой программы

Синтаксис для импортов
```wdl
import scriptName
import "scriptName"
import "scriptName.wdl"
import "/scriptName.wdl"
import "/scriptName"
// Все выше импорты идентичные записи на один скрипт

import "script-name-for-JAWIODj030-4i209j09-u(&*()*#^$0"
// Если в имени модуля символы не из WORD - обязательно должно быть в как строка. 
// То есть в импорте может быть как "" так и WORD

import lib.moduleName
import "lib/moduleName"
// для модулей в директорияъ - через точку указывается как внутри, через word токены
// для имени модуля через строку - нужно ссылаться по / - директория
```

Развернутый, переменные, функции, классы оттуда доступные оттуда
```wdl
import moduleName // Выполняется этот модуль, в итоге там есть переменная PI, есть функция add и класс TestClass

r = PI * 2
result = add(r, PI)
t = new TestClass()
```

Именованный импорт использует "as" оператор
```wdl
import moduleName as m // Выполняется этот модуль, в итоге там есть переменная PI, есть функция add и класс TestClass
// теперь локально есть переменная m

// r = PI * 2
// result = add(r, PI)
// t = new TestClass()
// PI локальной нет, add нет, TestClass нет. Работать не будет


// а вот это будет работать, обращение к тому модулю через m.
r = m.PI * 2
result = m.add(r, m.PI)
t = new m.TestClass()

```

Работа внутри функций
```wdl
def testFunc(){
    import module.Randoms // class RandomInt внутри есть и другие
    rr = new RandomInt().next(1000)
    import moduleName as mFunc // вызывается и выполняется
    sum = mFunc.add(mFunc.PI, rr)
    return sum;
}
// тут нет доступа до mFunc и до рандома уже
println("Result testFunc: ", testFunc())
// модули работал только в функии, тут его тоже нет

```


Для функций

> Сделано. Что получилось — в [docs/functions.md](docs/functions.md), рабочий пример —
> в [`examples/functions.wdl`](examples/functions.wdl). Отличие от задуманного одно:
> **после `return` обязательна точка с запятой**. Без неё `return` и следующая строка
> неразличимы — перевод строки токена не даёт, — и движку пришлось бы молча выбирать
> за автора одно из двух толкований. Тело-выражение `=>` терминатора не требует,
> так что самая короткая запись осталась ровно такой, как задумывалась.

```wdl
def name(a, b){
    return a + b;
}
def nameOneBlock(a, b) 
    return a + b;
    
// Одно и тоже
    
def nameOneBlock2(a, b) return a + b;

def nameOneBlock3(a, b) => a + b
    
println("result sum = ", name(1, 2))
println("result sum = ", nameOneBlock(1, 2))
println("result sum = ", nameOneBlock2(1, 2))
println("result sum = ", nameOneBlock3(1, 2))

funName = def(a, b)
    return a + b;

println("Результат переменной функции = ", funName(1, 2))


def name(a, b) { return a + b; }    // блочное тело
def name(a, b) return a + b;        // тело — одна инструкция (перенос строки не значим)
def name(a, b) => a + b             // тело-выражение, => вместо return
f = def(a, b) => a + b              // анонимная в выражении
f = def(a, b) { return a + b; }     // анонимная с блоком
```

## Константы

Хотелось `const` — имя, которое задаётся один раз и дальше не меняется.

> Сделано. Что получилось — в [docs/statements.md](docs/statements.md#const--имя-которое-нельзя-перезаписать),
> рабочий пример — в [`examples/const.wdl`](examples/const.wdl). Три вещи, которые стоит
> знать заранее. **Заморожено имя, а не значение**: `const items = [1, 2]` запрещает
> `items = [3]`, но не `items[0] = 5` — иначе один и тот же массив, положенный в две
> переменные, вёл бы себя по-разному. **Затенение разрешено**: вложенный блок или функция
> объявляет свою константу с тем же именем, внешняя не страдает, — `const` заводит имя
> в своей области, как `def`. **Встроенные константами не стали**: `println = 5`
> по-прежнему работает, пространство имён одно; заморозить их — отдельный разговор.

```wdl
const TAX_RATE = 0.2

def total(price, count) => price * count * (1 + TAX_RATE)

// TAX_RATE = 0.3
// ошибка: 'TAX_RATE' нельзя присвоить: это константа, её значение задаётся
// один раз при объявлении
```

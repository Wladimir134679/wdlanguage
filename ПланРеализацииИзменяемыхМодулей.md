# План: модуль изменяем снаружи так же, как изнутри

Статус: **сделано**. Отметки ставятся по мере выполнения: `[ ]` — не начато,
`[~]` — в работе, `[x]` — сделано.

## 0. Правило, из которого следует всё остальное

> **Импортировав модуль, с ним можно делать всё, что можно его собственному коду.**
> `const` не переприсваивается ни изнутри, ни снаружи; всё остальное — переменные,
> функции, классы, трейты — переприсваивается и там, и там. Обе формы импорта видят
> одно и то же состояние, потому что модуль выполняется один раз за запуск.

Отдельного правила «модуль только для чтения» больше нет — исчезает целый абзац
ограничений, а не добавляется новый механизм. При правке документации текст должен
**укорачиваться**.

## 1. Механизм: связка вместо копии

Сейчас развёрнутый импорт копирует значения (`Interpreter.visitImport`). Копия —
единственная причина, по которой `import test; a = 10` не доходит до функций модуля.
Заменяем копию на **связку** — «имя, которое живёт в другом месте».

Три места хранят связки, и в каждом они значат одно: имя есть здесь, значение — там.

* **`Scope`** — связки от `import` в обычной области (главный скрипт, тело функции, блок).
* **`ModuleScope`** — связки от `import` внутри файла модуля. Реэкспорт остаётся
  сквозным и живым: `ModuleValue` спрашивает связку при промахе. Цепочка
  `A → B → C` конечна — круг в импортах запрещён.
* **`ModuleValue`** — фасад над обеими картами области модуля.

Приоритет везде один: **своё имя бьёт связку, связка бьёт внешнюю область.**
Объявление стирает связку, импорт стирает ранее объявленное имя — обе стороны
затеняют друг друга симметрично.

## 2. Правки в `wdl-core`

* [x] **2.1 `value/Binding.java`** — новый интерфейс: `value()`, `constant()`,
  `set(Value)` → `false`, если имя заморожено. Лежит в `value`, а не в `runtime`,
  чтобы `ModuleValue` мог его знать: в `value/` ноль импортов из `runtime`, и это
  направление сохраняем.
* [x] **2.2 `value/types/ModuleValue.java`** — четвёртое поле `Map<String, Binding> aliases`
  (живая карта области модуля); конструктор на четыре аргумента, старый оставить
  делегирующим; `get`/`has`/`isConstant` — при промахе смотрят связки; новый
  `set(String, Value)`; новый `names()` (свои плюс пришедшие связкой); javadoc
  переписать под §0.
* [x] **2.3 `runtime/ModuleBinding.java`** — новый package-private
  `record ModuleBinding(ModuleValue module, String member) implements Binding`.
* [x] **2.4 `runtime/Environment.java`** — `default void defineAlias(String, Binding)`,
  по умолчанию копирующий значение. Именно `default`: пакет экспортирован,
  интерфейс реализуют приложения через `Library.installTo`.
* [x] **2.5 `runtime/Scope.java`** — **ленивое** поле связок (как `constants`:
  `lookup` — горячий путь); учёт в `lookup`, `lookupHere`, `isConstantHere`,
  `assign`; `define`/`defineConstant` стирают связку; `defineAlias`.
* [x] **2.6 `runtime/ModuleScope.java`** — то же, но карта обычная (`LinkedHashMap`,
  порядок имён важен); `module()` отдаёт её в `ModuleValue`; javadoc про реэкспорт.
  `InstanceScope` не трогаем — до него импорт не доходит.
* [x] **2.7 `runtime/Interpreter.java`** — `writeMember` вместо запрета в `write`
  (три исхода: не строка → `TYPE`, нет имени → `NAME`, константа → `DECLARATION`
  дословно тем же текстом, что `VariablePlace.write`); `visitImport` заводит связки
  вместо копий.

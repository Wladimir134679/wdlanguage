# Ленивые конвейеры — `sys.streams`

Конвейер — это способ протянуть данные через цепочку операций, **не собирая их
в память**. Ни одного промежуточного массива не строится, и работы делается ровно
столько, сколько нужно для ответа:

```wdl
import sys.streams as streams

use (s = streams.lines("access.log")) {
    println(s.filter(l => l.contains(" 500 ")).first())
}
```

Этот скрипт читает файл **до первой строки с пятисоткой** и закрывает его. Не до
конца, не в память, не целиком.

## Зачем, если у массива уже есть `map` и `filter`

Есть, и они закрывают подавляющее большинство скриптов:

```wdl
println(prices.filter(p => p >= 100).map(p => p * 2))
```

Конвейер заведён **не вместо этого**, иначе в языке появилась бы вторая запись для
того же самого. Его ниша — четыре случая, которых массив не даёт и дать не может.

1. **Короткое замыкание сквозь стадии.** `a.map(heavy).find(p)` считает `heavy` для
   всех элементов; конвейер — до первого совпадения.
2. **Источник, которого нет в памяти.** Строки большого файла, `th.channel`,
   бесконечная последовательность.
3. **Отсутствие промежуточных копий.** `a.filter(f).map(g)` строит два массива;
   у конвейера их ноль.
4. **Конкурентная обработка.** У массива её нет и быть не должно.

Отсюда граница:

> **Массив отвечает на «преобразуй эти данные». Поток — на «протяни данные через
> конвейер, не собирая их».**

Скрипту на тысячу элементов конвейер не нужен, и брать его там незачем.

## Поток — обычное значение

`Stream` — [класс от приложения](embedding.md), а не новый тип значения:
`s is streams.Stream` работает, `use` работает, `println(s)` печатает как экземпляр.

Отдельного типа у потока нет намеренно. У ленивого значения честно **нет ответов**
на вопросы, которые тип обязан иметь: что печатает `println(s)` — обойти источник
ради печати значит устроить побочный эффект в самом безобидном месте; чему равно
`len(s)`; что пишет JSON; чему равно `s == s`.

### У потока только методы, ни одного свойства

У массива `a.size` и `a.sum` — свойства, а у потока `s.count()` и `s.sum()` — методы.
Правило [то же самое](members.md#свойство-или-метод): «устареет ли ответ». У потока
устареет любой — он потребляет поток и зависит от источника, который живёт снаружи.

## Ничего не происходит, пока не спросили

Промежуточные операции работы не делают — они только надстраивают звено:

```wdl
s = streams.range(1, 1000000).map(x => heavy(x))    // ноль вызовов heavy
println(s.first())                                   // один вызов heavy
```

Работа происходит в **терминальной операции**, и её ровно столько, сколько нужно
для ответа: `first()` — один элемент, `find(p)` — до первого совпадения, `list()` —
до конца.

Видно это лучше всего на `peek`:

```wdl
streams.range(1, 100).peek(x => println("смотрю ", x)).limit(2).list()
// смотрю 1
// смотрю 2
```

## Поток одноразовый

Пройти его дважды нельзя, и **промежуточная операция расходует его наравне
с терминальной**: `s.map(f)` не копирует конвейер, а надстраивает его.

```wdl
s = streams.of([1, 2, 3])
s.list()
s.count()       // ошибка: поток уже пройден — он читается один раз
```

Ошибка, а не тихий пустой результат: пустой ответ выглядел бы как «данных не было»,
и причину автор пошёл бы искать в источник, а не в лишнюю строку. Нужен результат
дважды — соберите его: `items = s.list()`.

## Поток — ресурс

`streams.lines(path)` держит открытый файл, поэтому класс подмешивает трейт
`Closeable` и работает с [`use`](errors.md#ресурсы-closeable-и-use) без единой правки
в языке: `use` смотрит на трейт, а не на тип.

```wdl
use (s = streams.lines("big.log")) {
    println(s.filter(l => l != "").count())
}
```

Закрытие идёт **каскадом**: `close()` последнего звена закрывает предыдущее и так
до источника. Терминальная операция закрывает сама, из `finally`, — иначе
`streams.lines(p).first()` оставил бы открытый дескриптор, а именно ради этой записи
конвейер и заводят. Поэтому `use` поверх уже пройденного потока — не ошибка и не
двойное закрытие: источником владеет тот, кто его забрал.

Забытый источник закрывается вместе с запуском: модуль держит открытые в своём
реестре и отпускает их в `close()`, как это делает `sys.gui` с недозакрытыми окнами.

## Источники

```wdl
import sys.streams as streams

streams.of(array)                  // снимок массива
streams.of(1..100)                 // из диапазона, границы включительно
streams.of(channel)                // из th.channel
streams.range(1, 100)              // то же, что of(1..100)
streams.iterate(1, x => x * 2)     // бесконечный: значение, затем шаг от предыдущего
streams.repeat(value)              // бесконечный: одно и то же
streams.lines(path)                // ленивое чтение файла, Closeable
streams.concat(a, b, c)            // склейка потоков и массивов
streams.empty()

array.stream()                     // член массива, ставит сам модуль
```

Член `stream()` появляется у массива **с `import sys.streams`** и только с ним: без
импорта его нет, ядро об этом не знает, цена нулевая. Это [расширение
типа](members.md#приложение-memberregistry) от библиотеки, такое же, какое доступно
приложению.

`streams.of` берёт **снимок** массива на входе. Иначе конвейер, собранный сейчас
и пройденный через десять строк, отвечал бы на вопрос «какие данные», заданный
в другой момент, — а ленивость и без того делает порядок работы менее очевидным, чем
у массива. То же решение уже принято для `a.map` и `a.filter`.

Источником может быть **только массив, диапазон или канал**. Строка и объект тоже
перебираемы, но «развернуть строку на буквы» почти всегда значит опечатку, а объект
перебирается ключами — и выбрать за автора одно из двух хуже, чем спросить.

### Канал вместо генератора

Отдельного `yield` в языке нет и не планируется: генератор — это корутина, то есть
либо преобразование тела функции, либо второй механизм выполнения. Библиотечный ответ
уже есть — продюсер в своём потоке пишет в канал, конвейер читает:

```wdl
import sys.streams as streams
import sys.thread as th

ch = th.channel()
th.spawn("producer", def () {
    for (i in 1..3) { ch.send(i * i) }
    ch.close()                          // иначе читатель не узнает, что работа кончилась
})

println(streams.of(ch).list())          // [1, 4, 9]
```

Поток кончается там же, где кончается цикл `while ((item = ch.take()) != null)`:
канал закрыт и пуст.

## Промежуточные операции

| Операция | Что делает |
|---|---|
| `map(f)` | преобразовать каждый |
| `filter(p)` | оставить подходящие |
| `flatMap(f)` | развернуть: `f` отдаёт массив или другой поток |
| `peek(f)` | позвать по дороге, элемент пропустить дальше |
| `limit(n)`, `skip(n)` | первые `n`; всё после первых `n` |
| `takeWhile(p)`, `dropWhile(p)` | пока условие истинно; пропускать, пока истинно |
| `zip(other)` | попарно: `[своё, чужое]` |
| `chunked(n)` | кусками по `n`; последний бывает короче |
| `windowed(n)` | скользящее окно из `n`, шаг один |
| `distinct()` | без повторов |
| `sorted()`, `sorted(by)` | упорядочить — **барьер**, см. ниже |
| `mapConcurrent(n, f)` | то же `map`, но `n` задач сразу |

```wdl
println(streams.of([1, 2, 3]).zip(streams.of(["a", "b"])).list())   // [[1, "a"], [2, "b"]]
println(streams.range(1, 5).chunked(2).list())                      // [[1, 2], [3, 4], [5]]
println(streams.range(1, 4).windowed(3).list())                     // [[1, 2, 3], [2, 3, 4]]
```

`zip` кончается там, где кончился **любой** из двух: пары без второй половины
не бывает. `chunked` отдаёт последний кусок укороченным — «последние три записи
из тысячи» это данные, а не остаток от деления. `windowed`, наоборот, неполного окна
не даёт вовсе: окна спрашивают, чтобы сравнить соседей (`w[1] - w[0]`), и окно
не того размера сломало бы именно это.

`zip` и `flatMap` расходуют переданный им поток так же, как свой.

### `sorted` — барьер

`sorted` вынужден прочитать вход целиком: пока не увиден последний элемент, неизвестен
первый. Это не дефект, но **на бесконечном источнике `sorted` не кончится никогда**,
и написано это здесь, рядом с самой операцией, а не в разделе «ограничения» в конце.

Порядок берётся у той же цепочки, что стоит за `a < b`: ядро, потом член `` `<=>` ``
у класса. Своего сравнения у конвейера нет — заведи он его, разошёлся бы с оператором
на первом же потоке экземпляров.

Необязательный аргумент — **ключ**, а не компаратор:

```wdl
println(streams.of(["aaa", "b", "cc"]).sorted(s => len(s)).list())  // ["b", "cc", "aaa"]
```

Ключ считается один раз на элемент, а не на каждое сравнение: `sorted(p => heavy(p))`
иначе звал бы `heavy` порядка `n·log(n)` раз.

### `distinct` барьером не является

Ему довольно помнить уже выданное, поэтому вход он читает по мере надобности
и на бесконечном источнике работает:

```wdl
println(streams.iterate(1, x => (x + 1) % 3).distinct().limit(3).list())   // [1, 2, 0]
```

Сравнение — то же, что стоит за `a == b`, вместе с `` def `==` `` у класса. Отсюда
и список вместо хеш-множества: хеш у значения свой, а равенство скрипт вправе
переопределить, и разойдись они — `distinct` начал бы врать ровно на тех значениях,
ради которых оператор и переопределяли. Платой остаётся память под уже выданное:
на потоке, где различного много, она уходит вся.

## Терминальные операции

| Операция | Ответ |
|---|---|
| `list()` | массив |
| `object(byKey, byValue)` | объект; совпавший ключ побеждает последним |
| `each(f)` | сколько элементов прошло |
| `reduce(f)`, `reduce(f, начало)` | свёртка слева: `f(накопленное, элемент)` |
| `count()`, `sum()` | сколько; свёртка оператором `+` |
| `min()`, `max()` | наименьший, наибольший |
| `first()`, `find(p)` | первый; первый подходящий |
| `any(p)`, `all(p)`, `none(p)` | есть ли; все ли; ни одного ли |
| `join(sep)` | склеить строкой |
| `close()` | закрыть, ничего не читая |

**Ответы у пустого потока — те же, что у пустого массива**: `count` и `sum` — ноль,
`all` и `none` — истина, `any` — ложь, `min`, `max`, `first` и `find` — `null`.
Второго набора договорённостей про пустоту в языке нет.

`reduce` берёт аргументы в том же порядке, что `a.reduce(f, 0)`: сначала свёртка,
потом необязательное начало. У пустого потока без начала — ошибка, потому что ответа
у «сверни пустое ничем» действительно нет.

У `any`, `all` и `none` условие необязательно: без него спрашивается истинность самого
элемента — тот же вопрос, что задаёт `if (item)`.

`each` отдаёт **число пройденных**, а не сам поток, — в отличие от `a.each`, который
отдаёт массив. Причина простая: массив после обхода жив, а поток пройден, и вернуть
его значило бы отдать значение, любое действие над которым — ошибка.

## Конкурентная обработка: `mapConcurrent`

```wdl
import sys.streams as streams
import sys.net.http as http

texts = urls.stream().mapConcurrent(8, u => http.get(u).text).list()
```

Восемь запросов сразу вместо восьми подряд. **Порядок результатов — порядок входа**,
а не порядок завершения: стадия обещает соответствие элементу, и «кто раньше кончил»
к делу не относится. То же правило, что у `pool.map`.

`parallel()` в модели Java здесь не заводится. Он требует делимого источника,
ассоциативного слияния и отдельного разговора про порядок — то есть половины
машинерии `Spliterator`, — а выигрыш даёт на больших вычислительных объёмах, которых
у скрипта обычно нет. И он молча ломается о побочные эффекты, что для скриптового
языка хуже, чем для Java. Здесь названо то, ради чего конкурентность в скрипте
и заводят, и число задач пишет автор — в той же строке, где видно, что именно
распараллеливается.

Потоки берутся у запуска, тем же реестром, что у `th.pool`: [квота
считается](limits.md#потоки), закрытие запуска эти потоки останавливает. Не хватило
квоты — обычная ошибка скрипта, ловимая обработчиком. Первая ошибка задачи отменяет
остальные и летит наружу **ошибкой языка**, с классом и местом:

```wdl
try {
    streams.range(1, 100).mapConcurrent(4, i => risky(i)).list()
} catch (e is ValueError) {
    println("не сложилось: ", e.message)
}
```

## Лимиты выполнения

Конвейер, у которого ни одной функции скрипта нет, — это цикл целиком внутри Java:

```wdl
streams.repeat(1).count()
streams.iterate(1, x => x + 1).skip(1000000000).first()
```

Такой цикл не проходит ни одной точки движка, поэтому **шаг отмечает сам источник**,
на каждый выданный элемент. И `maxSteps`, и `maxTime` его останавливают. Стадии шага
не отмечают: своего шага у них нет, элемент им дал источник, а обработчики считаются
сами — вызов функции скрипта и так проходит точку проверки. Подробности —
в [лимитах](limits.md#шаг-отмечает-и-библиотека).

Профиль и метрики конвейером не трогаются: стадия — не шаг скрипта, а вызовы
обработчиков уже считаются в теле функции. Второй счётчик развёл бы профиль
с лимитами в ответе на «сколько работы сделано».

## Чего у конвейера нет

* **`reversed()`** — это `sorted` наоборот и барьер вдвойне; массив разворачивается
  сам (`a.reversed`), а поток разворачивать нечем, пока он не кончился.
* **`parallel()`** — см. `mapConcurrent` выше.
* **`for (item in stream)`** — пока нет: перебором в языке заведуют четыре типа,
  и протокол перебора для значений — отдельная работа со своими решениями (что считать
  исчерпанием, как закрывать источник при `break`, попадает ли протокол в `len`
  и в `in`). Обойти поток сейчас можно `each`, а выйти на нужном элементе — `find`
  или `takeWhile`.
* **Разделение между потоками.** Поток — значение с ленивым обходом, и делить его
  между потоками нельзя: обход это много обращений подряд, а обещание языка про
  атомарность покрывает одно. Конкурентность внутри конвейера даёт `mapConcurrent`.

## Где это лежит

| Что | Где |
|---|---|
| Модуль и его функции | `wdl-stdlib/.../stdlib/streams/Streams.java` |
| Класс `Stream` для скрипта | `NativeStream.java`, состояние — `Pipeline.java` |
| Звено конвейера | `Source.java` — `next()` плюс каскадное `close()` |
| Источники, стадии, терминальные | `Sources.java`, `Stages.java`, `Terminals.java` |
| Конкурентная стадия | `Concurrent.java` |
| Шаг из библиотеки | `CallContext.step(span)` → `Run.checkpoint` |

Модель — **вытягивание** (pull): у звена есть `next()`, и оно само тянет
из предыдущего. Java выбрала проталкивание (push) и получила скорость ценой
составимости: `zip` двух потоков в push-модели не выражается — оттого его в Java
до сих пор и нет. Цена pull — виртуальный вызов на элемент на стадию; на фоне вызова
функции скрипта (кадр, точка проверки лимитов, запись профиля) это шум.

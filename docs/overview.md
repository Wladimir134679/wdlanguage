# Идея языка

wdl — маленький динамический язык, который встраивают в Java-приложение, чтобы часть
поведения можно было писать и менять без пересборки: правила игры в моде, сценарий
для бота, формулу расчёта в отчёте, реакцию на событие в сервере.

Отсюда всё остальное. Язык не соревнуется с Java в больших программах: его дело —
короткие скрипты, которые пишет человек, не обязательно знающий JVM, и которые
запускает чужое приложение, не обязанное им доверять.

```wdl
товар = {имя: "болт", цена: 12, количество: 100}
товар.цена += 3

println(товар.имя, " по ", товар["цена"], " руб.")
println("Всего на ", товар.цена * товар.количество, " руб.")
```

## Что мы обещаем читателю скрипта

**Всё — значение.** Число, строка, массив, объект, функция — всё это лежит
в переменных на равных правах. Нет «специальных» сущностей, у которых свои правила:
`println` — такое же значение, как `12`, и его можно передать дальше или положить
в поле объекта. Отдельного мира «функций» и мира «переменных» не существует —
одно пространство имён.

**Обращение одно.** `товар.цена` и `товар["цена"]` — не две операции, а одна запись
в двух видах. Поле объекта, элемент массива, ключ словаря, поле класса, а позже
функция модуля — один и тот же механизм. Это решение подробно разобрано
в [единое обращение](access.md); из него же следует, что присваивание `a.b[0] = 1`
не требует отдельной грамматики.

**Формат не влияет на смысл.** Перевод строки — обычный пробел, точка с запятой
не обязательна. Один и тот же код можно записать в строку или в столбец, и разбор
не изменится. Человек пишет так, как ему удобно читать. Ровно два места, где `;` —
часть синтаксиса, а не разделитель: заголовок `for` и
[`return`](functions.md#return), — и там она снимает двусмысленность, которую иначе
пришлось бы разрешать за автора молча.

**Ошибка объясняет, где и что.** И разбор, и выполнение показывают строку исходника
с подчёркиванием — на русском, без стектрейсов Java, которые автору скрипта ничего
не говорят:

```
склад.wdl:7:9: ошибка: индекс 5 вне границ массива размером 2
  7 | println(склад[5].имя)
    |         ^^^^^^^^
```

Одна опечатка не прячет остальные: разбор не останавливается на первой ошибке,
за один запуск видно все проблемы файла.

## Что мы обещаем приложению, которое его встраивает

**Ядро без зависимостей.** `wdl-core` не тянет ни одной внешней библиотеки — это
проверяется задачей сборки, а не обещанием в README. Движок можно положить в мод,
в Android-приложение, в чужой продукт со своим зоопарком версий, и конфликтовать
будет нечему.

**Скрипт разбирается один раз, выполняется сколько угодно.** Дерево — неизменяемые
данные без ссылок на окружение, поэтому одно и то же дерево запускается параллельно
в разных потоках с разными переменными.

```java
WdlScript script = engine.compile(Source.ofFile(path));   // разбор один раз
for (Player p : players) {
    WdlInstance instance = script.newInstance();          // своё состояние на каждого
    instance.bind("player", p);
    instance.run();
}
```

**Никакой изменяемой статики.** Всё состояние выполнения живёт в контексте, который
передаётся аргументом. Сколько создано контекстов — столько взаимно изолированных
интерпретаторов работает в одной JVM. Скрипт одного игрока не может задеть скрипт
другого, потому что делить им нечего.

**Вывод и окружение задаёт хозяин.** `println` пишет туда, куда указало приложение:
в консоль, в лог, в игровой чат, в строку теста или в никуда. Перехватывать
глобальный `System.out` не нужно.

## Как это устроено

```
Source → Lexer → List<Token> → Parser → Program (AST) → Resolver → Interpreter → выполнение
                    ↓             ↓          ↓              ↓
                 Diagnostics: ошибки с местом в исходнике, разбор не прерывается
```

Резолвер — стадия ради одного обещания: невыполненное требование
[трейта](classes.md#трейты) должно быть ошибкой при объявлении класса, а не через час
работы скрипта. Он связывает классы по именам, собирает плоские таблицы полей и методов
и ловит круг в наследовании. Скрипту без классов он ничего не добавляет.

| Модуль | Назначение |
|---|---|
| `wdl-core` | лексер, парсер, AST, значения, резолвер, интерпретатор, [API встраивания](embedding.md). Без зависимостей |
| `wdl-stdlib` | стандартная библиотека `std`: математика, `File`, `Random` |
| `wdl-api` | фасад для встраивания: `WdlEngine`, компиляция, биндинг Java |
| `wdl-tools` | линтер, форматтер, дамп AST, позже LSP |
| `wdl-cli` | запуск скриптов из консоли, REPL |

Три правила, которые держат всю конструкцию:

1. **AST — только данные.** Узлы это `record`'ы в `sealed` иерархиях: ни `eval()`,
   ни ссылки на окружение. Дерево можно печатать, сравнивать, кэшировать, оптимизировать
   и запускать где угодно.
2. **Поведение — посетители.** Интерпретатор, дамп дерева, будущие оптимизатор
   и линтер — это реализации `ExprVisitor` и `StmtVisitor`. Новый вид обхода не требует
   правки ни одного узла, а забытая ветка в `switch` по `sealed` иерархии — ошибка
   компиляции, а не сюрприз в рантайме.
3. **Позиция у каждого узла.** `Span` несут и токены, и узлы. Добавлять позиции
   задним числом всегда дороже, а без них не будет ни внятных ошибок, ни подсветки,
   ни LSP.

Парсер рукописный: рекурсивный спуск для инструкций и алгоритм Пратта для выражений,
где приоритеты заданы таблицей. Генераторы парсеров сознательно не используются —
синтаксис с необязательными скобками и без разделителей инструкций плохо ложится
на декларативные грамматики, а качество сообщений об ошибках у рукописного парсера
несравнимо выше.

## Что уже работает

* значения: `null`, логическое, число, строка, массив, объект, функция — см. [типы данных](types.md);
* выражения: арифметика, сравнения, логика, биты, условное выражение, обращение,
  вызов — см. [выражения](expressions.md);
* инструкции: присваивание (включая `+=` и запись в контейнеры), объявление константы
  `const` и вызов — см. [инструкции](statements.md);
* блок, ветвления `if`/`else if`/`else`, циклы `while` и `for`, перебор `for ... in`,
  `break` и `continue` — см. [ветвления и циклы](control-flow.md);
* функции: объявление и анонимные, тело-выражение `=>`, `return`, значения параметров
  по умолчанию, замыкания, рекурсия — см. [функции](functions.md);
* классы и трейты: `class`, `trait`, `new`, `this`, `super`, наследование, подмешивание
  `with`, требования трейтов, проверка `is`, фабрики `fun Имя.член(...)` —
  см. [классы](classes.md);
* встроенные функции `println`, `print`, `typeof`, `len`;
* стандартная библиотека `std`: `pow`, `sqrt`, `abs`, классы `File` и `Random` —
  и вместе с ней [способ добавить в язык своё](embedding.md);
* диагностика разбора, объявления и выполнения с местом в исходнике, REPL,
  дамп токенов и AST.

Ещё нет: именованных аргументов, модулей и импорта, фасада для встраивания.
Порядок работ — в конце [выражений](expressions.md#что-дальше).

## Почему язык переписан заново

Предыдущая версия (`wdlang`) работала, но три её решения упирались в потолок,
и обойти его правками было нельзя:

* **`eval()` жил прямо в узлах дерева**, а узлы держали ссылку на контекст программы.
  Дерево оказывалось привязано к одному запуску: ни параллельного выполнения,
  ни кэширования, ни честной изоляции.
* **Глобальное изменяемое состояние** — статические поля для контекста, стека вызовов
  и флага «стоп». Один интерпретатор на процесс.
* **Функции жили в отдельной таблице**, а не в переменных, поэтому функцию нельзя было
  ни передать аргументом, ни положить в поле — а значит, не было ни замыканий,
  ни методов объектов в общем виде.

Новая версия начинается с этих решений, а не приходит к ним: узлы — данные, состояние
в контексте, функция — обычное значение.

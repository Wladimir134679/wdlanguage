# Установка и запуск

Нужен JDK 21 или новее: `java` в `PATH` либо `JAVA_HOME`, указывающий на JDK.
Для сборки Gradle использует toolchain Java 21. CLI и LSP запускаются без Gradle.

## Установка команд из текущего репозитория

Windows (PowerShell, из корня репозитория):

```powershell
.\gradlew.bat installWdl
```

Linux (Bash / Zsh):

```bash
chmod +x ./gradlew  # один раз после checkout: wrapper пока хранится в Git без executable-bit
./gradlew installWdl
```

Задача собирает все модули и дистрибутивы CLI/LSP/DAP. Устанавливает **для текущего
пользователя**, без прав администратора:

* `WDL_HOME` → `<репозиторий>/wdl-cli/build/install/wdl`;
* `WDL_LSP_HOME` → `<репозиторий>/wdl-lsp/build/install/wdl-lsp`;
* `WDL_DAP_HOME` → `<репозиторий>/wdl-dap/build/install/wdl-dap`;
* все три каталога `bin` добавляются в `PATH`.

На Windows меняется пользовательское окружение в реестре; системный `PATH`
сохраняется. Повторная установка не дублирует пути, при смене checkout заменяет
пути предыдущей установки. **Перезапустите терминал и IDEA**: уже открытый процесс
не может получить новое окружение от дочернего Gradle.

На Linux создаётся `${XDG_CONFIG_HOME:-~/.config}/wdl/env.sh`, подключаемый из
`~/.profile`, `~/.bashrc`, `${ZDOTDIR:-~}/.zshrc` и существующего login-профиля Bash.
Повторный запуск обновляет этот файл. Для текущего терминала выполните напечатанную
установщиком команду `. '/путь/к/env.sh'`. Для приложений рабочего стола может
потребоваться повторный вход в сеанс; если окружение рабочего стола не читает
`.profile`, запускайте IDEA из настроенного терминала или укажите пути явно.
Fish автоматически не настраивается.

Это установка **со ссылкой на текущий checkout**, а не копия в системный каталог.
После изменения исходников повторите `installWdl`. После `clean` нужно снова
собрать дистрибутивы; после перемещения репозитория — повторить установку.

## Команды

Из любого рабочего каталога:

```bash
wdl --help
wdl script.wdl
wdl --metrics script.wdl -- "два слова" --verbose
wdl /path/to/project -- arg1 arg2
wdl .
wdl --repl
wdl-lsp --stdio
wdl-lsp --socket=5007
wdl-dap
wdl-dap --socket=5005
```

`wdl-dap` — адаптер отладки: его запускает редактор, а не человек. Что он умеет
и какими полями просят запуск, описано в [docs/debugging.md](debugging.md).

На Windows пути могут быть вида `D:\scripts\main.wdl`; пути с пробелами заключайте
в кавычки. Если передан каталог, выполняется его `main.wdl`. Для другой точки
входа укажите файл явно: `wdl project/tools/build.wdl`.

Параметры интерпретатора (`--metrics`, `--debug`, `--ast`, `--tokens`) идут до `--`.
После `--` все параметры передаются скрипту без интерпретации, в массиве строк
`args`; имя файла в массив не входит. Без аргументов это пустой массив.

```wdl
println(args)
```

Рабочий каталог остаётся каталогом вызывающего процесса. Относительные операции
с файлами выполняются от него; все импорты модулей разрешаются от корня проекта.
Он задаётся через `--project-root <каталог>`, а по умолчанию равен каталогу
исполняемого файла. `wdl project` не выполняет `cd project`.

Например, `wdl --project-root . examples/testing/errors.wdl` использует корень
текущего проекта: импорт библиотеки в этом случае — `examples.testing.lib.test`.
В IDEA плагин автоматически передаёт корень открытого проекта и интерпретатору,
и LSP. Это действует также для ранее сохранённых конфигураций запуска.
Рабочий каталог влияет на файловые операции скрипта, но не на импорты.
Переопределять `--project-root` в параметрах wdl нельзя; для другого корня
откройте нужный каталог как проект IDEA.

Вызов из приложения: запускайте `wdl` / `wdl-lsp` как отдельный процесс. Для LSP
используйте stdin/stdout, stderr оставляйте для диагностики. Для встраивания в JVM
используйте модуль `wdl-api`, а не CLI.

## IntelliJ IDEA

```powershell
.\gradlew.bat prepareWdl
```

На Linux: `./gradlew prepareWdl`. Задача проверяет все модули, собирает дистрибутивы
и плагин; окружение не меняет. Только плагин: `./gradlew buildIdeaPlugin`.
Полная подготовка с установкой команд: `./gradlew prepareWdl installWdl`.
Первая сборка плагина скачивает дистрибутив IDEA.

1. В **Settings → Plugins → ⚙ → Install Plugin from Disk** выберите
   `ide/idea-plugin/build/distributions/wdl-idea-plugin-0.1.1.zip` и перезапустите IDE.
2. Откройте `.wdl`, выберите **Run** в контекстном меню файла либо зелёный значок
   у начала файла. Созданная конфигурация доступна через зелёную кнопку на панели.
3. В **Run → Edit Configurations → + → wdl** можно вручную создать конфигурацию:
   файл или каталог с `main.wdl`, рабочий каталог, параметры wdl, аргументы скрипта.
   Кавычки в полях параметров объединяют слова в один аргумент; `--` добавляется
   автоматически. Пустой рабочий каталог означает корень проекта IDEA.
4. Поле интерпретатора оставьте пустым для поиска через `WDL_HOME`, сборку внутри
   проекта и `PATH`, либо укажите полный путь к `bin/wdl.bat` / `bin/wdl`
   **из Gradle-дистрибутива**. Для LSP можно явно задать `WDL_LSP_HOME`.

Плагин запускает Java напрямую из `JAVA_HOME` или `PATH`, с JAR из соседнего `lib`;
параметры не проходят через shell. `JAVA_OPTS` / `WDL_OPTS` стартовых shell-скриптов
в IDEA не применяются. Вывод и ввод доступны в стандартной консоли Run, остановка —
кнопкой Stop. Отладчик WDL с breakpoint пока не реализован.

Кнопка **Профилировать** рядом с «Запустить» выполняет ту же конфигурацию с
`--profile-out` и показывает отчёт в окне **wdl Profile**: горячие функции таблицей
и дерево вызовов, двойной щелчок открывает объявление. Флажка в конфигурации для
этого нет и не нужно — профилирование это действие. Под ним скрипт идёт медленнее:
профиль считает каждый вызов ([docs/profiling.md](profiling.md)).

В репозитории есть общая конфигурация `wdl: hello` в `.run/`. Она запускает
`examples/language/hello.wdl`; параметры можно менять в Edit Configurations.

Текущий плагин требует IDEA Ultimate 2025.3+ из-за используемого LSP API.
Run-конфигурации реализованы через стандартные расширения платформы:
[Run Configurations, IntelliJ Platform SDK](https://plugins.jetbrains.com/docs/intellij/run-configurations.html).

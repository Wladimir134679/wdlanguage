# Классы

Класс в wdl — **запись с поведением**: заголовок перечисляет поля, тело перечисляет
методы. Ничего третьего в классе нет.

Рабочие примеры по возрастанию: [`examples/classes.wdl`](../examples/classes.wdl) —
один класс, [`examples/inheritance.wdl`](../examples/inheritance.wdl) — цепочка
и `super`, [`examples/traits.wdl`](../examples/traits.wdl) — трейты,
[`examples/modules/inherit.wdl`](../examples/modules/inherit.wdl) — то же самое
через файлы.

```wdl
class Point(x = 0, y = 0) {

    def move(dx, dy) {
        x += dx                     // x — поле: внутри класса оно видно по имени
        y += dy
    }

    def text() => "(" + x + ", " + y + ")"
}

p = new Point(20, 30)
p.move(10, -5)
println(p.text())               // (30, 25)
println(p)                      // Point{"x": 30, "y": 25}
```

Всё остальное в этом документе — следствия трёх решений, которые язык уже принял:
[всё — значение](overview.md#что-мы-обещаем-читателю-скрипта),
[обращение одно на все типы](access.md) и
[функция — значение с замыканием](functions.md). Класс не заводит для себя ни нового
пространства имён, ни особого вызова, ни отдельного правила доступа к полю.

## Заголовок — это поля

Список параметров класса задаёт и параметры создания, и набор полей. Отдельного
объявления полей нет.

```wdl
class Item(name, price, count = 0)

item = new Item("болт", 12)
println(item.name, " по ", item.price, ", на складе ", item.count)   // болт по 12, на складе 0
println(item)                       // Item{"name": "болт", "price": 12, "count": 0}
```

Тело можно не писать вовсе — класс без методов законен и полезен: это структура данных
с именем, которую видно в `typeof`-подобной проверке `is` и в печати. Заголовка тоже
может не быть: `class Marker` — законный класс без полей.

**Почему заголовок, а не объявления в теле.** Поля, разбросанные по конструктору,
нельзя перечислить, не выполнив его: до запуска неизвестно, какие ветки отработали.
Заголовок же читается глазами и известен движку до всякого выполнения — отсюда
и проверка числа аргументов до входа в конструктор (та же, что у
[функций](functions.md#ошибки)), и внятная печать, и будущая проверка `item.prcie`
линтером.

[Значения по умолчанию](functions.md#значения-по-умолчанию) достаются даром: это тот
же список параметров с теми же правилами — выражение вычисляется на каждом создании,
обязательный параметр не может идти после необязательного.

## Создание — `new`

```wdl
p = new Point(20, 30)
```

`new` — часть выражения, слева от скобок может стоять что угодно, что даёт класс:

```wdl
kinds = [Point, Item]
p = new kinds[0](1, 2)

def build(cls, a, b) => new cls(a, b)
q = build(Point, 3, 4)
```

Класс остаётся обычным значением в обычной переменной — его можно передать,
положить в массив и в поле объекта. `new` говорит не «здесь имя класса», а «создай
экземпляр того, что получится слева».

`new` забирает себе ровно одно обращение и один список аргументов, а всё, что идёт
дальше, применяется уже к экземпляру, — как в Java, и по той же причине: иначе
`new Circle(5).area()` пришлось бы писать в скобках, а читается оно однозначно.

```wdl
println(new Circle(5).area())       // создаётся Circle, у него зовётся area
```

**Почему не вызов класса как функции.** `Point(20, 30)` короче, но тогда создание
объекта и вызов функции выглядят одинаково, а стоят они разного: первый заводит
новое состояние, второй — нет. Слово на месте создания — единственная разница
в тексте между «посчитать» и «породить», и она стоит четырёх букв.

Поля заголовка можно называть по именам — правило то же и то же самое, что у
[вызова функции](functions.md#именованные-аргументы), потому что список аргументов
в скобках в языке один:

```wdl
class Point(x, y = 0) {}
p = new Point(y: 3, x: 1)           // порядок свободный
q = new Point(1)                    // как раньше
```

Оттуда же и [раскрытие](functions.md#раскрытие-массива-и-объекта): готовый массив
и готовый объект раскрываются и в `new`, и в заголовке родителя.

```wdl
class Point(x, y) {}
class Shape(kind, title = "фигура") {}
class Circle(parts) : Shape(*parts) {}

new Point(*[3, 4])
new Point(**{x: 5, y: 6})
new Circle(["round", "круг"])
```

Имена полей есть и у классов, встроенных приложением, — они объявлены в его коде,
поэтому `new Window(title: "Счёт", width: 400)` работает без всякой отдельной работы.

### Остаток в заголовке: `*args` и `**named`

Заголовок класса собирает остаток теми же двумя формами, что и заголовок функции:

```wdl
class Box(x, *rest, **named) {
    def Box() {
        println(x, " ", rest, " ", named)
    }
}

new Box(1, 2, 3, tag: "ok")         // 1 [2, 3] {"tag": "ok"}
```

Правила ровно те же, [что у функции](functions.md#вариативные-параметры-и-раскрытие):
остаток заканчивает заголовок, `*rest` собирает лишние позиционные аргументы,
`**named` — имена, которых среди параметров нет. С остатком у создания пропадает
верхняя граница числа аргументов, а обязательные параметры обязательными и остаются.

**Отличие от параметров одно: остаток не становится полем.**

```wdl
class Box(x, *rest, **named) {}
b = new Box(1, 2, tag: "ok")
println(len(b))                     // 1 — поле ровно одно
println(b)                          // Box{"x": 1}
```

Причина не в экономии. Заголовок задаёт поля позиционными параметрами, у каждого поля
есть номер параметра, а остаток позиции не занимает — та же формулировка, что уже
действует у функции. И следствие важнее причины: главный потребитель остатка —
[класс-обёртка из декоратора](decorators.md#обёртка-для-класса-это-наследник), а
обёртка обязана быть незаметной. Стань `rest` полем — два лишних ключа увидели бы
и перебор по объекту, и `len`, и печать, и обёртка перестала бы быть прозрачной.

Виден остаток там, где выполняется заголовок: в аргументах родителю и в конструкторе
своего класса. Правее остатка параметров не бывает, так что значений по умолчанию,
которым он мог бы понадобиться, не существует.

```wdl
class Base(all, size) {
    def Base() => println(all, " ", size)
}
class Head(size, *rest) : Base(rest, size) {}

new Head(3, 1, 2)                   // [1, 2] 3
```

Ради этого остаток и заводился: без него класс-наследник не мог бы перебросить
родителю то, что получил.

```wdl
class Proxy(*args, **named) : Target(*args, **named) { }
```

**У трейта остатка нет.** Заголовок трейта задаёт поля и требования к классу,
а конструктора, которому эти аргументы можно было бы перебросить, у трейта нет —
собирать остаток некому и незачем.

## Конструктор — метод с именем класса

Если заголовка мало — нужно проверить значения, нормализовать их или посчитать
производное поле, — в теле объявляется метод с именем класса:

```wdl
class Point(x = 0, y = 0) {

    def Point() {
        if (x < 0) x = 0            // x — это поле: правится оно
        if (y < 0) y = 0
        length = x + y              // ...а это новое имя, и полем оно не станет
        this.length = length        // производное поле заводится явно
    }
}

p = new Point(-5, 10)
println(p)                          // Point{"x": 0, "y": 10, "length": 10}
```

**Тело конструктора выполняется, когда объект уже собран.** Порядок такой:

1. проверяется число аргументов — по заголовку, до входа внутрь;
2. заводится пустой экземпляр, в его области связывается `this`;
3. заполняются все поля — родителя, [трейтов](#трейты) и свои,
   [по одной плоской таблице](#поля-собираются-в-плоскую-таблицу);
4. выполняется тело конструктора **родителя**, если оно есть;
5. выполняется тело `def Point()`, если оно есть;
6. экземпляр готов.

К шагу 5 в `this` уже всё: поля родителя, поля трейтов и свои. Поэтому в конструкторе
можно посчитать производное поле от чего угодно, проверить инвариант целиком
и — главное — отдать объект наружу:

```wdl
class Session(user, at) {
    def Session() {
        registry.add(this)          // объект полный, регистрировать его безопасно
    }
}
```

**Отдельного «до записи» в языке нет.** Оно понадобилось бы, будь поля неизменяемыми,
как у Java-рекорда, — там компактный конструктор правит параметры вынужденно. Здесь
поля обычные, и правка поля после записи делает ровно то же самое, зато `this`
не бывает наполовину собранным, а служебное имя в классе остаётся одно.

### Поле видно по имени, без this

Внутри класса `имя` — это `this.имя`: `x` и `this.x` — **одна и та же ячейка**,
а не две. Методы тоже: `area()` и `this.area()` — один и тот же вызов.

```wdl
def Point() {
    if (x < 0) x = 0                // то же самое, что this.x = 0
}
```

Это не исключение для классов, а [общее правило языка](functions.md#область-видимости-что-внутри-что-снаружи):
имя, которое снаружи есть, именно меняется, а не заводится заново. Экземпляр —
просто ещё одно «снаружи», и самое близкое:

```
локальные имена вызова → экземпляр (поля, затем методы) → область объявления класса → глобальные
```

Порядок внутри экземпляра тот же, что [при обращении по ключу](#что-такое-экземпляр):
сначала поля, потом методы. Одно правило на две записи — иначе `имя` и `this.имя`
разошлись бы в каком-нибудь углу, и объяснять пришлось бы оба.

Отсюда всё остальное само:

* **новое имя полем не становится** — `length = x + y` заводит обычную локальную
  переменную в области вызова, и поле из неё сделает только явное `this.length = ...`.
  Иначе каждая временная переменная превращалась бы в поле;
* **имя метода полем тоже не становится** — присваивание смотрит только поля, поэтому
  `text = "x"` внутри метода при существующем методе `text` заводит локальную
  переменную, а не подменяет поведение. Методы живут в классе, а не в экземпляре,
  и подменить их у одного объекта можно только явным `this.text = ...`;
* **параметр метода перекрывает поле** — параметры всегда локальны, и это единственный
  способ получить гарантированно своё имя. Отсюда привычное `this.name = name`;
* **`this` остаётся нужен ровно там, где нужен**: передать объект целиком, пробиться
  сквозь одноимённый параметр и завести новое поле.

```wdl
class User(name) {
    def rename(name) {              // параметр перекрыл поле
        this.name = name            // ...поэтому this обязателен
    }
    def greet() => "привет, " + name // а здесь перекрывать нечему
}
```

Цена та же, что у языка без объявлений вообще: временная переменная в методе,
случайно совпавшая с именем поля, изменит поле. Это ровно тот случай, для которого
в [функциях](functions.md#область-видимости-что-внутри-что-снаружи) уже намечено
лекарство — слово объявления или предупреждение резолвера имён.

### Перегрузки конструкторов не будет

```wdl
class User(name, password, age = null) {
    def User() {
        if (age == null) age = 0    // «не передали» отличимо от «передали 0»
    }
}

new User("wdeath", "секрет")
new User("wdeath", "секрет", 33)
```

Разное число аргументов — это [значения по умолчанию](functions.md#значения-по-умолчанию),
и они уже есть. Двух конструкторов с одним именем в языке быть не может по той же
причине, по которой нет [перегрузки методов](#чего-в-классах-не-будет): пространство
имён одно, а два значения по одному ключу не лежат. И читать такой код пришлось бы
пересчётом запятых в вызове.

Другие способы создания — с другими данными или с параметром, который не должен
становиться полем, — получают **имена**: см. [фабрики](#класс--тоже-значение).

## Методы

Метод — это [обычная функция](functions.md), объявленная в теле класса. Одна на класс,
а не своя копия у каждого экземпляра: у объектов разное состояние, а не разное
поведение.

Замыкание метода — область, где объявлен **класс**, поэтому глобальные имена методу
видны. Поля видны ещё раньше — [они ближе](#поле-видно-по-имени-без-this):

```wdl
SUFFIX = " руб."

class Item(name, price) {
    def text() => name + ": " + price + SUFFIX      // поле, поле, глобальная
}
```

**Оператор — такой же метод**, только имя записано в обратных кавычках:
`` def `+`(right) ``, `` def `<=>`(other) ``, `` mirror def `/`(left) ``. Полная
таблица — в [выражениях](expressions.md#перегрузка-операторов).

Тело класса содержит только объявления методов, [свойств](#свойства) и конструктор.
Любая другая инструкция —
ошибка разбора: класс это описание, а не код, который что-то делает в момент объявления.

```
shop.wdl:3:5: ошибка: в теле класса допустимы только объявления функций и свойств,
а здесь имя 'x'. Начальные значения полей задаются в заголовке
```

**Тело метода — это `{ ... }` или `=> выражение`, и ничего третьего.** Одиночная
инструкция без скобок, разрешённая у `if` и циклов, здесь запрещена, и причина
в [требованиях трейта](#трейты): у `def report()` тела нет, а следующей строкой
идёт `def full() => ...`. Разреши мы инструкцию без скобок — второе объявление
молча стало бы телом первого.

## Свойства

> Свойство — это имя, за которым стоит **код**, а не ячейка.

Читается и пишется оно тем же обращением, что поле, — `r.area` и `r["area"]`
одинаково зовут getter, — но между обращением и значением встаёт вызов.

```wdl
class Rect(w, h) {
    property area => this.w * this.h        // короткая форма: только чтение

    property side {
        def get() => this.w

        def set(value) {
            this.w = value
            this.h = value
        }
    }
}

r = new Rect(10, 20)
println(r.area)         // 200
r.w = 15
println(r.area)         // 300 — считается заново на каждом чтении
r.side = 4              // зовёт set
```

`property` — **контекстное слово, а не ключевое**: член тела класса иначе может
начаться только с `def` или `synchronized`, поэтому слово, за которым стоит имя,
ни с чем не спутать. Переменная `property` в чужом скрипте продолжает работать,
и метод так назвать тоже можно — он начинается с `def`.

### Правила чтения и записи

Чтение `obj.name` — четыре шага, остановка на первом попадании:

1. собственное поле экземпляра;
2. **свойство класса — вызвать getter**;
3. метод класса — вернуть [связанную функцию](#методы);
4. `null`.

Запись `obj.name = value`:

1. существующее поле — заменить;
2. **свойство с setter — вызвать setter**;
3. свойство без setter — ошибка «только для чтения»;
4. иначе — завести поле, как у обычного объекта.

Третий пункт — единственное место, где обращение к объекту **не** заводит новый
ключ. Причина в том, что имя уже занято: положить рядом второе значение под тем же
именем нельзя, а промолчать значило бы, что запись как будто прошла.

```
свойство 'area' класса 'Rect' только для чтения: у него нет 'def set(value)'
```

**Составное присваивание — один getter и один setter.** `w.size += 100` читает
один раз, складывает, пишет один раз: место вычисляется один раз, ровно как
у `t[k()] += 1`, где `k()` тоже зовётся однажды.

### Свойство и поле — одна ячейка имени

Оба — «место, которое читают и пишут», и отличается только то, стоит ли за именем
значение или код. Поэтому в плоской таблице они делят имя, и работает обычное
правило «побеждает последний»:

```wdl
class Shape(area)
class Rect(w) : Shape(0) { property area => this.w * 2 }   // свойство поверх поля

class Base(w) { property area => this.w * 2 }
class Fixed(w, area) : Base(w)                             // поле поверх свойства
```

Ради этого свойства и заведены: поле можно заменить вычисляемым свойством, не тронув
ни одного места, которое его читает.

**А вот свойство и метод под одним именем — ошибка связывания.** Это единственное
место, где плоские таблицы отступают от «побеждает последний», и отступают по делу:
свойство даёт значение, метод — функцию, которую потом зовут. Молчаливый выбор
одного из двух означал бы, что `obj.size` в одном месте число, а в другом функция,
и разницу видно только по объявлению предка.

```
в классе 'Rect' имя 'size' занято и свойством (из 'Rect'), и методом (из 'Shape'):
свойство даёт значение, метод — функцию, и выбрать за вас язык не станет
```

### Внутри класса имя работает так же

Правило [«поле видно по имени»](#поле-видно-по-имени-без-this) распространяется
на свойства целиком — и на чтение, и на запись:

```wdl
class Rect(w, h) {
    property size {
        def get() => this.w
        def set(value) { this.w = value }
    }

    def resize(n) { size = n }          // зовёт setter, а не заводит переменную
    def report() => size               // зовёт getter
}
```

Иначе `size = n` молча завёл бы локальную переменную вместо записи — тихая ошибка,
которой в коде не видно. Цена та же, что у поля: имя, занятое свойством, локальной
переменной уже не станет.

### Скрытое поле: `field`

`property x = 0` заводит место для значения — но **не среди полей объекта**:

```wdl
class Box() {
    property size = 0 {
        def get() => field

        def set(value) {
            field = value < 0 ? 0 : value      // инвариант в одном месте
        }
    }
}

b = new Box()
b.size = -3
println(b.size)     // 0
println(b)          // Box{} — скрытого поля не видно
```

Лежи такое поле среди обычных пар — и правило чтения «сначала собственное поле»
побеждало бы, а getter не вызывался никогда; вдобавок `size` попадал бы в перебор,
в `len` и в печать, то есть скрытым бы не был.

`field` — **обычное имя, которое заводит область аксессора**, устроенное ровно как
`this`. Ключевым словом его делать нельзя: слово `field` встречается в скриптах
переменной, и отнимать его ради одного места было бы плохой сделкой. Вне аксессора
свойства со скрытым полем это имя разрешается по общему правилу — снаружи.

Начальное значение вычисляется при создании, там же и тогда же, где значения полей,
и видит заголовок своего класса: `property x = w * 2` работает.

### Форма аксессоров

`def get()` — ровно ноль параметров, `def set(value)` — ровно один, без значений
по умолчанию и без остатков: свойство читают обращением, а у обращения аргументов
нет. `synchronized` у свойства не бывает — замок экземпляра берёт
[synchronized-метод](threads.md), а свойство читают внутри выражения, где такой
замок всё равно ничего не склеит.

**Свойство только для записи не заводится.** Значение, которое нельзя прочитать, —
приглашение к опечатке: `obj.x = 1` проходит, `obj.x` молча даёт `null`.

### Чего свойство не делает

* **Не даёт ссылку на место.** `x = window.width` кладёт в `x` число; передать
  «саму ячейку» нельзя, потому что ссылок в языке нет вовсе. Кому нужно поведение,
  передаёт функции:

  ```wdl
  reader = def () => window.width
  writer = def (value) { window.width = value }
  ```

* **Не участвует в переборе, `len` и печати.** Среди пар экземпляра его нет —
  ровно как нет метода.
* **Не обещает атомарности.** [Одно обращение атомарно](threads.md) — обещание
  про ячейку, а обращение к свойству это вызов, и вызов целиком не атомарен.
  `w.width += 1` из двух потоков теряет обновление там, где обычное поле его
  не теряло бы.

Тем же протоколом устроены свойства и методы **встроенных типов** — `text.upper`,
`a.sort()`, `213.toString()`: один механизм на класс, на тип и на приложение,
и правила чтения, записи и невидимости в переборе у них общие. Описание —
в [членах значений](members.md). Оттуда же приходит `extend`: расширить своими
членами можно и класс, а не только тип.

## `this` — обычное имя

`this` не магия вызова, а имя, заведённое в области конструктора и метода наравне
с параметрами. Из этого следует три вещи, которых в языках с «динамическим `this`»
нет.

**Метод — значение, и он помнит свой объект.** Чтение метода даёт связанную функцию,
поэтому его можно передать, положить в поле и вызвать позже:

```wdl
p = new Point(1, 2)
handler = p.text
println(handler())              // (1, 2) — объект не потерялся
```

Это ровно то, что [обещано в «едином обращении»](access.md#что-из-этого-уже-выросло):
отдельного «вызова метода» в языке нет, `p.text()` — это обращение по ключу, давшее
функцию, и её вызов.

**Поля и `this` видны вложенной функции.** Она замыкает область метода, а область
экземпляра — [часть цепочки](#поле-видно-по-имени-без-this):

```wdl
class Basket(items, rate) {
    def report() {
        for (item in items) {
            // rate — поле, и внутри анонимной функции оно то же самое: это обычное
            // замыкание, а не подставленный при вызове приёмник
            show = def() => println(item.name, ": ", item.price * rate)
            show()
        }
    }
}
```

В JavaScript такой код до появления стрелочных функций терял объект, и терял его
именно потому, что `this` там связывался вызовом. Здесь связывать нечего: имя заведено
в области, а области замыкаются [по общему правилу](functions.md#замыкания).

**`this` вне класса — ошибка разбора**, а не выполнения: парсер знает, внутри класса
он сейчас или нет, — как знает про [`return` вне функции](functions.md#return).
Присвоить `this` тоже нельзя: это имя самого объекта, а не переменная для хранения.

## Что такое экземпляр

Экземпляр — это [объект](types.md#объект) со ссылкой на класс. Не восьмой тип
значения: `typeof(p)` даёт `object`, и всё, что умеет объект, экземпляр умеет тоже.

В коде это `InstanceObjectValue` — наследник `MapValue`, той самой карты пар,
из которой сделан обычный объект. Наследник, а не поле в карте: ссылка на класс,
точка отсчёта для `super` и корневой экземпляр нужны экземпляру и бессмысленны
у литерала `{}`, а объектов в скрипте всегда больше, чем экземпляров. Наследование
при этом ничего не отнимает — любая операция над объектом принимает и то и другое.

```wdl
p = new Point(20, 30)

println(p.x)                    // 20 — поле
println(p["x"])                 // 20 — то же обращение, другая запись
println(p[field])               // ключ можно вычислить
for (name in p) println(name, " = ", p[name])   // перебор полей
println(len(p))                 // 2 — полей два
```

Поиск по ключу идёт сверху вниз и останавливается на первом попадании:

| Порядок | Где ищем | Что вернётся |
|---|---|---|
| 1 | поля экземпляра | значение поля |
| 2 | методы, собранные классом при объявлении | метод, связанный с этим экземпляром |
| 3 | нигде не нашлось | `null` — как у обычного объекта |

Таблица методов у класса **одна и плоская**: она собрана один раз при объявлении
из родителя, [трейтов](#трейты) и собственных методов — по правилу
[«побеждает последний»](#последний-побеждает). Поиска по цепочке во время выполнения
нет: обращение к методу стоит столько же, сколько обращение к полю, и не зависит
от глубины наследования.

### Поля собираются в плоскую таблицу

Точно так же — и поля. При объявлении класса собирается список: имя поля и откуда
берётся его значение (параметр класса, значение по умолчанию трейта, параметр
родителя). Одинаковые имена схлопываются там же, [по тому же правилу](#последний-побеждает),
и в таблицу попадает один победитель.

Поэтому при создании каждое поле записывается **ровно один раз**, и никакого «сначала
записали, потом затёрли» не бывает. Порядок вычисления при этом естественный: сначала
свои параметры (их видят аргументы родителя), затем родительская часть, затем
значения по умолчанию трейтов.

Про перекрытые имена язык обещает две разные вещи, и они не симметричны:

* **аргументы родителя вычисляются всегда**, слева направо и ровно один раз, даже
  если одноимённое поле перекрыто своим параметром. Это список аргументов, а не
  источник поля, и побочный эффект в нём не должен зависеть от того, какие имена
  завёл потомок;
* **значение по умолчанию трейта для проигравшего поля не вычисляется** — оно
  [подставляется скрыто](#требования-проверяются-при-объявлении-класса), а скрытое
  не должно быть наблюдаемым.

Печатается экземпляр в порядке таблицы — родитель, трейты, свои, — а поля, заведённые
конструктором через `this`, идут после них.

**Поле перекрывает метод**, и это не случайность: `p.text = def() => "иначе"` —
законная подмена поведения у одного объекта, обычная в динамическом языке. А `null`
в конце вместо ошибки — то же решение, что у объекта: проверка `if (p.print)` должна
просто работать.

Методы при переборе не появляются: они живут в классе, а не в экземпляре. Поэтому
`for (name in p)` — это перебор данных, а не данных вперемешку с поведением.

## Наследование

```wdl
class Shape(name) {
    def area() => 0
    def text() => name + " площадью " + area()      // area() ≡ this.area()
}

class Circle(radius) : Shape("круг") {
    def area() => 3.14159 * radius * radius
}

c = new Circle(5)
println(c.text())               // круг площадью 78.53975
println(c.name)                 // круг — поле досталось от родителя
```

После `:` стоит выражение, дающее класс, и аргументы его заголовка. Аргументы — тоже
выражения, и вычисляются они в области конструктора, где параметры потомка уже связаны:

```wdl
class Square(side) : Shape("квадрат со стороной " + side)
```

Их тоже можно назвать по именам, и здесь у языка есть преимущество перед обычным
вызовом: **имена в заголовке родителя проверяются при объявлении класса**, а не при
первом `new`. Форма родителя известна ровно тогда, когда класс связывается, — та же
причина, по которой [требования трейтов](#требования-проверяются-при-объявлении-класса)
проверяются там же.

```wdl
class Circle(r) : Shape(name: "круг")
class Broken(r) : Shape(nmae: "круг")   // ошибка на этой строке, до всякого создания
```

Поля экземпляра — это поля родителя плюс поля [трейтов](#трейты) плюс свои.
Одноимённое поле или метод — не ошибка, а перекрытие по общему правилу:
[побеждает последний](#последний-побеждает).

Добраться до реализации родителя можно через `super`:

```wdl
class Circle(radius) : Shape("круг") {
    def area() => 3.14159 * radius * radius
    def text() => super.text() + " (радиус " + radius + ")"
}
```

`super` — такое же обычное имя, как `this`, и такое же обычное значение: это **тот же
экземпляр, но поиск методов начинается с родителя**. Поля у него те же самые,
не копия, и `super == this` — истина. Поэтому `super` не спецформа: его можно положить
в переменную, и работать он будет так же.

Родитель при этом берётся у **того класса, где написан метод**, а не у класса
экземпляра. Метод `Shape.text()`, доставшийся кругу, зовёт родителя `Shape` — иначе
в цепочке из трёх классов `super` зациклился бы. А голое имя внутри такого метода
по-прежнему ищется в классе экземпляра: `area()` внутри `Shape.text()` найдёт
реализацию круга, и `area()` с `this.area()` там не расходятся.

`super` вне класса и `super` у класса без родителя — ошибки разбора, как и `this`
вне класса. В трейте `super` тоже запрещён: трейт не знает, в какой класс его
подмешают, и отвечать на вопрос «кто там родитель» было бы гаданием.

**Родитель ровно один.** Не потому, что нечем разрешать конфликты — правило
[«побеждает последний»](#последний-побеждает) их разрешает, — а потому, что
у родителя есть конструктор. Два родителя это два конструктора, и порядок их вызова
пришлось бы задавать правилом, а ромб (два родителя от одного предка) — решать,
выполняется общий конструктор один раз или два. Ни один ответ на это не бывает
очевидным при чтении чужого скрипта.

У [трейта](#трейты) конструктора нет, поэтому трейтов подмешивается сколько угодно:
поля с готовыми значениями и методы складываются в один плоский набор, и складывать
их можно в любом количестве.

### Ссылка на родителя — выражение

Класс — [обычное значение](#класс--тоже-значение), и в заголовке он берётся оттуда же,
откуда любое другое: по имени, по ключу, из результата вызова. То же и для трейтов
после `with`.

```wdl
class Circle : Shape("круг")                    // имя — основная форма
class Square : m.Shape("квадрат")               // класс из модуля
class Deep   : w.m.Shape("глубоко")             // модуль модуля
class ByKey  : registry.classes["Shape"]("по ключу")
class ByCall : registry.classFor("shape")("вызовом") with plugins["Logged"]
```

Разбирается такая ссылка **цепочкой обращений и вызовов** — `.имя`, `[ключ]`,
`(аргументы)` — и ничем больше. Любой бинарный оператор цепочку обрывает: `class A : x + y`
не разберётся, и это нарочно. Складывать классы незачем, а внятная ошибка на разборе
лучше вычисления неизвестно чего в заголовке.

**Последние скобки — аргументы заголовка, а не вызов.** Иначе `Shape("круг")` — основная
форма записи — означало бы «вызвать `Shape` и наследоваться от того, что вернулось».
Поэтому:

```wdl
class A : make("x")     // родитель make, аргумент "x"
class B : make()        // родитель make, аргументов нет
class C : make()("x")   // а вот здесь make вызывается, и аргумент "x" уходит результату
```

Вызову внутри цепочки это не мешает — важна только последняя операция:
у `registry.all()["Shape"]` она обращение, и скобки достаются `all`. У трейта скобки
всегда вызов: передавать ему нечего, конструктора у него нет.

Ссылка-выражение при этом ничем не отличается от простого имени по времени жизни:
[объявление существует со своей строки](#родитель-объявляется-выше-потомка) в обоих
случаях, и вычисляется ссылка тогда же, когда выполняется само объявление.

```wdl
new Later("рано")                          // ошибка: переменной 'Later' ещё нет
class Later(t) : registry["Base"](t)
```

Проверки при этом не сдвигаются никуда: требования трейтов и число аргументов родителю
[по-прежнему](#требования-проверяются-при-объявлении-класса) проверяются на строке
`class`, каким бы выражением ни был получен тип. А `is` работает через любую запись —
сравниваются формы, а не то, как до класса дотянулись:

```wdl
println(new ByKey() is Shape)   // true
```

## Трейты

**Трейт** — от английского *trait* (из французского *trait* «черта, штрих»): характерная
особенность, черта поведения. Здесь это и есть черта поведения класса — то, что класс
получает целиком, вместе с состоянием и реализациями. Ключевое слово в языке английское
(`trait`), в русском тексте слово пишется транслитерацией — как в Rust, Scala и PHP.
Перевода «типаж» мы избегаем сознательно: он созвучен «типу», а
[тип значения](types.md) — другое понятие, и показывает его `typeof`.

Трейт устроен как класс, у которого забрали конструктор: заголовок перечисляет поля,
тело перечисляет методы. Отличие ровно одно и оно определяет всё остальное —
**в трейте и поле, и метод бывают требованием**:

| Запись | Что это |
|---|---|
| `count = 0` в заголовке | поле с готовым значением — класс о нём не заботится |
| `limit` в заголовке | **требование**: класс обязан объявить поле `limit` сам |
| `def full() => ...` | готовый метод — вспомогательная возможность |
| `def report()` | **требование**: класс обязан объявить метод `report` |
| ``def `<=>`(other)`` | требование или реализация [оператора](expressions.md#перегрузка-операторов) — он тоже метод |

```wdl
trait Counted(count = 0, limit) {

    def inc() { count += 1 }
    def full() => count >= limit
    def report()                            // требование: класс обязан это уметь
}

class Basket(items, limit = 10) with Counted {

    def add(item) {
        items += [item]
        inc()                               // метод трейта работает с полем трейта
    }

    def report() => println(len(items), " шт., ", count, " добавлений")
}

b = new Basket([])
b.add("болт")
println(b)                                  // Basket{"count": 1, "items": ["болт"], "limit": 10}
println(b.full(), " ", b is Counted)        // false true
```

Читается это так: трейт — то, чего классу **не хватает**, и то, что он взамен
**обязан дать**. Обязательное объявляется без значения, вспомогательное — со значением
или с телом. Одно правило на поля и на методы, потому что поле и метод в языке
[и так одно и то же обращение](access.md).

Трейтов может быть сколько угодно: `with Printable, Counted, Comparable`. Конструктора
у трейта нет, поэтому и складывать их можно в любом количестве — конфликтовать может
только имя, а про имена сказано [ниже](#последний-побеждает).

### Требования проверяются при объявлении класса

Не при вызове и не при создании экземпляра. Это единственное, чего не даёт утиная
типизация, и ради этого трейты и заведены: ошибка появляется там, где сделана, а не
через час работы скрипта в чужом приложении.

Момент — выполнение самой инструкции `class`. Для класса верхнего уровня это значит
«до первой строки скрипта», для класса внутри функции — «на первом же её вызове»,
для класса в модуле — «внутри его `import`». Дальше этого ошибка не откладывается
никогда: объявленный класс — проверенный класс.

```
figures.wdl:6:7: ошибка: класс 'Basket' не выполняет требование трейта 'Counted':
нет поля 'limit'. Объявите его в заголовке класса

figures.wdl:6:7: ошибка: класс 'Basket' не выполняет требование трейта 'Counted':
нет метода 'report'
```

Требование считается выполненным, если нужное поле или метод есть у самого класса,
у его предка или у другого трейта — смотрят в уже собранные плоские таблицы, поэтому
порядок в `with` на результат не влияет. Для метода проверяется ещё и число аргументов:
метод должен принимать столько, сколько требуется.

Поле закрывает поле, метод — только метод. У поля нечего проверять на число
аргументов, а то, что поле потом перекроет метод при обращении, — уже
[другая история](#поля-собираются-в-плоскую-таблицу) и работа линтера.

#### Требование к свойству: через возможность, а не через хранение

Трейт вправе потребовать не «поле», а «имя, которое читается» или «имя, которое
читается и пишется» — и не касаться того, чем класс это обеспечит:

```wdl
trait Sized {
    property size { def get() }
}

trait MutableSized {
    property size {
        def get()
        def set(value)
    }
}
```

Аксессор без тела здесь — требование, ровно как `def report()` без тела у метода.
Закрывается оно по таблице:

| Что объявил класс | `get` | `set` |
|---|---|---|
| обычное поле `size` | да | да |
| `property size` только с `get` | да | нет |
| `property size` с `get` и `set` | да | да |
| метод `size()` | нет | нет |

Работает это и в обратную сторону: **свойство с `get` и `set` закрывает обычное
полевое требование** (`trait Sized(size)`). Иначе замена поля вычисляемым свойством
ломала бы контракт — то самое, ради предотвращения чего свойства и заведены.

```
figures.wdl:8:7: ошибка: класс 'Computed' не выполняет требование трейта
'MutableSized': свойство 'size' не умеет записи
```

Метод не закрывает ничего: его читают именем, а зовут скобками, и это другая операция.

Значение по умолчанию у поля трейта **подставляется скрыто** — в заголовке класса
его писать не нужно. Если класс всё же объявит одноимённое поле, победит класс:
он в цепочке последний, а правило одно на всё.

### Последний побеждает

Поля и методы собираются в один плоский набор в порядке записи: **родитель из `:`,
затем трейты из `with` слева направо, затем сам класс**. Одинаковое имя не ошибка —
побеждает последний.

```wdl
trait Loud    { def text() => "ГРОМКО" }
trait Quiet   { def text() => "тихо" }

class A(x) with Loud, Quiet                     // text() → "тихо": Quiet записан позже
class B(x) with Quiet, Loud                     // text() → "ГРОМКО"
class C(x) with Loud, Quiet { def text() => "по-своему" }   // класс всегда последний
```

**Почему не ошибка.** Порядок и так написан в объявлении, слева направо, и читается
без всяких правил линеаризации: «сначала родитель, потом примеси, потом я сам».
Ошибка на конфликте вынудила бы переопределять метод в классе только ради того, чтобы
выбрать один из двух — то есть писать код, ничего не решающий по существу.
А переопределение методов родителя языку и так нужно, и это то же самое правило:
класс идёт последним, поэтому его `area()` побеждает `area()` предка.

Обратная сторона честная: два трейта могут молча перекрыть друг друга. Заметить это
— работа [линтера](overview.md#как-это-устроено), а не причина запрещать конструкцию.

### У трейта нет конструктора

`new Counted()` — ошибка: трейт описывает, чего не хватает классу, а не самостоятельную
вещь.

```
figures.wdl:9:5: ошибка: 'Counted' — трейт, экземпляр создаёт класс
```

Поэтому у трейта нет и значений полей, зависящих от параметров создания: `count = 0`
вычисляется в области, где трейт объявлен, и на каждом создании заново — по тем же
правилам, что [значения по умолчанию у функций](functions.md#значения-по-умолчанию).

**Одно понятие вместо трёх.** Интерфейс — это трейт из одних требований; абстрактный
класс — трейт с реализациями и полями; примесь — трейт без требований. Отдельных слов
`interface` и `abstract` в языке нет, потому что называть три частных случая одного
и того же тремя словами — это три страницы правил вместо одной.

## Проверка `is`

```wdl
println(c is Circle)            // true
println(c is Shape)             // true — предок
println(c is Printable)         // true — трейт
println(c is Point)             // false
println(42 is Circle)           // false, а не ошибка
```

`is` — обычный бинарный оператор с приоритетом сравнений: слева значение, справа
класс или трейт. Для значения, которое не экземпляр, ответ — `false`: вопрос «этот ли
это класс» осмыслен для чего угодно, а ошибку здесь пришлось бы обходить проверкой
типа перед проверкой класса.

Справа — только класс, трейт или [дескриптор типа](types.md#проверка-типа), и
`x is 5` это ошибка, а не `false`: спросить «является ли значение пятёркой» через
`is` можно только по ошибке, и молчать о ней незачем.

`is` понимает и дескрипторы типов из [types.md](types.md#проверка-типа):
`c is Object` истинно для любого экземпляра — экземпляр это `object`, — а
`new Circle(1) is Circle` истинно вдобавок. Про то, чем это отличается
от сравнения `typeof(c) == Circle`, — сразу ниже.

## typeof против is

`typeof` теперь тоже отвечает не строкой, а [дескриптором типа](types.md#проверка-типа)
— тем же самым значением, что стоит в переменных `Object`, `Class`, `Trait`
из корневой области. У типов иерархии нет, поэтому для них равенство
дескрипторов и `is` — один и тот же вопрос: `typeof(5) == Number` истинно
ровно тогда же, когда истинно `5 is Number`.

На классах эти два вопроса расходятся, и это не недосмотр, а следствие того, что
`typeof` отвечает **каким типом** является значение (ответов одиннадцать, список закрыт,
иерархии нет), а `is` — **кому принадлежит** значение (а тут есть предки и трейты):

```wdl
p = new Point(1, 2)
println(typeof(p) == Point)      // false — typeof даёт Object, экземпляр это object
println(p is Point)              // true

e = new IndexError("x")
println(typeof(e) == Exception)  // false
println(e is Exception)          // true — is знает наследование и трейты
```

Отсюда практическое правило: **проверять тип и класс — через `is`**, а `==` над
типами оставить для «тот же тип, какой бы он ни был», ровно как делает
`typeof(left) == typeof(right)` в [`lib/test.wdl`](../examples/testing/lib/test.wdl).

`equals` у `WdlClass` и у дескриптора типа при этом нарочно не переопределён:
сравнение по ссылке — правильный ответ, а переопределённое равенство сделало бы
два разных класса с одним именем одним и тем же значением.

## Класс — тоже значение

```wdl
println(typeof(Point))          // class
println(typeof(Printable))      // trait
println(Point)                  // class Point(x, y)

Point.zero = new Point(0, 0)    // «статическое поле» — обычная запись по ключу
println(Point.zero.text())      // (0, 0)
```

Отдельного слова `static` нет и не нужно: класс — значение, значение — контейнер,
запись по ключу уже работает. Читаются у класса только такие поля; методы через класс
не читаются — без экземпляра они всё равно бесполезны, а до реализации родителя есть
`super`.

По той же причине поля класса **не наследуются**: `Circle.zero` не видит `Shape.zero`.
Это обычная запись по ключу в конкретном значении, а не ещё одна таблица со своими
правилами поиска.

### Фабрики: `def User.of(...)`

Функцию, которая живёт на классе, а не на экземпляре, можно объявить прямо в теле
класса — по имени с точкой:

```wdl
class User(name, hash, age = null) {

    def User.of(name, password, age = null)
        => new User(name, password + ":хеш", age)

    def User.guest() {
        return new User("гость", "", 0);
    }

    def greet() => "привет, " + name
}

u = User.of("wdeath", "секрет")
```

Это и есть «статические функции», но **не отдельный вид члена**, как `static` в Java.
`User.of` — то же самое обращение по ключу, что `user.name`: обычное значение
в значении-классе. Его можно прочитать, передать аргументом, положить в массив
и подменить в рантайме — ничего специального в нём нет, кроме места записи.

Ровно то же самое можно написать и снаружи, и разницы для движка не будет:

```wdl
User.of = def(name, password, age = null) => new User(name, password + ":хеш", age)
```

Форма `def User.of(...)` нужна затем, чтобы способ создания читался вместе с классом,
а не терялся строчкой ниже.

**`this` внутри такой функции нет** — экземпляра ещё не существует, она его и создаёт.
Обращение к `this` там — ошибка разбора.

Фабрики закрывают то, ради чего в других языках заводят перегрузку конструкторов,
и закрывают лучше: у каждого способа создания есть **имя**. `User.of` и
`User.guest` видно в месте вызова, а `new User(...)` против `new User(...)`
различались бы только числом аргументов.

## Родитель объявляется выше потомка

Класс существует со своей строки — то же правило, что
у [функции](functions.md#объявление-существует-со-своей-строки) и у переменной.
Связывается он тогда, когда до его объявления дошло выполнение, и родителя с трейтами
ищет среди значений, видимых в этой точке. Значит, они обязаны быть объявлены выше:

```wdl
class Shape(name)
class Circle(radius) : Shape("круг")        // Shape уже есть — связывается
```

Обратный порядок — ошибка, и она называет строку настоящего объявления:

```
скрипт.wdl:1:23: ошибка: неизвестный класс 'Shape': объявление стоит ниже,
на строке 2, а имя существует с той строки, где его завели
```

Правило одно на все формы записи ссылки: простое имя, `m.Shape` после импорта,
[выражение](#ссылка-на-родителя--выражение) вроде `registry["Shape"]` — разницы нет.

Круг в наследовании — тот же случай, но переставить объявления нельзя в принципе,
и сообщение говорит именно это: «`A` и `B` наследуют друг друга по кругу, поэтому
нужного порядка объявлений не существует».

**Родитель и трейт из [модуля](modules.md#наследование-и-трейты-через-файлы) — по тому
же правилу**: тип из модуля виден только ниже своего `import`.

```wdl
import lib.shapes                    // Shape виден отсюда и ниже
class Circle(radius) : Shape("круг") // существует с этой строки
```

Объявление внутри функции или блока, как и объявление функции, живёт в своей области
и видно от своей точки и ниже. Класс из тела функции замыкает вызов, в котором его
объявили, — два вызова дают два значения с разными замыканиями, но один и тот же класс
для `is`: объявлен-то он в одном и том же месте текста.

```wdl
def kind(rate) {
    class Priced(sum) { def total() => sum * rate }
    return Priced;
}

ten = kind(10)
twenty = kind(20)
println(new ten(1).total(), " ", new ten(1) is twenty)      // 10 true
```

## Печать и равенство

Экземпляр печатается именем класса и полями [в порядке таблицы](#поля-собираются-в-плоскую-таблицу)
— родительские, из трейтов, свои, а за ними то, что завёл конструктор:

```wdl
println(new Point(20, 30))      // Point{"x": 20, "y": 30}
```

Отдельного правила печати для экземпляра нет: он [объект](types.md#объект), у объекта
порядок пар — порядок вставки, а вставка идёт по таблице. Отсюда и кавычки вокруг имён
полей: ключ поля — обычное строковое значение, и печатается он как строка. Печатать
имена голыми пришлось бы с оговоркой «если ключ похож на имя», а `p["ключ с пробелом"]`
в языке законен.

Метода `toString` язык пока не спрашивает: `display()` у значения — чистая функция без
доступа к интерпретатору, а вызов метода требует контекста выполнения. Когда
в `CallContext` появится способ вызвать функцию (место для него
[уже предусмотрено](types.md#как-это-устроено-в-коде)), печать начнёт спрашивать
у экземпляра метод `text`. До тех пор своя печать — это явный `println(p.text())`.

Экземпляры, как объекты и массивы, **сравниваются по ссылке**. Сравнение по полям
стоит обхода всей структуры и требует решать, что делать с объектом, который ссылается
сам на себя, — это функция стандартной библиотеки, а не операция `==`.

## Чего в классах не будет

* **`private`, `protected`.** Скрипт живёт в чужом приложении, где границу доверия
  проводит не язык, а движок: изоляция контекстов и то, что приложение положило
  в область видимости. Внутри скрипта прятать поля не от кого, а слово в языке было бы.
* **`static` как модификатор.** Класс — значение, поле класса — обычная запись
  по ключу; `def User.of(...)` — [место записи, а не вид члена](#фабрики-def-userof).
  Слово не добавляет возможностей.
* **Перегрузка методов и конструкторов** — не путать с [перегрузкой
  операторов](expressions.md#перегрузка-операторов), которая есть.
  [Одно пространство имён](overview.md),
  метод — обычное значение в поле; два значения по одному ключу не лежат. Разное
  число аргументов — это [значения по умолчанию](functions.md#значения-по-умолчанию),
  разные способы создания — [фабрики с именами](#фабрики-def-userof).
* **Множественное наследование.** Родитель один — из-за конструктора, а не из-за
  конфликтов имён; см. [наследование](#наследование). Переиспользовать состояние
  и поведение из нескольких мест дают [трейты](#трейты), и их сколько угодно.
* **Анонимные классы.** У `def` анонимная форма есть, потому что функция без имени
  осмысленна. Класс без имени нечем показать в `is`, в печати и в ошибке, а объект
  на один раз в языке уже есть — это [литерал объекта](types.md#объект).

## Как это устроено в коде

Классы не добавили в конвейер ни одной стадии: `Parser → Interpreter`, как и всё
остальное. Форма класса собирается при выполнении объявления, когда родитель и трейты
уже стали значениями. Иначе наследование от класса из модуля требовало бы разбирать
чужие файлы до запуска, и скрипт не работал бы без них
([модули](modules.md#файл-читается-на-своей-строке)).

Отдельная стадия здесь была — она расставляла объявления верхнего уровня так, чтобы
родитель шёл раньше потомка, — и была убрана. Ради неё в языке пришлось бы держать
целый набор исключений («класс с родителем из модуля появляется на своей строке»,
«класс с родителем-выражением — тоже»), а купить на них можно было только свободу
порядка внутри одного файла. Одно правило на весь язык оказалось дороже.

| Слой | Что делает |
|---|---|
| `lexer` | `TRAIT`, `WITH`, `SUPER`, `IS` — по строке в `TokenType`, таблицы лексера строятся из него же |
| `ast/expr` | `NewExpr`; `is` — константа в `BinaryOp` и строка в таблице `Operators` |
| `ast/stmt` | `ClassDeclStmt`, `TraitDeclStmt`: заголовок — те же `FunctionExpr.Param`, что у функции; конструктор, методы, фабрики, свойства и требования разложены по отдельным полям. `PropertyDecl` — запись, а не узел: посетителей она не касается |
| `parser` | разбор `class`/`trait`/`new`/`def Имя.член(...)`/`property`; `property`, `get` и `set` — контекстные слова, в `TokenType` их нет: ключевые слова лексера глобальны, а отнимать эти имена у чужих скриптов незачем; ссылка на тип — цепочка силой `Operators.ACCESS`, последний `CallExpr` расщепляется на родителя и аргументы; `this` и `super` — обычные `VariableExpr`, а где они допустимы, помнят поля-счётчики по образцу `functionDepth` |
| `resolve` | `Shape` — форма: плоские таблицы полей, методов и свойств, цепочка предков, набор трейтов. Поле и свойство делят ячейку имени, поэтому таблицы собираются послойно (`ClassShape.place`). Собирает её `Linker` при выполнении объявления, он же проверяет требования трейтов и аргументы родителю и кэширует связку по узлу дерева — на этом кэше держится `is` для класса из функции. Стадии до выполнения в пакете больше нет |
| `value` | `ClassValue` и `TraitValue` — `non-sealed` интерфейсы, как `FunctionValue`: реализация тянет за собой дерево и область видимости, поэтому живёт в `runtime`. Экземпляр — `InstanceObjectValue`, наследник `MapValue`: карта пар плюс ссылка на класс |
| `runtime` | `WdlClass` и `WdlTrait` — форма плюс замыкание. `InstanceScope implements Environment` — область поверх экземпляра: поля, свойства, методы класса. `WdlProperty` зовёт аксессоры обычной `UserFunction`, `FieldScope` добавляет одно имя `field`. `Interpreter` об этом не знает, он видит только интерфейсы |

Разделение, на котором всё держится: **форма — имена и порядок, значение — замыкание
и данные.** Форма собирается один раз на связку «объявление плюс родитель с трейтами»
и лежит в кэше запуска; `WdlClass` создаётся на каждое выполнение объявления. Отсюда
и класс из тела функции: форма одна, значений столько, сколько вызовов. Одно и то же
дерево, запущенное дважды, получит две формы — родители-то у запусков разные значения.

Отдельного «связанного метода» в коде нет: чтение метода даёт обычную `UserFunction`,
замыканием которой служит `InstanceScope`. Объект помнится замыканием, а арность,
значения по умолчанию, `return` и защита от рекурсии достаются готовыми.

## Что дальше

* печать через метод `text` — вместе с расширением `CallContext`;
* свойства у встроенных типов (`"строка".длина`) — тот же механизм, но контейнером
  выступает не экземпляр класса;
* сравнение экземпляров по полям — функцией стандартной библиотеки;
* слово объявления локальной переменной (`local x = 0`) или предупреждение резолвера —
  чтобы временная переменная в методе не могла молча попасть в одноимённое поле;
* классы в REPL: каждая введённая строка — своя программа, поэтому наследоваться
  можно в пределах одного ввода;
* защита печати от цикла: `println` ловит только прямую самоссылку объекта, а
  `registry += [this]` в конструкторе делает цикл через массив обычным делом;
* мост к Java-объектам: `player.getName()` — это тот же поиск по ключу, только
  реализация ветки другая.

# Единое обращение

> `значение.имя` — это в точности `значение["имя"]`.
> Одна операция, две записи. Разные вещи из них делать не будем.

Это решение уровня всего языка, а не деталь синтаксиса, поэтому оно записано отдельно.

## Правило

Поле объекта, элемент словаря, элемент массива, символ строки, а в будущем — поле
класса, функция модуля и свойство Java-объекта — **один механизм**: взять значение
и достать из него содержимое по ключу.

Точка — сахар: она избавляет от кавычек, когда ключ известен заранее и выглядит
как имя. Разворачивается сахар в парсере, до всякого выполнения:

```wdl
точка.x            // разбирается в точка["x"]
настройки["цвет"]  // ключ вычисляется на месте
настройки[поле]    // ключ — любое выражение
данные.строки[3].имя
```

В дереве обе формы дают один и тот же узел — `AccessExpr(target, key, style)`,
где `style` помнит форму записи только ради форматтера и текстов диагностики.
Проверить можно глазами:

```
$ wdl --ast скрипт.wdl        # для 'данные.поле' и 'данные["поле"]'
обращение (точка)   [0..12]        обращение (скобки)  [0..16]
  имя данные        [0..6]           имя данные        [0..6]
  литерал "поле"    [7..12]          литерал "поле"    [8..15]
```

Разница — только в слове в скобках и в интервалах исходника. Дальше по конвейеру
эти деревья неразличимы.

## Зачем так

**Одно правило вместо трёх.** Не бывает «доступа к полю», отдельно «индексации»
и отдельно «работы со словарём» — с тремя наборами ошибок и тремя местами, где
про какой-то случай забыли. Правило пишется один раз на тип контейнера.

**Ключ можно вычислить.** `настройки[префикс + "Цвет"]` работает там же, где
`настройки.цвет`, без отдельного синтаксиса и без рефлексии. Обход всех полей
объекта — обычный цикл, а не особая возможность языка.

**Новый тип-контейнер получает обе записи даром.** Класс, модуль, обёртка над
Java-объектом добавляют одну ветку в чтение по ключу — и сразу поддерживают
и `объект.поле`, и `объект["поле"]`, и перебор. Так и вышло с [модулями](modules.md):
`log.info` — обычное обращение, и никакого особого синтаксиса им не понадобилось.

**Присваивание — та же структура.** Разобрать `a.b[0] = 1` значит вычислить всё,
кроме последнего ключа, и записать по нему. Одна реализация вместо ветвлений
по форме записи; когда появится присваивание, писать её заново не придётся.

**Цепочка — вложение, а не список.** `a.b.c` — это `Access(Access(a, "b"), "c")`.
У каждого шага свой интервал в исходнике, поэтому ошибка показывает именно то звено,
где всё сломалось, а вычисление промежуточного значения — обычное вычисление
левого поддерева, без особого случая.

## Правила по типам

| Контейнер | Ключ | Результат |
|---|---|---|
| объект | любое значение | значение по ключу; нет ключа — [член типа](members.md), потом **`null`** |
| массив | целое число | элемент; отрицательное — от конца; выход за границы — ошибка с указанием размера |
| массив | диапазон | срез — новый массив; границы включительны, выход за границы подрезается |
| массив, строка | строка | [член типа](members.md): `a.size`, `"x".upper` |
| строка | целое число | символ строкой длиной 1; отрицательное — от конца; выход за границы — ошибка |
| строка | диапазон | срез — новая строка, по тем же правилам, что у массива |
| число, функция, класс, трейт, модуль | строка | [член типа](members.md); промах — ошибка с подсказкой |
| логическое | строка | только универсальный член `type` |
| `null` | — | ошибка: обращение к `null` обязано ломаться там, где написано |

У массива и строки **строковый ключ уходит в члены раньше проверки индекса** —
иначе на `a.size` человек получал бы «индекс массива должен быть целым числом»,
то есть сообщение про то, чего он не писал.

Два несимметричных решения — намеренные:

* **У объекта отсутствующий ключ даёт `null`.** Проверка «есть ли поле» — обычная
  операция в динамическом языке, и заставлять писать её через перехват ошибки
  неразумно: `настройки.цвет || "по умолчанию"` должно просто работать.
* **У массива выход за границы — ошибка.** Индекс берётся из расчёта, и молчаливый
  `null` в этом месте означает, что расчёт неверен, а узнают об этом через десяток
  строк, уже без объяснения причины.

### Две дисциплины числового ключа

Третья несимметричность — внутри самого массива: **элемент строг, срез подрезается.**
Разделяет их заданный вопрос. `a[i]` спрашивает «какой элемент под этим номером» —
такого номера может не быть, и ответа тогда не существует. `a[from..to]` спрашивает
«какая часть попадает в этот промежуток» — ответ есть всегда, иногда пустой:

```wdl
items = [10, 20, 30]
println(items[1..100])      // [20, 30] — верх подрезан
println(items[2..1])        // []       — пустой диапазон, пустой срез
// println(items[9])        // ошибка: индекс 9 вне границ массива размером 3
```

Правило не новое: так же всегда вели себя `slice` (подрезает) и `insert`/`remove`
(ошибаются). Отрицательное число нормализуется в обеих дисциплинах одинаково —
`-1` значит последнюю позицию, — и это тоже осознанно: иначе одна и та же запись
`-1` значила бы в `a[-1]` и в `a[1..-1]` разное.

**Записи в срез нет.** `a[1..3] = [x, y]` заменило бы часть массива вместе с его
длиной, а присваивание по ключу длины не меняет — такая операция заслуживает
собственного имени и собственного разговора про то, что происходит с длиной.

Границы среза обязаны быть целыми: `a[0.5..2.5]` — ошибка, тем же доводом, что
и `for (x in 0.5..2.5)`. Какие позиции содержит такой диапазон «по одной», языку
решать не за что.

**Срез — копия, а не вид на исходный массив:** `b = a[0..1]; b[0] = 9` не трогает `a`.
Вид потребовал бы либо второго вида массива, либо неявно разделяемой памяти — обе
цены несопоставимы с выгодой.

Ключи объекта нормализуются: `obj[1]` и `obj[1.0]` — одна и та же ячейка. Одно и то же
по смыслу число не должно давать два разных ключа.

### Экземпляр класса: пять шагов

У [экземпляра](classes.md#свойства) правило чуть длиннее — между полем и методом
стоит свойство, а за методом — члены:

1. собственное поле;
2. **свойство класса — вызвать getter**;
3. метод класса — связанная функция;
4. [член типа или расширение](members.md) — экземпляр это `object`;
5. `null`.

Из «одна операция, две записи» тут следует важное: `obj["area"]` зовёт getter
так же, как `obj.area`, и `obj[ключ]` с вычисленным ключом — тоже. Цена честная
и её стоит знать: обращение по вычисленному ключу к экземпляру может выполнить
чужой код. Обратное следствие мягче — свойства нет среди пар, поэтому
`for (k in obj)` его не покажет, ровно как не показывает метод.

## Что из этого уже выросло

**Вызов метода** `point.text()` — это обращение, давшее функцию, и вызов полученного
значения. Отдельного «вызова метода» в языке нет, и это видно: метод можно прочитать
в переменную и вызвать позже, объект при этом не потеряется.

```wdl
handler = point.text
println(handler())
```

**Поле класса** `Point.zero = new Point(0, 0)` — та же запись по ключу, только
в значении-классе. Отдельного слова `static` поэтому не понадобилось. Подробности —
в [классах](classes.md).

**Члены значений** — `text.size`, `a.sort()`, `213.toString()` — тот же узел:
контейнер отвечает на известные ему ключи сам, когда своих данных с таким ключом нет.
Ни новой формы записи, ни нового правила это не потребовало — только ещё одного шага
в чтении по ключу. Описание — в [членах значений](members.md).

## Безопасное обращение

`config?.db` — то же обращение, только с вопросом «а есть ли получатель».
Пусто — звено пропускается, и значением становится `null`.

Это **флаг на узле**, а не третья форма записи, и накрывает он все записи разом:

```wdl
config?.db          // через точку
rows?.[0]           // по вычисляемому ключу
handler?.()         // вызов — метода в языке нет, значит вопрос и к нему тоже
```

Лексема `?.` одна на все три формы. Записи `a?[i]` нет и не будет: лексер берёт
самое длинное совпадение, и тогда `flag ? [1] : [2]` разобралось бы как безопасный
индекс. С `?.` двусмысленности нет по построению — выражение в языке никогда
не начинается с точки. Цена у этого одна и названа сразу: **пробел между `?` и `.`
перестал быть свободным**, и тернарник, написанный как `flag ?.x : y`, стал
безопасным обращением. Так его не пишет никто.

### Замыкание — на всю цепочку

```wdl
user = null
user?.profile.name      // null, а не ошибка на '.name'
```

`?.` достаточно написать там, где пусто бывает. Обратная дисциплина — «`?.`
отвечает за себя, дальше как обычно» — рассматривалась и отвергнута: в Kotlin
её держит компилятор (`a?.b.c` там просто не соберётся), а языку без типов поймать
это нечем. Ошибка осталась бы невидимой до того единственного прогона, где значение
окажется пустым, — ровно от этого `?.` и заводился.

Второй довод решает окончательно: **метода в языке нет**. `logger?.info("go")` —
это обращение и вызов его результата, и при звеньевой дисциплине писать пришлось бы
`logger?.info?.()`. Записей, где `?.` нужен дважды на одно намерение, в языке быть
не должно.

Граница цепочки поэтому лежит в дереве отдельным узлом и видна в дампе:

```
$ wdl --ast скрипт.wdl        # для 'user?.profile.name'
безопасная цепочка
  обращение (точка)
    обращение (точка, безопасное)
      имя user
      литерал "profile"
    литерал "name"
```

Скобки закрывают цепочку раньше: `(user?.profile).name` — это обращение
к её значению, и пустота там уже не безопасна.

### Чего `?.` не делает

Закрывает он **ровно один случай** — пустого получателя. Всё остальное остаётся
ошибкой, какой и было: промах индекса (`items?.[9]`), промах по члену
(`"abc"?.nosuch`), вызов не-функции. Иначе он превратился бы в `try?` с худшим
именем — а `try?` про ошибку, и это другая беда и другой знак вопроса.

Слева от присваивания безопасного обращения не бывает:

```wdl
config?.db = {}     // ошибка: '?.' не может стоять слева от '='
```

«Не записал, потому что некуда» — это молчаливая потеря данных, и разрешать такое
языку нельзя. Отказ выдаёт парсер, отдельным сообщением: обращение слева как раз
стоит, и общий совет «поставьте имя или обращение» отправил бы искать ошибку не туда.

Подстановка `??` и запись по нужде `??=` описаны в [выражениях](expressions.md),
пример целиком — в [examples/language/null-safety.wdl](../examples/language/null-safety.wdl).

## Что появится дальше

* **Принудительное развёртывание** `a!!.b` («тут точно не пусто, иначе ошибка») —
  пока не нужно: `?.` полон и без него, а второй восклицательный знак рядом
  с `try!` придётся объяснять.

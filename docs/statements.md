# Инструкции

Скрипт — последовательность инструкций. Простых видов четыре: **присваивание**,
**распаковка**, **вызов** и **объявление константы**; к ним добавляются блок,
[ветвления и циклы](control-flow.md) и [объявление функции с `return`](functions.md).

```wdl
имя = "мир"                 // присваивание
x, y = *точка               // распаковка
println("Привет, ", имя)    // вызов
```

Готовый пример целиком — [`examples/hello.wdl`](../examples/hello.wdl).

## Присваивание — инструкция, а не выражение

`x = 5` не имеет значения и никуда не вкладывается. Отсюда сразу следует, что
`if (x = 5)` не разберётся вообще — а не «сработает не так, как имел в виду автор,
который хотел `==`». Классическая ошибка, которую язык может не допустить по
построению, и не допускает.

Объявлять переменную не нужно: имя заводится первым присваиванием в текущей области
видимости. Существующее имя присваивается там, где было объявлено, — вложенная область
не создаёт себе тихую копию. Объявление в языке ровно одно, и оно про другое:
[`const`](#const--имя-которое-нельзя-перезаписать) заводит имя, которому присвоить уже нельзя.

```wdl
счёт = 0        // завели
счёт = 10       // перезаписали
счёт += 5       // составное присваивание
```

Составные: `+=` `-=` `*=` `/=` `%=` `&=` `|=` `^=` `<<=` `>>=` `>>>=`.
Они **не** разворачиваются в `a = a + b` при разборе, и это важно:

```wdl
таблица[ключ()] += 1        // ключ() вызывается ровно один раз
```

Место записи вычисляется один раз, а операция берётся из узла. Разворачивание
в парсере вызвало бы `ключ()` дважды — тихая ошибка, которую почти невозможно найти.

### Слева стоит обращение

Цель присваивания — имя или [обращение](access.md), то самое, что используется
для чтения:

```wdl
товар.цена = 15
склад[0].количество -= 1
настройки[префикс + "Цвет"] = "белый"
```

Никакой отдельной грамматики для левой части нет: `a.b[0]` слева и справа от `=` —
буквально один и тот же узел дерева. Новый тип-контейнер получает поддержку записи
там же, где и чтения.

Записать можно в массив (по целому индексу, в границах) и в объект (по любому ключу).
Строка неизменяема: `s[0] = "я"` — ошибка, и это не случайность реализации — строки
лежат в ключах объектов, изменение на месте испортило бы их.

## Распаковка: `x, y = *point`

Одна строка раскладывает составное значение по нескольким именам. Форм две, и
различает их **знак на источнике**:

```wdl
x, y = *point                       // по позициям
host, port = **config               // по именам
```

Никакого нового слова язык на это не тратит. `*` и `**` уже значат «разложи по
позициям» и «разложи по именам» — в [вызове](functions.md#раскрытие-массива-и-объекта),
`f(*args)` и `f(**named)`; присваивание берёт те же два знака в том же смысле.
Знак при этом зеркалится ровно как в функциях: справа `*` **раскрывает**, слева
`*rest` **собирает остаток**.

Целый пример — [`examples/unpack.wdl`](../examples/unpack.wdl).

### Почему маркер на источнике, а не на списке имён

Написание `[x, y] = arr` пришлось бы разводить с массивом в позиции инструкции,
`{x, y} = obj` — с блоком, а `x, y = arr` потребовало бы правила «справа одно
выражение — распаковка, несколько — попарно». Звёздочка снимает все три вопроса
разом: префиксной `*` в языке нет вовсе, поэтому `= *` больше ничем быть не может,
и разбор идёт без единого заглядывания вперёд.

Побочно из этого получается и то, что список справа **без** звёздочки остаётся
тем, чем выглядит, — списком значений попарно:

```wdl
a, b = b, a                 // обмен
a, b, c = first, *pair      // раскрытие в списке — то же, что в аргументах
```

### По позициям

Источник — массив или экземпляр класса. У экземпляра порядок задаёт заголовок:
отдельного объявления полей в языке нет, [заголовок и есть список
компонентов](classes.md), как у Java-рекорда.

```wdl
class Vec3(x, y, z) { }
p = new Vec3(1, 2, 3)
x, y, z = *p
```

Обычный объект по позициям **не** распаковывается. Порядок вставки у него
сохраняется, но это данные, а не договорённость: объект из JSON или из сети приехал
бы переставленным, и распаковка молча положила бы не то. Строка, диапазон и модуль
не распаковываются тоже — символы по позициям это `text[0]`, и тихая поддержка тут
только плодила бы случайные срабатывания.

**Длина — контракт, и ошибка идёт в обе стороны:**

```
x, y, z = *[1, 2]
  распаковка ждёт 3 значения, а массив даёт 2

x, y = *[1, 2, 3]
  распаковка берёт 2 значения, а массив даёт 3;
  остаток пишется как 'x, y, *rest' или 'x, y, *_'
```

Та же логика, по которой выход за границы массива — ошибка, а не `null`:
`x, y, z = *[1, 2]` почти всегда значит, что расчёт выше неверен. Отказ от остатка
пишется явно, `*_`, а сам остаток — `*rest`, и он даёт **новый** массив, а не вид
на источник: иначе запись в `rest` меняла бы источник через вторую переменную,
и выяснялось бы это далеко от места.

```wdl
head, *tail = *items        // tail — новый массив
n1, n2, *_ = *row           // остальное не нужно, и это написано
only = *[42]                // «здесь ровно один элемент» — тоже проверка
```

### По именам

Источник — объект или экземпляр. Экземпляр, таким образом, распаковывается обеими
формами: `*` по порядку заголовка, `**` по именам полей. Свойства в `**` не
участвуют — свойство вычисляемое, и дёргать неизвестно сколько аксессоров на
распаковке нельзя; берётся то же, что даёт перебор, то есть поля.

```wdl
x, z = **{x: 1, y: 2, z: 3}         // ключ 'y' просто не назван
host, port, **options = **config    // остаток — новый объект
connect(host, port, **options)      // и уходит дальше тем же '**'
```

**Размер объекта, в отличие от длины массива, не контракт: лишние ключи не ошибка.**
Асимметрия сознательная. Объект приходит из конфига, из JSON, из ответа сервера
и почти всегда несёт больше, чем берут; будь лишние ключи ошибкой, отказ от остатка
пришлось бы дописывать в каждую вторую строку. А вот недостающий ключ — ошибка:
это как раз опечатка в имени или изменившийся формат данных.

```
host, port = **config
  в объекте нет ключа 'port'
```

Ключ ищется **наличием**, а не значением: `{x: null}` — это «ключ есть, значение
null», и распаковка обязана его принять.

Следствие правила про лишние ключи: `**rest` здесь **необязателен**. Он не
«разрешение забрать остаток», а способ получить остаток значением, — поэтому `**_`
запрещён: под этим правилом он не делает вообще ничего.

### Цель — та же, что у обычного присваивания

Имя, `p.x`, `grid[0]`: своего понятия цели распаковка не заводит и пользуется
проверкой [присваивания](#слева-стоит-обращение).

```wdl
p.x, p.y = *velocity
grid[0], grid[1] = *pair
```

Одно уточнение есть только в `**`-форме, и оно не про форму цели, а про наличие
у неё имени: там имя цели делает двойную работу — оно же ключ, по которому лезут
в источник. Поэтому цель обязана **заканчиваться именем**:

```wdl
p.x, p.y = **vec            // p.x = vec.x, p.y = vec.y
p["x"] = **vec              // годится наравне: обращение в языке одно
grid[i] = **config          // ошибка: имени нет вовсе
```

Вычисленный ключ не годится не потому, что его нельзя взять, — а потому, что тогда
список распаковки перестаёт читаться: что именно берут из источника, видно уже
не в тексте, а только в отладчике.

### Порядок вычисления

Правая часть считается **целиком до первой записи**. Отсюда `a, b = b, a` работает,
а ошибка на середине не оставляет половину имён перезаписанными. Источник при этом
вычисляется ровно один раз, сколько бы имён ни стояло слева, и маркер относится
ко всему выражению, а не к первому его звену:

```wdl
x, y, z = **reacts[i].getReact().getCenter()    // один вызов цепочки, а не три
```

### Чего у распаковки нет

Составного присваивания (`x, y += *v` — ошибка разбора: непонятно ни к чему
прибавлять, ни что делать при ошибке на середине), вложенных списков
(`a, (b, c) = *pair`), переименования по именам (`host as h`), распаковки
в `const` и в параметрах функции. Ничего из этого не нужно, чтобы работало
описанное выше, и каждое — отдельное решение.

## `_` — пропуск, а не имя

`_` не хранит значения, повторяется сколько угодно и **читать его нельзя**:

```
println(_)
  '_' — это пропуск, а не переменная: читать его нельзя
```

Ошибка здесь при разборе, а не при выполнении: место известно прямо по тексту.
Запрет на чтение — главное в этой конструкции: разреши язык читать `_`, и он
немедленно станет «мусорной переменной», которую читают через три строки.

Ровно один символ подчёркивания. `_x`, `__`, `_1` — обычные имена, и такими остаются.

Пропуск годится в трёх местах: в целях распаковки, в переменных
[перебора](control-flow.md#перебор-for--in) и в [параметрах
функции](functions.md#_-как-параметр).

```wdl
n1, n2, _, _, _, n6, *_ = *row      // взять первое, второе и шестое
for (_, v in config) println(v)     // ключ не нужен
def onClick(_, event) => event      // сигнатуру диктует не автор
```

В `**`-форме пропуск запрещён: имена там — это ключи, по которым лезут в объект,
пропускать нечего, а порядок ничего не значит. Не написать лишнее имя — и есть пропуск.

```
x, _, z = **vector3
  в списке по именам пропускать нечего: уберите имя '_'.
  Порядок в '**'-форме ничего не значит — значения берутся по ключам
```

## `const` — имя, которое нельзя перезаписать

```wdl
const TAX_RATE = 0.2
TAX_RATE = 0.3      // ошибка: 'TAX_RATE' нельзя присвоить: это константа,
                    // её значение задаётся один раз при объявлении
```

Начальное значение обязательно — второго присваивания не будет. Слева допустимо только
имя: `const item.price = 1` не разберётся, потому что заморозить можно имя, а не ячейку
внутри чужого значения. Составное присваивание запрещено тем же правилом и с тем же
сообщением: `TAX_RATE += 0.1` — то же присваивание.

Рабочий пример целиком — [`examples/const.wdl`](../examples/const.wdl).

### Заморожено имя, а не значение

```wdl
const items = [1, 2]
items[0] = 5        // можно: меняется содержимое
items = [3]         // ошибка: меняется имя
```

Причина не в экономии проверок. Значение не знает, в какой переменной лежит, и знать не
должно: положив один и тот же массив в две переменные, из которых одна `const`, мы получили
бы значение, ведущее себя по-разному в зависимости от того, через какое имя его трогают.
Изменяемость — свойство [типа](types.md), а не переменной, и `const` его не меняет.

### `const` заводит имя в своей области

Это **объявление**, и работает оно как объявление функции: заводит имя здесь, а не ищет
его снаружи. Поэтому вложенная область вправе объявить своё имя — это затенение, а не
переопределение:

```wdl
const rate = 1
{
    const rate = 2      // своё имя в своей области
    println(rate)       // 2
}
println(rate)           // 1
```

А два объявления в одной области — ошибка: `'rate' нельзя объявить: в этой области уже
есть константа с таким именем`. По той же причине константу не перекрывают `def`, `class`
и `trait` — они тоже заводят имя здесь:

```wdl
const total = 1
def total() => 2        // ошибка на этой строке
```

Обратный порядок ошибки не даёт: `const total = 1` после `def total()` перекрывает функцию,
ровно как это сделало бы обычное `total = 1`. Асимметрия сознательная — объявление заводит
имя поверх прежнего, а константа запрещает переопределение только после себя, и читатель
скрипта видит то же, что и движок, сверху вниз.

### Константа существует со своей строки

Как и [функция](functions.md#объявление-существует-со-своей-строки), и класс, и всё
остальное: стадии до выполнения в языке нет, имя заводится тогда, когда до объявления
дошло выполнение.

Следствие: функция, объявленная выше константы, её видит — если вызвана после объявления.
Замыкание захватывает область, а не снимок значений.

```wdl
def show() => LIMIT
const LIMIT = 7
println(show())         // 7; вызов выше этой строки дал бы «переменная не определена»
```

Ровно этот же механизм и ловит `def total()` поверх константы: помеченное объявление
выполняется ещё раз, когда до него доходит очередь, — уже после того, как имя заморожено.

### Что `const` не делает

Встроенные `println`, `print`, `typeof`, `len` константами не стали: перекрыть их
по-прежнему можно, пространство имён одно (см. ниже). По той же причине
константами не стали и [дескрипторы типов](types.md#проверка-типа) —
`Number`, `String`, `Array` и остальные: `Number = 5` законно и ломает только тот
скрипт, который это сделал, а `typeof` и `is` дескрипторы всё равно берут не поиском
имени, а из своей внутренней таблицы. В теле `class` и `trait` `const`
не пишется — там допустимы только объявления функций, а значения полей задаёт заголовок.

## Вызов

Вызывается **значение**, а не имя:

```wdl
println("привет")
точка.строкой()          // обращение дало функцию — вызываем её
обработчики[0](x)
f()(1)
```

Отдельного «вызова метода» в языке нет: `точка.строкой()` — это обращение по ключу
плюс вызов результата, два узла вместо особого случая.

Инструкцией может стать не всякое выражение. Строка `a + 1` ничего не делает —
это почти наверняка опечатка, и парсер о ней скажет. Сейчас в роли инструкции
разрешён только вызов; когда появятся `i++` и другие операции с эффектом, список
расширится ровно на них.

## Встроенные функции

| Функция | Аргументы | Что делает |
|---|---|---|
| `println` | сколько угодно | печатает аргументы подряд и переводит строку |
| `print` | сколько угодно | то же без перевода строки |
| `typeof` | 1 | [дескриптор типа](types.md#проверка-типа) значения: печатается как `number`, `string`, `bool`, `array`, `object`, `function`, `class`, `trait`, `module`, `range`, `null`, а сравнивать его стоит с именем типа (`typeof(x) == Number`), а не со строкой |
| `len` | 1 | длина строки, размер массива или объекта |

`println("итого = ", 5)` печатает `итого = 5`: аргументы идут подряд, без разделителей —
разделитель по умолчанию пришлось бы каждый раз отключать при сборке строк.

**Функция — обычное значение в обычной переменной.** Не синтаксис и не особая
сущность:

```wdl
напечатать = println
напечатать("работает")

вывод = {строкой: println}
вывод.строкой("и так тоже")

println = 5              // и перекрыть можно — пространство имён одно
```

Из этого же следует, что функцию можно передать аргументом и вернуть из другой
функции — что [свои функции](functions.md) и делают. Отдельная таблица функций,
как в прошлой реализации, всё это делала невозможным.

**Куда печатает `println`** — решает вызывающий, а не ядро. Вывод приходит в
`ExecutionContext` как зависимость (`Output`): консоль для CLI, лог для сервера,
строка для теста, «никуда» по умолчанию для встроенного движка. Перехватывать
глобальный `System.out` не нужно — и соседние скрипты в том же процессе это не задевает.

## Границы инструкций и ошибки

Разделитель — перевод строки или `;`; как разделитель точка с запятой обязательна
только когда инструкции стоят в одной строке. Частью синтаксиса она бывает ровно
в двух местах: в заголовке `for` и после [`return`](functions.md#return). Перевод строки при этом не порождает токена
(для лексера это обычный пробел), поэтому строка, начатая со скобки, приклеится
к предыдущей — здесь `;` и нужна:

```wdl
a = 1; b = 2; println(a + b)
```

Одна испорченная строка не уносит остальные: парсер сообщает об ошибке, пропускает
строку до `;` или до начала следующей — и разбирает файл дальше. Восстановление идёт
по тому, как текст выглядит для человека (`Token.afterNewline()`), а не по тому, как
он разбирается.

```
скрипт.wdl:2:5: ошибка: ожидалось выражение, найдено '='
  2 | b = = =
    |     ^
```

Выполнение, в отличие от разбора, останавливается на первой же ошибке: продолжать
после неверной операции значит считать заведомо неверный результат.

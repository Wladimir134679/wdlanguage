# Декораторы

Декоратор — **функция, применённая к объявлению в момент объявления**. Она получает
цель, может её посмотреть, зарегистрировать, а может вернуть вместо неё другую —
обёртку.

Рабочий пример целиком: [`examples/decorators.wdl`](../examples/decorators.wdl).

```wdl
def traced(meta) {
    return like(meta.target, def (*args, **named) {
        println("-> ", meta.name)
        try {
            return meta.target(*args, **named);
        } finally {
            println("<- ", meta.name)
        }
    });
}

@[traced]
def command(a, b = 10) => a + b

println(command(1))             // -> command / <- command / 11
```

Ничего такого, чего нельзя было бы написать руками: `command = timer(m.of(command))`
делает то же самое. Декоратор покупает одно — **обвес виден там, где объявление**,
а не двадцатью строками ниже, где его легко не заметить.

## Синтаксис

```
@[выражение]
@[выражение](аргументы)
```

Внутри квадратных скобок — обычное выражение, которое должно дать функцию. Дальше
необязательные скобки с аргументами декоратора. `@[reg]` и `@[reg]()` — одна и та же
запись.

```wdl
@[reg]
def app() { }

@[reg] def app2(x) { }                          // на одной строке — то же самое

@[t.commands["all"]().getDeco()](1)             // выражение любой сложности
def abcd() { }
```

**Почему скобки обязательны.** Без них `@t.deco()` неразличимо: то ли декоратор
`deco`, которому не передали аргументов, то ли вызов, результат которого станет
декоратором. Языку пришлось бы выбрать одно толкование за автора — Python из-за
этой же неоднозначности до версии 3.9 разрешал после `@` не выражение, а только
точечное имя с необязательным вызовом. Скобки разводят два случая буквально:

```wdl
@[t.getDeco]()          // декоратор — сама getDeco, аргументов нет
@[t.getDeco()]          // декоратор — то, что вернула getDeco()
```

Короткой формы `@reg` без скобок пока нет. Добавить её можно будет, не сломав ни
одного скрипта; убрать потом — уже нельзя, поэтому первой она не пошла.

## На что вешается

На объявление: `def` с именем, `class`, `trait`. Больше ни на что — попытка повесить
декоратор на присваивание или на анонимную функцию даёт ошибку разбора.

```wdl
@[reg] def command() { }        // да
@[reg] class Command { }        // да
@[reg] trait Printable { }      // да

@[reg] x = 1                    // ошибка: декоратор вешается на объявление
@[reg] def () => 1              // ошибка: у анонимной функции нет объявления
```

Декораторы стоят **перед** модификатором:

```wdl
@[audit]
synchronized def bump() { count = count + 1 }
```

Замок при этом остаётся на внутреннем значении, обёртка зовёт синхронизированную
функцию — синхронизация продолжает работать ровно так, как [обещано](threads.md).

## Метаданные: первый аргумент

Первым аргументом декоратор всегда получает объект с данными о цели. Имя у параметра
любое — `meta`, `func`, `d`: аргументы раскладываются по позициям, и занята здесь
именно позиция.

```wdl
meta.target             // сама цель: функция, класс или трейт
meta.name               // имя, под которым цель известна, или null
meta.isAnonymous        // записана ли цель без имени
```

**`name` и `isAnonymous` — два разных вопроса**, и оба нужны. Имя берётся какое есть:
у объявления своё, у анонимной функции — имя переменной, в которую её положили.
Подставляет его разбор, тот же механизм, что даёт сообщение «функция 'f' принимает
ровно 1 аргумент» вместо «функция 'def' ...».

```wdl
import sys.meta as m

def named(x) => x
anon = def (x) => x

println(m.of(named).name, " ", m.of(named).isAnonymous)     // named false
println(m.of(anon).name,  " ", m.of(anon).isAnonymous)      // anon  true
println(m.of(def (x) => x).name)                            // null
```

Последняя строка — про то, чего в `name` **не** будет. У функции, которую никуда
не клали, имени нет, и движок его не выдумывает: в сообщениях об ошибках на этом месте
стоит `def`, но это подстановка для человека, а не имя. Попади она в данные,
`commands[meta.name] = ...` зарегистрировал бы все такие функции под одним ключом,
и вторая молча затёрла бы первую.

Сюда же попадает обёртка, возвращённая декоратором ниже по стеку: у неё имени нет
по той же причине.

Типа цели среди полей нет намеренно: он спрашивается у самой цели встроенной
`typeof`.

```wdl
def show(meta) {
    println(meta.name, " ", typeof(meta.target))
}

@[show]
class Command(id) { }           // Command class
```

Два источника одного факта рано или поздно разойдутся, а `typeof` в языке уже есть
и отвечает про любое значение, а не только про декорируемое.

**Занять первую позицию своим именем нельзя.**

```wdl
def deco(meta, **opts) { }

@[deco](meta: 5)                // ошибка: параметр 'meta' передан дважды
def command() { }
```

Это не отдельная проверка, а то же правило, что и у обычного вызова: позиция уже
задана, задать её ещё и по имени — ошибка. Ровно то же сказал бы `deco(1, meta: 5)`.

### Позвать декоратор руками: `sys.meta`

Декоратор — обычная функция, и звать его должно быть можно не только через `@`.
Иначе его нельзя было бы ни протестировать, ни применить к значению, полученному
в рантайме. Карту метаданных собирает модуль `sys.meta`:

```wdl
import sys.meta as m

def reg(meta) {
    println("зарегистрирован ", meta.name)
}

@[reg]
def app() { }                   // зарегистрирован app

reg(m.of(app))                  // зарегистрирован app — то же самое
```

Внутри это тот же код, которым пользуется интерпретатор, так что разойтись двум
путям негде. `m.of` берёт любое значение, а не только объявляемое: `m.of(42)` даст
карту, в которой `name` равно `null`.

## Что декоратор возвращает

Вернул значение — оно и встанет под именем. Не вернул ничего или вернул `null` —
цель остаётся прежней.

```wdl
regs = []

def reg(meta) {
    regs = regs + [meta.target]     // ничего не возвращает: цель не меняется
}

def wrap(meta) {
    return def (*args, **named) => "обёрнуто:" + meta.target(*args, **named);
}
```

Возвращать цель явно не нужно — регистрирующему декоратору возвращать нечего, и
заставлять его писать `return meta.target;` значило бы шуметь в самом частом случае.
Цена одна: подменить цель на `null` нельзя. Потеря невелика — имя со значением
`null` ни вызвать, ни создать.

Тип возвращённого никто не проверяет: декоратор класса вправе вернуть функцию.
Ошибка тогда придёт там, где это имя попробуют использовать по назначению, — и это
честно: движок не знает, чего автор хотел.

## Порядок применения

**Снизу вверх.** Ближайший к `def` получает саму цель, следующий — то, что вернул
предыдущий, и так до верхнего. Под именем оказывается результат самого верхнего.

```wdl
@[timer]                    // применяется вторым, оборачивает результат log
@[log]("info")              // применяется первым, видит саму command
def command() { }
```

Отсюда правило записи, которое стоит запомнить сразу:

> **Не оборачивающие декораторы ставятся ближе к `def`, чем оборачивающие.**

`log` только печатает и цель не подменяет — ему нужна настоящая `command` с её именем
и типом, поэтому он идёт вниз. `timer` возвращает обёртку — он идёт вверх и
оборачивает всё, что накопилось ниже.

Поставить наоборот можно, и язык не возразит, но `log` тогда увидит анонимную обёртку
из `timer`, и `meta.name` окажется `null` — у обёртки имени нет и взяться ему неоткуда.
Это не баг: под именем в тот момент действительно лежит она.

## Когда декоратор выполняется

В тот момент, когда исполнение проходит через объявление. Стадии между разбором и
выполнением в языке [нет](functions.md), имя существует с той строки, где его завели, —
значит `def` внутри функции декорируется **на каждом её вызове**.

```wdl
count = 0
def tick(meta) { count = count + 1 }

def outer() {
    @[tick]
    def inner() { }
    return inner;
}

outer()
outer()
println(count)                  // 2
```

Это не оговорка, а то же правило, применённое к декоратору. Практический вывод один:
регистрирующие декораторы вешаются на верхнем уровне, иначе список наберёт дубликатов.

Из того же правила бесплатно получается обёрнутая рекурсия — имя ищется в момент
вызова и находит обёртку:

```wdl
@[counted]
def fact(n) => n <= 1 ? 1 : n * fact(n - 1)

fact(5)                         // counted сработал пять раз, а не один
```

## `like`: обёртка, представляющаяся целью

У обёртки `def (*args, **named)` арность «сколько угодно». Значит, декоратор молча
съедает проверку числа аргументов, которая в языке стоит **до** входа в функцию:

```wdl
@[wrap]
def command(a, b) => a + b

command(1, 2, 3, 4)
// без like: ошибка приходит изнутри обёртки, со строки 'meta.target(...)'
```

Лечится встроенной `like(цель, обёртка)` — она возвращает обёртку, которая снаружи
выглядит целью: то же имя, та же арность, тот же контракт имён.

```wdl
def wrap(meta) {
    return like(meta.target, def (*args, **named) => meta.target(*args, **named));
}

@[wrap]
def command(a, b) => a + b

command(1, 2, 3, 4)
// ошибка: функция 'command' принимает ровно 2 аргумента, а передано 4
```

Сквозь `like` проходят имена, значения по умолчанию и пропуски: вызывающий
раскладывает аргументы по контракту цели, а `like` собирает набор заново под обёртку,
у которой позиций нет вовсе. Пропущенную середину он не заполняет — значение
по умолчанию посчитает сама цель, в своей области, как и положено.

Обёртка при этом обязана быть объявлена как `def (*args, **named)`: через неё проходит
всё, что примет цель, включая имена, которых у самой обёртки нет. Проверяется это
при создании, а не при вызове, — ошибка полезна там, где обёртку написали.

## Классы и трейты

Наблюдать и подменять класс можно так же, как функцию:

```wdl
commands = {}

def command(meta, name) {
    commands[name] = meta.target
}

@[command]("send")
class Send(text) { }
```

### Обёртка для класса это наследник

Отдельного «класса-обёртки» в языке нет и не нужно: наследование уже умеет всё,
что для этого требуется.

```wdl
def traced(meta) {
    class Proxy(*args, **named) : meta.target(*args, **named) {
        def text() => "[trace] " + super.text()
    }
    return Proxy;
}

@[traced]
class Point(x, y) {
    def text() => "(" + x + ", " + y + ")"
}

println(new Point(3, y: 4).text())      // [trace] (3, 4)
```

Держится это на [остатке в заголовке класса](classes.md#остаток-в-заголовке-args-и-named):
без `*args` и `**named` наследник не смог бы перебросить родителю то, что получил,
и обёртка работала бы только для классов без полей.

### Декораторы на методах внутри класса

Их нет. У метода нет отдельного значения, которое можно подменить: он живёт
в плоской таблице класса и связывается с экземпляром в момент обращения. Если обёртка
нужна на одном методе, её пишут снаружи:

```wdl
p = new Point(1, 2)
timed = timer(m.of(p.text))
```

`p.text` — обычное связанное значение, и объект в нём уже запомнен.

### Декорированный класс не переиспользуется

Обычное объявление класса при повторном прохождении возвращает то же значение, если
форма совпала, — на этом держится `is` для класса, объявленного внутри функции.
У декорированного класса под именем лежит результат декоратора, и совпасть ему
не с чем: каждое прохождение даёт новый класс, а объект из прошлого прохода перестаёт
быть `is` новому.

Чинить тут нечего: декоратор выполняется заново и волен вернуть что угодно —
переиспользовать просто нечего. На верхнем уровне объявление проходится один раз,
так что видно это только у декорированного класса внутри функции или цикла.

## Как это устроено в коде

| Что | Где |
|---|---|
| Токен `@` | `lexer/TokenType.AT` |
| Один декоратор в дереве | `ast/expr/Decorator` — **не** `Expr`, как и `Argument` |
| Объявление под стеком | `ast/stmt/DecoratedStmt` — обёртка вокруг объявления |
| Разбор | `Parser.decorated()`, `Parser.decorator()` |
| Применение | `Interpreter.visitDecorated`, `Interpreter.apply` |
| Сборка метаданных | `value/DecoratorMeta` — общая с `sys.meta` |
| `like` | `runtime/LikeFunction` |

Отдельный узел, а не поле в `DefDeclStmt`, `ClassDeclStmt` и `TraitDeclStmt`: три
`record` в `sealed`-иерархии — это три правки, задевающие каждого посетителя. И по
существу так вернее — декораторы не часть объявления, а действие над тем, что
объявление породило.

`visitDecorated` строит значение **не заводя имени**, применяет стек и заводит имя
один раз, уже результатом. Промежуточной записи быть не должно: между ней и итоговой
существовало бы окно, в котором под именем лежит цель, а не то, что просил автор.

Метаданные дописываются нулевым позиционным аргументом к обычному списку и
раскладываются обычным связывателем. Отсюда бесплатно берётся и ошибка про дважды
заданный параметр, и работа именованных аргументов декоратора, и раскрытие в них.

## Чего в декораторах не будет

* **`@reg` без скобок** — отложено, а не отвергнуто: аддитивно, добавится второй
  версией.
* **Декоратор на анонимной функции** (`f = @[timer] def () { }`) — тоже вторая версия.
  Сейчас это пишется как `f = timer(m.of(g))`, а новая ветка в префиксной позиции
  разбора стоит дороже, чем экономит.
* **Декораторы на методах** — см. выше: подменять нечего.
* **Автоматический перенос имени и арности на обёртку.** Это делает `like`, и делает
  явно. Молча подменять контракт возвращённого значения движок не станет — декоратор
  вправе вернуть функцию с другим смыслом, и притвориться целью она должна по просьбе,
  а не по умолчанию.

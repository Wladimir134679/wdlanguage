# Члены значений

> `text.size`, `a.sort()`, `213.toString()`, `Circle.parent` — это не новый синтаксис.
> Это [то же обращение по ключу](access.md), на которое значение отвечает само,
> когда своих данных с таким ключом у него нет.

Рабочие примеры: [`examples/members.wdl`](../examples/members.wdl),
[`examples/introspection.wdl`](../examples/introspection.wdl),
[`examples/extend.wdl`](../examples/extend.wdl).

## Одно правило

Ни нового узла, ни второй формы записи. `x.имя ≡ x["имя"]` остаётся дословно верным,
а значит из правила сразу следует то, что в других языках делают отдельно:

```wdl
text = "Hello"
println(text.size)          // 5
println(text["size"])       // 5 — та же запись
key = "si" + "ze"
println(text[key])          // 5 — имя члена можно вычислить

a = [1, 2]
push = a.push               // метод — обычное значение
push(3)
println(a)                  // [1, 2, 3] — получатель не потерялся
```

«Вызова метода» в языке по-прежнему нет: есть обращение, давшее функцию, и вызов.

## Свойство или метод

Половины две, и различает их **не цена и не то, что член делает с получателем,
а можно ли верить ответу через строку**:

> **Метод** — если есть аргументы, **или** меняется получатель, **или** ответ приходит
> из времени либо из мира снаружи, **или** честное имя для него — глагол.
> **Свойство** — если ответ зависит только от значения, каким оно видно сейчас,
> и измениться может лишь от действия, написанного в тексте.

```wdl
n = a.size
a.push(4)                   // причина изменения написана в тексте
println(a.size)             // n + 1 — сюрприза нет
```

Планка именно такая — «не меняется само по себе», а не «не меняется никогда», —
потому что более высокую язык не держит и в основании: `a[0]` после записи в массив
тоже отвечает иначе, и никто не считает это ложью. Обещание языка про время
сформулировано в [потоках](threads.md): «одно обращение атомарно, выражение целиком
нет».

Отсюда два следствия, которыми пользуются:

* **свойство безопасно вынести из цикла** — между итерациями его меняет только
  написанное действие;
* **записи у встроенного свойства нет.** Присваивание в свойство — действие,
  замаскированное под имя, а имя обещает, что за ним ничего не происходит:

```wdl
a = [1, 2]
a.size = 5                  // ошибка: член 'size' только для чтения
```

**Имя — часть правила.** Свойство называется существительным, метод — глаголом.
Отсюда пары «свойство даёт новое значение, метод переставляет на месте»:

```wdl
println(a.sorted)           // новый массив, a не тронут
a.sort()                    // тот же массив, переставлен на месте
```

## Порядок разрешения

Сверху вниз, остановка на первом попадании:

| # | Что | У кого |
|---|---|---|
| 1 | собственные данные | ключ объекта, индекс массива и строки, имя модуля, поле экземпляра, статика класса |
| 2 | свойство класса | у экземпляра |
| 3 | метод класса | у экземпляра |
| 4 | член типа | у всех, кроме `null` |
| 5 | расширение (`extend`, приложение) | у типа и у класса |
| 6 | нечего вернуть | объект, экземпляр, класс — `null`; остальные — ошибка |

**Данные раньше членов** — то же решение, что «поле перекрывает метод» у класса:

```wdl
box = {size: "L"}
println(box.size)           // L — это данные, их клали руками
println(len(box))           // 1 — а это размер
```

Иначе язык решал бы за автора, что его собственный ключ значит меньше встроенного
имени. Цена честная, и её надо знать: **у объекта, экземпляра, класса и модуля член
работает, только пока имя не занято**. Для кода, которому нужен гарантированный ответ,
есть [путь через дескриптор](#дескриптор-типа-путь-в-обход-данных). У строки, числа,
массива и функции конфликта нет вовсе: строковый ключ у них данными быть не может.

`len` и `typeof` берут ответ из таблицы типа напрямую, не проходя обращением по ключу, —
поэтому `len({size: "L"})` возвращает 1, а не «L». И поэтому же `len(x)` и `x.size`
разойтись не могут: за ними один и тот же член.

## Наборы по типам

### Массив

| Свойства | |
|---|---|
| `size`, `empty` | сколько элементов, пуст ли |
| `first`, `last` | первый и последний; у пустого — `null` |
| `sorted`, `reversed`, `copy` | снимки: новый массив, получатель не тронут |

| Методы | |
|---|---|
| `push(v)`, `pop()` | добавить в конец (отдаёт сам массив), снять с конца |
| `insert(i, v)`, `remove(i)` | вставить, удалить (отдаёт удалённое) |
| `indexOf(v)`, `contains(v)` | позиция или `-1`, есть ли такое — тот же ответ, что у `v in a` |
| `join(sep)`, `slice(from, to)` | склеить строкой, вырезать кусок; конец не входит |
| `sort()`, `reverse()`, `clear()` | на месте; отдают сам массив |

`first` и `last` у пустого массива дают `null`, а не ошибку: это вопрос «есть ли
что-нибудь», и `if (a.first)` должен просто работать. Ошибкой остаётся `a[0]` —
там названа позиция, которой нет.

**Отрицательный аргумент у `insert`, `remove` и `slice` считается от конца** — то же
правило, что у `a[-1]`: «число значит позицию» обязано значить одно и то же везде.
Из двух [дисциплин числового ключа](access.md#две-дисциплины-числового-ключа) `insert`
и `remove` строги, `slice` подрезает границы. У `slice` конец не входит, в отличие
от среза `a[from..to]`, и это сознательно: `..` включителен во всём остальном языке,
а полуинтервал нужен ровно затем, чтобы `a.slice(0, n)` при `n == 0` давало пусто.

Сортировка упорядочивает ровно так же, как оператор `<`: сравнение одно на язык.

### Строка

Строка неизменяема, поэтому здесь **нет ни одного члена, меняющего получателя**.

| Свойства | |
|---|---|
| `size`, `empty` | длина в кодовых единицах UTF-16 |
| `upper`, `lower`, `trimmed` | снимки: новая строка |
| `chars` | снимок: массив символов **по кодовым точкам** |

| Методы | |
|---|---|
| `indexOf(s)`, `contains(s)` | где встретилась, встретилась ли — тот же ответ, что у `s in text` |
| `startsWith(s)`, `endsWith(s)` | начинается, заканчивается |
| `split(sep)`, `slice(from, to)`, `replace(a, b)`, `repeat(n)` | у `slice` конец не входит, отрицательный аргумент — от конца |
| `toNumber()` | число или `null`, если не разобралось |

Единицы измерения названы вслух, потому что ответов честно два:

```wdl
smile = "😀"
println(smile.size)         // 2 — кодовые единицы: так работает индексация, и это O(1)
println(smile.chars.size)   // 1 — обход идёт по кодовым точкам и не рвёт пару
```

### Число

| Свойства | | | Методы | |
|---|---|---|---|---|
| `abs`, `sign` | модуль и знак | | `round(digits)` | округление |
| `floor`, `ceil` | вниз и вверх, целым | | `clamp(low, high)` | загнать в границы |
| `integer` | целое ли значение | | `toString()` | глагол в имени — значит метод |

Обращение к числовому литералу разбирается само собой: дробная часть требует цифру
*после* точки, поэтому `213.toString()` — это обращение, а не сломанный литерал.
Одна ловушка есть, и она общая для всех языков:

```wdl
println(-5.abs)             // -5 — это -(5.abs): обращение связывает сильнее минуса
println((-5).abs)           // 5
```

### Объект

| Свойства | | | Методы | |
|---|---|---|---|---|
| `size`, `empty` | | | `has(key)`, `get(key, default)` | `has` — тот же ответ, что у `key in obj` |
| `keys`, `values`, `pairs` | снимки | | `remove(key)`, `clear()` | |

Набор короткий намеренно: каждый член объекта — это отобранное у автора имя ключа,
работающее через раз. Всё остальное живёт у дескриптора `Object`.

### Диапазон

| Свойства | | | Методы | |
|---|---|---|---|---|
| `from`, `to` | границы, обе включительны | | `contains(v)` | то же, что `v in range` |
| `empty` | пуст ли (`5..1` пуст) | | | |

Диапазон неизменяем, поэтому меняющих членов здесь нет вовсе, а всё, что он о себе
знает, — это две границы и ответ «пуст ли»; устареть такой ответ не может, значит
это свойства.

`size` сознательно нет: он честно определён только при целых границах, а свойство,
бросающее ошибку на `0.5..2.5`, — плохое свойство, потому что границу «когда можно
спрашивать» пришлось бы держать в голове читателю. Вернётся вместе с шагом, когда
будет спрос.

### Логическое и `null`

Своих членов нет, и это ответ, а не пропуск: отрицание уже есть оператором,
а приведение логического к числу язык не позволяет [намеренно](types.md).
Обращение к `null` остаётся ошибкой — оно обязано ломаться там, где написано.

Универсальный член `type` (дескриптор значения) есть у всех типов, кроме `null`;
всеобщим ответом остаётся `typeof(x)`.

## Что рассказывает о себе значение

Интроспекция без рефлексии: движок и так знает имена параметров, состав класса
и подмешанные трейты — член просто открывает дверь.

### Функция

| Член | |
|---|---|
| `name` | имя, под которым функция известна, или `null` |
| `anonymous` | объявлена ли без имени |
| `params` | массив параметров или **`null`, если имена неизвестны** |
| `arity` | `{min, max}`; `max` — `null` у функции с остатком |
| `rest`, `namedRest` | имена остатков или `null` |
| `annotations` | [аннотации](annotations.md) объявления снимком; пустой объект, если их нет |

Параметр — объект `{name, required, default, annotations}`, а не строка: за именами в контракт
придут типы, и строка закрыла бы дверь в тот же день. У параметра с отложенным
значением по умолчанию `default` — честный `null`: за ним стоит выражение, которое
считается в области вызова.

```wdl
def total(price, count = 1) => price * count

println(total.params[1].name)       // count
println(total.params[1].required)   // false
println(println.params)             // null — контракт без имён, а не «нет параметров»
```

**Честная оговорка: декоратор подменяет значение.** У обёртки своя сигнатура, поэтому
после `@[log]` спрашивают уже её. Имена и аннотации переживают декоратор там, где автор
позвал `like()` — она делегирует цели и контракт, и `annotations`
([декораторы](decorators.md)).

### Класс, трейт, модуль

| Класс | | | Трейт | | | Модуль | |
|---|---|---|---|---|---|---|---|
| `name` | | | `name` | | | `name` | |
| `parent` | классом или `null` | | `methods` | с телом | | `names` | что объявлено |
| `traits` | значениями | | `properties` | | | | |
| `methods`, `properties` | плоские таблицы | | `requirements` | что класс обязан объявить | | | |
| `params`, `arity` | заголовок = поля | | `annotations` | снимком | | | |
| `method(имя)`, `property(имя)` | описание члена или `null` | | | | | | |
| `annotations` | снимком | | | | | | |

Класс и трейт отдаются **значениями, а не именами**: по строке нельзя ни спросить
`is`, ни создать экземпляр, а реестра имён язык не заводит.

```wdl
println(Circle.parent.name)         // Shape
println(circle is Circle.traits[0]) // true — трейт сразу годится для is
```

`methods` и `properties` — это **имена**, потому что значения у них снаружи
не существует. Спросить о конкретном члене можно `method(имя)` и `property(имя)`;
они отдают **описание, а не значение**: несвязанного метода в языке не бывает
(приёмника у него нет), а за свойством стоит код, который без экземпляра выполнять
нечем. Нет такого члена — `null`: это вопрос, а не обращение.

```wdl
class User(id) {
    @{transactional: true}
    def save(force = false) { }

    property label => "user " + id
}

println(User.method("save")["name"])            // save
println(User.method("save")["annotations"])     // {"transactional": true}
println(User.property("label")["readonly"])     // true
println(User.method("nope"))                    // null
```

## Дескриптор типа: путь в обход данных

У объекта, экземпляра, класса и модуля данные перекрывают члены. Гарантированный путь
идёт через [дескриптор типа](types.md): член становится обычной функцией, берущей
получателя первым аргументом.

```wdl
box = {size: "L"}
println(box.size)                   // L — данные
println(Object.size(box))           // 1 — член типа

println(Array.size([1, 2, 3]))      // 3   — свойство функцией одного аргумента
println(Array.join(["a", "b"], "-")) // a-b — метод функцией n + 1 аргумента
```

**Таблица одна, дескриптор — её проекция**, а не второй набор: разойтись
`"x".upper` и `String.upper("x")` нечем. Справка о самом типе лежит отдельно
от членов — под ключом `info`, — иначе `Function.name` значило бы сразу и «имя типа»,
и «член name у функций»:

```wdl
println(Number.info.name)           // number
println(Number.info.title)          // число
```

Дескриптор неизменяем: `Number.x = 1` — отказ. Он один на процесс, и запись меняла бы
его всем интерпретаторам сразу.

## Расширение

### Скрипт: `extend`

```wdl
extend Array {
    property second => this[1]

    def swap(i, j) {
        item = this[i]
        this[i] = this[j]
        this[j] = item
        return this;
    }
}
```

Слова те же, что в теле класса, и это не совпадение: `this` — получатель,
`property` — свойство, `def` — метод. Расширять можно и класс — тогда член достаётся
его экземплярам и экземплярам потомков.

**К получателю обращаются явно — `this.name`, а не `name`.** Правило одно для типа
и для класса: у массива и строки полей нет вовсе, и разрешить голое имя только классам
значило бы завести два разных `extend`. Заодно ключ чужого объекта не перекрывает
глобальные имена.

Запретов четыре, и расширение из них и состоит:

* **встроенное перекрыть нельзя** — скрипт сломал бы не себя, а всё, что работает
  с такими значениями в этом запуске, включая библиотеки;
* **повторное объявление тем же именем — ошибка**: тихая победа последнего здесь
  худший из возможных исходов;
* **записи нет**: `def set(value)` у члена типа — отказ при объявлении;
* **только на верхнем уровне файла**: объявление внутри условия или функции меняло бы
  поведение уже отработавшего кода в середине запуска.

**Член появляется тогда, когда выполнился `extend`** — то же правило, что у всякого
имени в языке. Верхний уровень ограничивает место в тексте, но не момент во времени:
`import` законен в теле функции и в потоке, а выполнение модуля — это выполнение его
верхнего уровня. Регистрировать расширения заранее значило бы вернуть стадию
подготовки, убранную ради ленивой загрузки модулей.

**Расширение принадлежит запуску, а не файлу.** Объявили в модуле — работает везде
в этом запуске, но не в соседнем интерпретаторе того же процесса.

`extend` — контекстное слово, а не ключевое: обычной переменной с таким именем язык
не отнял, ровно как и `property`.

### Приложение: `MemberRegistry`

Библиотека добавляет члены оттуда же, откуда кладёт имена и классы, — из
`Library.installTo`, через область видимости ([встраивание](embedding.md)):

```java
public Environment installTo(Environment scope) {
    MemberRegistry members = scope.members();
    if (members != null) {
        members.install(ValueType.STRING, MemberSet.builder()
                .property("slug", (receiver, context, span) -> ...)
                .method("times", Arity.exactly(1), (receiver, context, arguments, span) -> ...)
                .build());
    }
    return scope;
}
```

Набор принадлежит запуску: два движка в одном процессе не делят расширения. Перекрыть
встроенное библиотека тоже не вправе — отказ приходит при установке.

## Оператор — тоже член

`` def `+`(right) `` в теле класса объявляет **обычный метод**: имя записано
в обратных кавычках, потому что иначе его не написать, — и на этом отличия кончаются.
Отсюда бесплатно следует всё остальное: оператор виден в `Money.methods`, читается
как значение через обращение, добавляется готовому классу через `extend` и работает
у классов, встроенных приложением.

```wdl
class Money(amount) {
    def `+`(right) => new Money(amount + right.amount)
    def `<=>`(right) => amount - right.amount
}

println(new Money(3) < new Money(5))    // true
```

Спрашивается оператор **только там, где не справилось ядро**, и новой встроенной
функцией не сопровождается. Полная таблица — что перегружается, что нет и почему —
в [выражениях](expressions.md#перегрузка-операторов).

## Чего члены не делают

* **не участвуют в переборе.** `for (k in obj)` идёт по данным; член — это ответ
  о значении, а не его содержимое;
* **не попадают в сериализацию.** JSON пишет данные, и только их;
* **не меняют равенство и печать.** Связанный метод при этом сравнивается по ссылке:
  `a.push == a.push` — ложь, ровно как у метода класса;
* **не заменяют модули.** Работа с файлами и сетью остаётся модулем: если для действия
  нужен мир снаружи процесса — это модуль, а не член.

## Диагностика

Промах по имени — самая частая ошибка при таком наборе, поэтому текст называет тип,
называет промах и предлагает похожее имя:

```
у значения типа массив нет члена 'sze'. Похоже на 'size'
у значения типа число нет члена 'qqq'. Есть: abs, sign, floor, ceil, integer, ...
```

Второе частое — скобки, и сообщение говорит именно про них, а не про тип результата:

```wdl
println([1, 2].size())
// 'size' у значения типа массив — свойство, а не метод: скобки лишние
```

Подсказки про скобки нет там, где имя перекрыто данными: за скобками стоял ключ,

как и раньше, — именно поэтому нужен путь через дескриптор.

# Типы данных

Язык динамический: тип есть у значения, а не у переменной. Одна и та же переменная
спокойно держит сначала число, потом строку, потом функцию — проверять, что там
сейчас, приходится по значению.

```wdl
значение = 42
println(typeof(значение))      // number
значение = "теперь строка"
println(typeof(значение))      // string
```

Типов одиннадцать, и список закрыт: новый тип — это правка ядра, а не то, что
появляется само из библиотеки. У каждого есть имя-дескриптор в корневой области
видимости (`Number`, `String`, …) — про это раздел
[«Проверка типа»](#проверка-типа) ниже.

| Тип | `typeof` | Литералы | Изменяемый | Внутри |
|---|---|---|---|---|
| ничего | `null` | `null` | — | `NullValue.NULL` |
| логическое | `bool` | `true`, `false` | — | `BoolValue.TRUE` / `FALSE` |
| число | `number` | `42`, `1_000`, `3.14`, `6.02e23`, `0xFF`, `0b1010` | — | `IntValue(long)` или `FloatValue(double)` |
| строка | `string` | `"текст"`, `"с \n экранами"` | — | `StringValue(String)` |
| массив | `array` | `[1, 2, [3]]` | **да** | `ArrayValue` поверх `ArrayList` |
| объект | `object` | `{имя: "болт", "цена": 12}` | **да** | `MapValue` поверх `LinkedHashMap`; экземпляр класса — её наследник `InstanceObjectValue` |
| функция | `function` | пока только встроенные, дальше — `def` | — | `FunctionValue`: `BuiltinFunction` / `UserFunction` |
| класс | `class` | `class Точка(x, y)` — класс сам по себе значение | — | `ClassValue`: `WdlClass` / `NativeClass` |
| трейт | `trait` | `trait Печатаемый { def text() }` | — | `TraitValue`: `WdlTrait` / `NativeTrait` |
| модуль | `module` | значение `import`а | — | `ModuleValue` |
| диапазон | `range` | `1..5`, `0..n - 1` | — | `RangeValue(NumberValue, NumberValue)` |

Подробности про последние три — в [классах](classes.md) и [модулях](modules.md);
здесь они упомянуты только ради полноты списка типов.

## null

Отсутствие значения — самостоятельный тип с единственным значением `null`.

```wdl
println({a: 1}.b)                    // null: у объекта нет такого ключа
println({a: 1}.b || "по умолчанию")  // по умолчанию
```

Это единственный тип (вместе с `false`), который ложен в условиях. Арифметика с ним
запрещена: `null + 1` — ошибка, а не «единица» и не «строка null». Если значение
не пришло, продолжать расчёт бессмысленно, и лучше сказать об этом сразу.

## Логическое

Два значения: `true` и `false`. Отдельный тип, а не число `0/1` — иначе `true + 1`
становится «работающим» кодом, а вместе с ним приходит целый класс ошибок, которые
язык мог бы поймать сам.

Логические значения возвращают сравнения (`==`, `<`, …) и отрицание `!`.
Операции `&&` и `||`, наоборот, возвращают **операнд**, а не приведённое значение —
об этом ниже, в разделе про истинность.

## Число

Для скрипта число одно. Внутри их два представления, и разделение существует ради
одного: целочисленные расчёты должны оставаться точными.

* **целое** — 64 бита со знаком (`long`). Счётчики, индексы, битовые маски;
* **вещественное** — `double`.

### Правило продвижения

Пока оба операнда целые — результат целый. Появилось вещественное — весь пример
считается в `double`.

```wdl
println(2 + 2)        // 4
println(2 + 2.0)      // 4.0
println(2 * 3.0)      // 6.0
```

Переполнение 64 бит не заворачивает разряды, а переводит результат в вещественное:

```wdl
println(9223372036854775807 + 1)     // 9.223372036854776E18
```

Потерю точности видно в выводе, заворот — нет. Поэтому выбран первый вариант.

### Деление

Деление целых даёт целое, только если оно точное:

```wdl
println(6 / 3)        // 2
println(7 / 2)        // 3.5
```

Округление вниз в динамическом языке — источник тихих ошибок в расчётах; когда
понадобится именно целочисленное деление, для него будет функция с говорящим именем.

**Деление на ноль — всегда ошибка**, в том числе вещественное. `inf` в середине
расчёта обнаруживается через десяток строк и уже без объяснения причины.

### Биты

`&` `|` `^` `~` `<<` `>>` `>>>` работают только с целыми. Вещественное здесь почти
всегда означает ошибку выше по коду, а тихое отбрасывание дробной части её прячет.

```wdl
println(0xF0 | 0b1111)    // 255
println(1 << 10)          // 1024
println(~0)               // -1
println(1.5 & 1)          // ошибка: операция '&' работает только с целыми числами,
                          //         а здесь вещественное 1.5
```

Шестнадцатеричный и двоичный литералы — это про биты, а не про величину:
`0xFFFFFFFFFFFFFFFF` законно читается как маска из 64 единиц, то есть `-1`.

### Печать

Целое печатается без точки, вещественное — с точкой, даже если дробная часть нулевая:
раз тип вещественный, скрывать это незачем. Особые значения короткие: `inf`, `-inf`,
`nan` вместо джавовских `Infinity` и `NaN`.

## Строка

Неизменяемая последовательность символов в двойных кавычках. Поддерживаются
`\n`, `\t`, `\r`, `\b`, `\f`, `\0`, `\\`, `\"`, `\'` и `\uXXXX`.

```wdl
привет = "Привет, мир!"
println(len(привет))       // 12
println(привет[0])         // П — символ строкой длиной 1
```

Обращение по номеру символа — то же [единое обращение](access.md), что и у массивов.
Запись по индексу запрещена: строки лежат в ключах объектов, и изменение на месте
испортило бы их.

```wdl
привет[0] = "п"           // ошибка: строки неизменяемы
```

Сложение со строкой — конкатенация, с любой стороны, и второй операнд печатается
в пользовательском виде:

```wdl
println("итого: " + 42)    // итого: 42
println(5 + " штук")       // 5 штук
println("флаг: " + true)   // флаг: true
```

Сравниваются строки по кодовым точкам — предсказуемо и без зависимости от локали.
Сортировка по правилам конкретного языка появится в стандартной библиотеке, где
можно будет указать, какого именно.

Имена в скриптах, кстати, тоже могут быть на любом алфавите: `количество`, `товар` —
обычные имена.

## Массив

Упорядоченный **изменяемый** список значений с доступом по целому индексу.

```wdl
склад = [10, 20, 30]
println(склад[1])          // 20
склад[0] = 15
склад[2] += 5
println(len(склад))        // 3
println(склад)             // [15, 20, 35]
```

Элементы любых типов, включая другие массивы и объекты. Складывать массивы можно —
получается новый:

```wdl
println([1, 2] + [3])      // [1, 2, 3]
```

**Выход за границы — ошибка**, а не `null`:

```wdl
println(склад[5])          // ошибка: индекс 5 вне границ массива размером 3
```

Индекс берётся из расчёта, и молчаливый `null` в этом месте означает, что расчёт
неверен, — а узнают об этом через десяток строк, уже без объяснения причины.

Массив — ссылка. Присваивание копии не делает, сравнение идёт по ссылке:

```wdl
a = [1, 2]
b = a
b[0] = 99
println(a[0])              // 99 — это тот же массив
println([1, 2] == [1, 2])  // false — два разных массива
```

## Объект

Набор пар «ключ — значение» с сохранением порядка вставки. Закрывает сразу две
привычные роли: запись с полями и словарь.

```wdl
товар = {имя: "болт", цена: 12}

println(товар.имя)             // болт
println(товар["цена"])         // 12 — та же операция, другая запись
товар.цвет = "серый"           // запись — тоже она
товар.цена += 3
println(товар)                 // {"имя": "болт", "цена": 15, "цвет": "серый"}
```

**Ключ — любое значение, а не только строка.** Имя без кавычек в литерале и точка
в обращении — сахар, разворачивающийся в ключ-строку. Поэтому ключ можно вычислить,
и отдельного синтаксиса для словарей не нужно:

```wdl
поле = "цена"
println(товар[поле])                   // 15
println(товар["це" + "на"])            // 15

счётчики = {1: "один", 2: "два"}
println(счётчики[1])                   // один
println(счётчики[1.0])                 // один — ключ нормализуется
```

Числовые ключи приводятся к каноническому виду: `1` и `1.0` попадают в одну ячейку.
Одно и то же по смыслу число не должно давать два разных ключа.

**Отсутствующий ключ даёт `null`, а не ошибку** — в отличие от массива. Проверка
«есть ли поле» в динамическом языке обычная операция, и заставлять писать её через
перехват ошибки неразумно:

```wdl
println(товар.вес || "вес не указан")
```

Объект, как и массив, — ссылка и сравнивается по ссылке. Порядок пар сохраняется:
объекты печатают и сериализуют, и вывод не должен меняться от запуска к запуску.

### Экземпляр класса — тот же объект, но с порядком

`typeof(p)` у экземпляра даёт `object`, и всё, что умеет объект, экземпляр умеет
тоже: обращение по вычисленному ключу, перебор полей, `len`, запись нового ключа.
Одно у него есть сверх этого — **объявленный порядок полей**: отдельного объявления
полей в языке нет, [заголовок класса](classes.md) и есть список его компонентов,
ровно как у Java-рекорда.

Отсюда экземпляр [распаковывается обеими формами](statements.md#распаковка-x-y--point),
а обычный объект — только по именам:

```wdl
class Vec3(x, y, z) { }
p = new Vec3(1, 2, 3)

a, b, c = *p                // по позициям — порядок берётся из заголовка
x, z = **p                  // по именам полей

o = {x: 1, y: 2, z: 3}
x, z = **o                  // так можно
// a, b, c = *o             // а так нет: порядок вставки — данные, а не договорённость
```

Порядок вставки у объекта сохраняется, но договорённостью не является: объект
из JSON или из сети приехал бы переставленным, и распаковка по позициям молча
положила бы не то. У заголовка класса такой беды нет — он написан в исходнике.

## Функция

Функция — обычное значение в обычной переменной. Не синтаксис, не особая сущность,
не отдельная таблица имён.

```wdl
напечатать = println
напечатать("работает")

вывод = {строкой: println, без_перевода: print}
вывод.строкой("и из поля объекта тоже")

println(typeof(println))       // function
println(println)               // def println
```

Из этого следует всё остальное: функцию можно передать аргументом, вернуть из другой
функции, положить в массив и в поле, а `точка.строкой()` — это обращение по ключу
плюс вызов результата, а не особый «вызов метода».

Число аргументов проверяется до входа в функцию, поэтому сообщение одинаково
для всех функций:

```
ошибка: функция 'typeof' принимает ровно 1 аргумент, а передано 0
```

Функций два вида, и различить их изнутри языка нечем: встроенные — `println`, `print`,
`typeof`, `len` (см. [инструкции](statements.md#встроенные-функции)) — и написанные
на wdl через `def` (см. [функции](functions.md)). Это две реализации одного типа;
вызывающий код о разнице не знает, поэтому свою функцию можно передать туда, где
ждут встроенную, и наоборот.

## Диапазон

Диапазон — два числа и правило «между ними включительно»: `1..5` читается «от 1 до 5».

```wdl
workingAge = 18..65
println(typeof(workingAge))    // range
println(42 in workingAge)      // true
println(workingAge.from, "..", workingAge.to)
for (i in 1..5) print(i, " ")  // 1 2 3 4 5
```

**Полноценный тип, а не форма записи внутри `case`.** Пока `..` жил только справа
от `in` в образце, его можно было держать частью синтаксиса; как только
[`in` стал работать везде](expressions.md#семантика-операций), `age in 18..65`
обязано работать, а значит `18..65` обязано быть значением, которое кладут
в переменную и передают в функцию. Сделать его нативным классом прелюдии дешевле,
но тогда `typeof(1..5)` ответил бы `object`, а `typeof` врать не должен.

**`5..1` пуст, а не идёт вниз.** Довод железный: `for (i in 0..n - 1)` при `n == 0`
даёт `0..-1`, и это обязано быть нулём проходов, а не тихим проходом в обратную
сторону. Убывающий диапазон, когда понадобится, будет записан шагом, а не порядком
границ.

**Границы бывают вещественными, перебор — нет.** `1.5 in 0.5..2.5` — законный вопрос
и работает; `for (x in 0.5..2.5)` — ошибка, потому что шаг перебора равен единице,
и какие числа этот диапазон содержит «по одному», языку решать не за что.

**Неизменяем и сравнивается по значению** — в отличие от массива: `1..5 == 1..5`
истинно, потому что менять в диапазоне нечего, и два одинаковых диапазона
неразличимы по определению.

Шага (`1..10 by 2`) и свойства `size` нет. Шаг — третье поле и новый оператор ради
редкого случая; `size` честно определён только при целых границах, а свойство,
бросающее ошибку на `0.5..2.5`, — плохое свойство. Оба вернутся, когда будет спрос.

## Операторы у своих типов

Класс задаёт свой смысл `+`, `<`, `in` и остальным операторам — объявлением обычного
члена с именем в обратных кавычках:

```wdl
class Money(amount) {
    def `+`(right)   => new Money(amount + right.amount)
    def `<=>`(right) => amount - right.amount
}
```

Спрашивается такой член только там, где не справилось ядро, поэтому арифметика чисел
не меняется ни от одного объявления. Правила целиком — в
[выражениях](expressions.md#перегрузка-операторов).

## Проверка типа

У каждого из одиннадцати типов есть свой дескриптор — значение с именем, стоящее
в корневой области видимости с большой буквы: `Null`, `Bool`, `Number`, `String`,
`Array`, `Object`, `Function`, `Class`, `Trait`, `Module`, `Range`. `typeof` возвращает
именно его, а не строку:

```wdl
println(typeof(1))            // number  — печатается так же, как раньше
println(typeof(1) == Number)  // true    — а сравнивать теперь можно с именем типа
```

**Печать не меняется: меняется только сравнение.** `typeof(x)` печатается словом
`number`, `string`, `array` — тем же самым, что стоит в столбце `typeof` выше:
это `display()` дескриптора, буквальный идентификатор типа. А вот
`typeof(x) == "number"` больше не работает — сравниваются дескриптор и строка,
два разных типа, и результат тихо `false`. Проверять тип нужно так:

```wdl
println(typeof(1) == Number)      // true
x is Number                       // то же самое, короче и читается как вопрос
```

**Дескриптор — ещё и путь к [членам типа](members.md) в обход данных.** `Array.size`
— это функция `(массив) -> число`, тот же член, что отвечает на `a.size`; нужен он там,
где имя занято собственным ключом значения:

```wdl
box = {size: "L"}
println(box.size)             // L — данные
println(Object.size(box))     // 1 — член типа
```

Справка о самом типе лежит отдельно от его членов — под ключом `info`:
`Number.info.name` даёт `"number"`, `Number.info.title` — `"число"`. Иначе имя типа
и одноимённый член спорили бы за одно и то же место.

**Дескриптор — обычное имя, а не константа.** Пространство имён в языке одно,
и как `println` можно перекрыть присваиванием, так можно перекрыть и `Number`:
`Number = 5` ломает только тот скрипт, который это сделал, — `typeof` и `is`
других имён не знают, они берут дескрипторы из своей внутренней таблицы, а не
поиском по имени.

**Дескриптором нельзя ни создать значение, ни дописать в него член:**

```wdl
new Number()      // ошибка: 'Number' — тип, а не класс: типом нельзя создать экземпляр
Number.x = 1       // ошибка: в тип 'Number' нельзя записать: дескриптор типа неизменяем
```

Оба отказа — не капризы реализации, а следствие того, что дескриптор один на весь
процесс (см. [«Как это устроено в коде»](#как-это-устроено-в-коде) ниже): позволь
он запись, одна строка одного скрипта поменяла бы дескриптор всем остальным
интерпретаторам, работающим в этом же процессе одновременно.

**`typeof(x) == Тип` и `x is Тип` — разные вопросы**, и совпадают они только
у самих дескрипторов, потому что у типов иерархии нет. У классов
это уже не так: подробности и пример — в разделе
[«`typeof` против `is`»](classes.md#typeof-против-is) документации по классам.

## Общие правила

### Истинность

Ложны только `null` и `false`. Ноль, пустая строка и пустой массив истинны.

```wdl
println(!0)        // false — ноль истинен
println(!"")       // false
println(!null)     // true
```

Одно правило вместо списка исключений, и «значения нет» не путается с «значение равно
нулю». Это же правило действует в `&&`, `||`, `? :`, `if` и `while`.

`&&` и `||` ленивы и возвращают сам операнд:

```wdl
имя = null
println(имя || "без имени")            // без имени
println(товар && товар.цена)           // 15
```

### Равенство и сравнение

`==` не приводит типы: разные типы — не равны, и точка.

```wdl
println(1 == 1.0)      // true  — числа сравниваются по величине
println(1 == "1")      // false — число и строка
println(null == null)  // true
```

Языки, где `1 == "1"` истинно, десятилетиями расплачиваются таблицами исключений,
которые никто не помнит наизусть.

Упорядочивать (`<`, `<=`, `>`, `>=`) можно числа между собой и строки между собой;
остальное — ошибка. Диапазон сравнивается по значению, как число и строка:
`1..5 == 1..5` истинно.

Массивы и объекты сравниваются по ссылке (см. выше). Сравнение по содержимому,
когда понадобится, будет функцией стандартной библиотеки, а не операцией `==`:
структурное сравнение стоит обхода всей структуры и требует решать, что делать
с массивом, который содержит сам себя.

### Как значения печатаются

У значения два вида: пользовательский и отладочный. Разница только в строках.

| Значение | Пользовательский (`println`, `+`) | Отладочный (внутри массива, в REPL) |
|---|---|---|
| `"текст"` | `текст` | `"текст"` |
| `42`, `3.5`, `true`, `null` | `42`, `3.5`, `true`, `null` | так же |
| `[1, "два"]` | `[1, "два"]` | `[1, "два"]` |
| `{a: "б"}` | `{"a": "б"}` | `{"a": "б"}` |
| `1..5` | `1..5` | `1..5` |

То есть строка сама по себе печатается без кавычек, а внутри контейнера — с кавычками:
`println("итого: " + 5)` не должен выводить лишние кавычки, а вот в `[1, "2"]` важно
видеть, где число, а где строка.

### Изменяемость

Неизменяемы все типы, кроме массива и объекта. Присваивание массива или объекта
копии не делает — передаётся ссылка. Функции копирования появятся в стандартной
библиотеке.

## Как это устроено в коде

Все значения — `sealed`-иерархия `ru.wds.wdl.value.Value`:

```
Value
├── NullValue          (синглтон NULL)
├── BoolValue          (TRUE / FALSE)
├── NumberValue        (sealed)
│   ├── IntValue       long, кэш значений -128..1024
│   └── FloatValue     double
├── StringValue        record поверх String
├── ArrayValue         ArrayList
├── MapValue           LinkedHashMap<Value, Value>
│   └── InstanceObjectValue   она же + ссылка на класс
├── FunctionValue      интерфейс (открытая ветка иерархии)
│   ├── BuiltinFunction
│   └── UserFunction
├── ClassValue         интерфейс, реализация в runtime.WdlClass
└── TraitValue         интерфейс, реализация в runtime.WdlTrait
```

Почему так:

* **`sealed`, а не `int`-константа типа.** В прошлой реализации тип значения был
  числом, и компилятор ничем не помогал. Здесь полный список типов известен, каждый
  `switch` по значению проверяется на полноту, и добавление типа сразу подсвечивает
  все места, которые надо дополнить.
* **`FunctionValue`, `ClassValue` и `TraitValue` — открытые ветки** (`non-sealed`):
  их реализации держат дерево, замыкание и интерпретатор, поэтому живут в `runtime`,
  а здесь остаются интерфейсы. Иначе пакет `value` потянул бы зависимость
  на выполнение. Для вызывающего реализации неразличимы: встроенная функция,
  пользовательская с телом-деревом, позже мост к Java-методу.
* **Один тип языка — два класса.** Тип `object` представлен `MapValue` (карта пар)
  и её наследником `InstanceObjectValue` (экземпляр класса). Для скрипта это один
  тип: `typeof` у обоих даёт `object`, и все операции над объектом работают
  с обоими. Разделены они потому, что ссылка на класс, точка отсчёта для `super`
  и корневой экземпляр — вещи, нужные экземпляру и бессмысленные у обычной карты;
  держать их полем в каждом объекте ради конструкции, которая встречается в скрипте
  считанные разы, — плохая сделка. Наследование при этом оставляет
  `case MapValue` рабочим для обоих: что умеет объект, экземпляр умеет тоже.
* **Значения ничего не знают о выполнении.** Функция получает всё нужное через
  `CallContext` — интерфейс, объявленный рядом со значениями и реализованный
  контекстом выполнения. Поэтому пакет `value` не зависит от `runtime`.
* **Правила операций живут в `runtime.Operations`**, а не в самих значениях: обход
  дерева и правила сложения — разные задачи, и те же правила понадобятся свёртке
  констант, которая работает до всякого выполнения.

Где что проверяется:

| Что | Где |
|---|---|
| арифметика, сравнения, биты | `runtime/Operations.java` |
| истинность | `Value.isTruthy()` — одно место на весь язык |
| чтение и запись по ключу, границы | `runtime/Interpreter.java` |
| нормализация ключей объекта | `value/types/MapValue.java` |
| разбор литералов чисел | `parser/Parser.java` — один раз, при построении дерева |

## Как добавить тип значения

1. Новый класс в `ru.wds.wdl.value`, `permits` в `Value`, элемент в `ValueType`
   (с именем для `typeof` и русским названием для сообщений).
2. Собрать проект: компилятор перечислит все `switch`, которые надо дополнить, —
   это и есть список работ.
3. Если тип контейнерный, ветка в чтении и записи по ключу
   (`Interpreter.read` / `Interpreter.write`) сразу даёт ему обе формы обращения:
   и `.поле`, и `["поле"]`.
4. Тесты: печать, истинность, равенство, операции.

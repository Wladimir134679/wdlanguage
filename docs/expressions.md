# Выражения

Всё, что даёт значение: литералы, операции, обращение, вызов. Из чего состоит сам
скрипт — в [инструкциях](statements.md).

```bash
wdl examples/expressions.wdl          # выполнить шпаргалку по выражениям
wdl --ast examples/expressions.wdl    # показать дерево
wdl --repl                            # построчно, интерактивно
```

## Типы данных

| Тип | Литералы | Заметки |
|---|---|---|
| `null` | `null` | отсутствие значения, самостоятельный тип |
| логическое | `true`, `false` | не число: `true + 1` — ошибка |
| число | `42`, `1_000`, `3.14`, `6.02e23`, `0xFF`, `0b1010` | внутри целое (64 бита) или вещественное |
| строка | `"текст"`, `"с \n экранами"`, `"✓"` | неизменяемая |
| массив | `[1, 2, [3]]` | изменяемый, сравнивается по ссылке |
| объект | `{имя: "болт", "цена": 12}` | пары «ключ — значение», порядок записи сохраняется |
| функция | пока только встроенные: `println` | обычное значение в обычной переменной |
| диапазон | `1..5`, `0..n - 1` | границы включительны, неизменяем, сравнивается по значению |

Тип значения возвращает `typeof`, размер — `len` (см. [инструкции](statements.md)).

**Целое и вещественное — один тип для скрипта.** Разделение внутри нужно только затем,
чтобы `2 + 2` оставалось `4`, а счётчики и битовые маски не теряли младшие разряды.
Правило продвижения: пока оба операнда целые — результат целый; появилось вещественное —
считаем в `double`. Переполнение 64 бит тоже переводит результат в вещественное:
потерю точности видно, а заворот разрядов — нет.

**Истинность.** Ложны только `null` и `false`. Ноль, пустая строка и пустой массив
истинны — одно правило вместо списка исключений, и «значения нет» не путается
с «значение равно нулю».

## Приоритеты

От слабых к сильным. Все бинарные операции левоассоциативны, условное выражение —
правоассоциативно.

| Сила | Операции |
|---|---|
| 2 | `? :` |
| 4 | `\|\|` |
| 6 | `&&` |
| 8 | `==` `!=` |
| 10 | `<` `<=` `>` `>=` `is` `!is` `in` `!in` `has` `!has` |
| 12 | `\|` |
| 14 | `^` |
| 16 | `&` |
| 17 | `..` |
| 18 | `<<` `>>` `>>>` |
| 20 | `+` `-` |
| 22 | `*` `/` `%` |
| 26 | префиксные `-` `+` `!` `~` |
| 30 | обращение `.` `[]` |

Три отличия от привычного:

* **Побитовые операции сильнее сравнений**, в отличие от Си. `флаги & МАСКА == 0`
  считается так, как читается. В Си это классическая ловушка, повторять её незачем.
* **Унарный оператор слабее обращения, но сильнее умножения**: `-a.x` — это `-(a.x)`,
  а `-a * b` — это `(-a) * b`. Операнд разбирается не «одним примитивом», поэтому
  `!!флаг` и `- -x` тоже работают.
* **Диапазон сильнее сравнений и слабее арифметики.** Иначе `x in 1..5` разобралось
  бы как `(x in 1)..5`, а `0..n - 1` — как `(0..n) - 1`. Место 17 было свободно
  между `&` и `<<`: шаг 2 в таблице заводился ровно для этого.

Числа приоритетов заданы с шагом 2 — между соседними уровнями всегда есть место
для нового оператора без перенумерации.

## Семантика операций

**`+`** — три смысла в порядке проверки: числа складываются; если хоть один операнд
строка, получается конкатенация (`"итого: " + 5` → `"итого: 5"`); два массива дают
новый массив. Остальное — ошибка.

**`-` `*` `%`** — только числа. **`/`** — деление целых даёт целое, только если оно
точное: `6 / 3` → `2`, `7 / 2` → `3.5`. Округление вниз в динамическом языке —
источник тихих ошибок в расчётах; для целочисленного деления будет отдельная функция
с говорящим именем.

**Деление на ноль — ошибка**, в том числе вещественное. `inf` в середине расчёта
обнаруживается через десяток строк и уже без объяснения причины.

**`==` `!=`** — без приведения типов: `1 == "1"` ложно. Числа при этом сравниваются
по величине: `1 == 1.0` истинно. Массивы и объекты — по ссылке: два одинаковых
с виду массива всё-таки два разных массива.

**`<` `<=` `>` `>=`** — числа между собой и строки между собой. Строки сравниваются
по кодовым точкам: предсказуемо и не зависит от локали, а сортировка по правилам
конкретного языка — задача стандартной библиотеки.

**`&&` `||`** — ленивые и возвращают сам операнд, а не приведённое логическое:
`имя || "без имени"` подставляет значение по умолчанию, `настройки && настройки.цвет`
безопасно читает. Для условий разницы нет — они смотрят на истинность.

**`&` `|` `^` `~` `<<` `>>` `>>>`** — только целые. Вещественное здесь почти всегда
означает ошибку в расчётах выше, а тихое отбрасывание дробной части её прячет.

**`in` `has` и отрицания `!in` `!has` `!is`** — принадлежность. `x in a` спрашивает
у правого операнда, `a has x` — у левого; это одна и та же операция, записанная
с двух сторон:

```wdl
if (role in user.roles) grant()
if (user.roles has "admin") grant()
banned = text !in allowed
```

Искать можно в массиве (по значению), в строке (подстрока), в объекте (**по ключу**,
как и перебор) и в диапазоне (границы включительно). Всё прочее справа — ошибка.

**Зачем два имени.** Не ради синонима: в [`match`](control-flow.md#match) левый
операнд зафиксирован предметом, и фразу «предмет содержит `"admin"`» иначе не
записать. За обоими стоит одна реализация — та же, что за членами
`a.contains(x)`, `s.contains(sub)` и `obj.has(k)`; разведи их, и оператор
с методом однажды разойдутся.

**Отрицания — отдельные операции, а не `!` вокруг сравнения.** Прецедент уже стоит:
`!=` — это самостоятельная операция, а не отрицание `==`. Дерево честно отражает
текст, а `!x in list` перестаёт быть единственной записью (там `!` прилипает
к левому операнду и значение получается другое).

**`..`** — диапазон: `1..5`. Обе границы числа, обе включительны — так это
и читается, «от 1 до 5». Диапазон — полноценное значение
([одиннадцатый тип](types.md)), а не форма записи внутри `case`:

```wdl
workingAge = 18..65
if (age in workingAge) println("работает")
for (i in 1..5) println(i)
```

**`5..1` пуст, а не идёт вниз.** Довод железный: `for (i in 0..n - 1)` при `n == 0`
даёт `0..-1`, и это обязано быть нулём проходов, а не тихим проходом в обратную
сторону. Убывающий диапазон, когда понадобится, будет записан шагом, а не порядком
границ.

**Обращение `.` и `[]`** — одна операция, см. [единое обращение](access.md).

### Условное выражение

`условие ? одно : другое` — ветвление, у которого есть значение:

```wdl
знак = число > 0 ? "плюс" : "минус"
println("товаров: ", len(список) == 0 ? "нет" : len(список))
```

Вычисляется только выбранная ветвь, поэтому `делитель == 0 ? 0 : сумма / делитель`
безопасно. Условие смотрит на [истинность](types.md#истинность), а не на тип.

Правоассоциативно: `a ? b : c ? d : e` — это `a ? b : (c ? d : e)`, как и ожидает
любой, кто писал такие цепочки. От `if` отличается тем же, чем выражение от инструкции:
условное выражение даёт значение и вкладывается куда угодно, `if` — выполняет действие;
подробности в [ветвлениях и циклах](control-flow.md).

**Вызов `f(...)`** — связывает так же крепко, как обращение, и вызывает любое
выражение, дающее функцию: `f()()`, `точка.строкой()`, `обработчики[0](x)`.

## Ошибки

Ошибки разбора не прерывают работу: всё найденное копится в `Diagnostics`, а на месте
неразобранного выражения остаётся узел `ErrorExpr`. Дерево возвращается всегда — с ним
работают форматтер, подсветка и будущий LSP, которым битый файл дело обычное.
Интерпретатору такое дерево не отдают: перед выполнением проверяется `hasErrors()`.

Ошибки выполнения (`WdlRuntimeError`) несут интервал в скрипте и показываются тем же
способом, что и ошибки разбора — строкой исходника с подчёркиванием:

```
скрипт.wdl:1:1: ошибка: деление на ноль
  1 | 10 / (5 - 5)
    | ^^^^^^^^^^^
```

## Как это устроено

```
Source → Lexer → List<Token> → Parser → Program (AST) → Interpreter → выполнение
```

Три правила, которые здесь важнее остального:

1. **AST — только данные.** У узлов нет `eval()` и нет ссылки на окружение: это
   `record`'ы в `sealed` иерархии. Одно и то же дерево можно запускать одновременно
   в нескольких потоках с разными переменными, кэшировать между запусками и разбирать
   инструментами, которым до выполнения нет дела.
2. **Выполнение — посетитель.** `Interpreter implements ExprVisitor<Value, ExecutionContext>,
   StmtVisitor<Void, ExecutionContext>`. Тем же способом написаны дамп дерева и тестовый
   принтер — ни один узел ради них не менялся, потому что диспетчеризация собрана
   в одном месте: `visit(Expr, C)` и `visit(Stmt, C)`, где `switch` по `sealed` иерархии
   компилятор проверяет на полноту. Забыть ветку — ошибка сборки.
3. **Ноль изменяемой статики.** Всё состояние выполнения — в `ExecutionContext`,
   который интерпретатор получает аргументом. Сколько корневых окружений создано —
   столько независимых интерпретаторов живёт в одной JVM.

## Рецепты

### Добавить бинарный оператор

1. `TokenType` — лексема (лексер подхватит её из перечисления сам).
2. `BinaryOp` — операция и её символ.
3. `Operators` — одна строка в таблице: токен, операция, сила связывания.
4. `Operations` — что операция делает со значениями.
5. Тест в `ParserTest` на форму дерева и в `InterpreterTest` на результат.

Менять сам парсер не нужно: он читает таблицу.

### Добавить тип значения

1. Новый класс в `ru.wds.wdl.value`, `permits` в `Value`, элемент в `ValueType`.
2. Компилятор покажет все `switch`, которые нужно дополнить, — это и есть список работ.
3. Если тип контейнерный, ветка в `Interpreter.visitAccess` даст ему обе формы
   обращения сразу.

### Добавить вид узла

1. `record` в `ru.wds.wdl.ast`, `permits` в `Expr` (или в `Stmt`, если это инструкция).
2. Метод в `ExprVisitor` / `StmtVisitor` и ветка в его `visit` — дальше компилятор
   проведёт по всем посетителям: интерпретатору, дампу, тестовому принтеру.

### Добавить встроенную функцию

Одна запись в `Builtins.installTo`: имя, `Arity` (или `Signature`, если параметрам
нужны [имена](functions.md#именованные-аргументы)) и лямбда. Число аргументов
проверяется до вызова, поэтому тело начинается с дела. Всё, что функции нужно от среды
(вывод, а позже часы и способ вызвать другую функцию), приходит в `CallContext`.

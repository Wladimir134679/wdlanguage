# Документация wdl

Здесь описан сам язык: что он такое, из чего состоит и почему устроен так, а не иначе.
Обоснования важны не меньше правил — язык ещё растёт, и через полгода нужно будет
понимать, какое решение можно менять, а какое держит на себе остальные.

## Оглавление

| Документ | О чём |
|---|---|
| [Идея языка](overview.md) | зачем wdl нужен, что обещает автору скрипта и приложению, как устроен конвейер |
| [Типы данных](types.md) | семь типов, их правила и внутреннее устройство, истинность, равенство, печать |
| [Выражения](expressions.md) | приоритеты, семантика операций, рецепты «как добавить оператор / тип / узел» |
| [Инструкции](statements.md) | присваивание, вызов, встроенные функции, вывод, границы инструкций |
| [Ветвления и циклы](control-flow.md) | `if`, `while`, `for`, перебор `for ... in`, `break`/`continue`, области видимости |
| [Единое обращение](access.md) | почему `a.b` и `a["b"]` — одна операция, и что из этого следует |

Черновые заметки автора о том, каким язык хочется видеть, лежат отдельно —
в `Основные идеи.md` в корне репозитория. Это источник желаний, а не описание
реализованного: то, что уже работает, описано здесь.

## С чего начать

Читать по порядку: [идея](overview.md) → [типы](types.md) → [выражения](expressions.md)
→ [инструкции](statements.md) → [ветвления и циклы](control-flow.md). Документ
про [обращение](access.md) — отдельно, потому что это решение уровня языка,
а не деталь синтаксиса.

Пощупать руками:

```bash
./gradlew :wdl-cli:installDist              # → wdl-cli/build/install/wdl/bin/wdl

wdl examples/hello.wdl                      # программа: переменные и вывод
wdl examples/expressions.wdl                # шпаргалка по выражениям
wdl examples/control-flow.wdl               # ветвления и циклы
wdl --ast examples/hello.wdl                # дерево программы
wdl --tokens examples/lexer-check.wdl       # поток токенов
./gradlew :wdl-cli:repl --console=plain     # построчно, интерактивно
```

## Как вести эти документы дальше

* **Один документ — одна тема.** Новая крупная возможность (функции, классы, модули)
  получает свой файл и строку в этой таблице.
* **Записывать не только правило, но и причину.** «Деление на ноль — ошибка» стоит
  дёшево; ценно то, почему не `inf`.
* **Примеры должны выполняться.** Всё, что приведено в документах, проверено запуском;
  при изменении поведения примеры и тексты ошибок обновляются вместе с кодом.
* **Состояние языка — в одном месте.** Что уже работает и чего ещё нет, написано
  в [идее языка](overview.md#что-уже-работает) и в корневом `README.md`; в остальных
  документах этого дублировать не нужно.

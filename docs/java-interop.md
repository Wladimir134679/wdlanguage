# Мост в Java

> Приложение отдаёт скрипту **чужой класс** — и скрипт создаёт его экземпляры, зовёт
> методы, читает поля. Или отдаёт **готовый объект** — и скрипт работает с ним так же,
> не зная, что за обёрткой чужой `LocalDate` или `Connection`.

Живёт это в отдельном модуле `wdl-bridge`, а не в ядре: ядро не знает слова
«рефлексия» и знать не должно — открывать чужие типы это политика приложения,
а не свойство языка.

Все примеры ниже покрыты тестами (`wdl-bridge/src/test/.../JavaBridgeTest.java`) —
они не иллюстрация, а то, что действительно выполняется.

## Граница: построитель или мост

Класс от приложения один — [`NativeClass`](embedding.md#класс). Различаются
не классы, а **откуда у класса члены**:

| откуда члены | чем описывается | когда |
|---|---|---|
| лямбдами | `NativeClass.named(...).method(...)` | класс свой целиком: имена точные, опечатку ловит компилятор |
| рефлексией, весь тип | `JavaBridge.open().expose(...)` | класс чужой: приложение его не писало и переписывать не будет |
| рефлексией, часть членов | `.members(FromJava.of(...))` | класс свой, но половина его методов уже написана в чужом типе |

Третья строка — не третий вид класса, а смесь первых двух в одном объявлении:
конструктор и обработчики лямбдами, остальное от типа. Ей посвящён
[раздел ниже](#свои-обёртки-над-чужим-типом).

## Открыть тип

```java
JavaBridge bridge = JavaBridge.open()
        .expose(LocalDate.class, "Date")     // всё public под именем Date
        .expose(Counter.class)               // под своим именем: Counter
        .build();

bridge.installTo(scope);
```

```wdl
d = Date.of(2026, 8, 29)
println(d)                      // 2026-08-29 — печать это toString() объекта
println(d.plusDays(3))          // 2026-09-01
println(d is Date)              // true

c = new Counter("счёт", 1)      // конструктор Java
println(c.getValue())           // 1
println(c.name)                 // счёт — публичное поле Java
println(Counter.LIMIT)          // 10 — константа класса
```

Для языка это обычный класс и обычный объект: `typeof` даёт `object`, `is` отвечает,
члены ищутся тем же путём, что у всех. Нового типа значения мост не заводит — и
нового вида класса тоже: **тип, открытый мостом, это тот же `NativeClass`**, что
и класс от приложения, только члены ему пришли не лямбдами, а рефлексией. Видов
класса в языке ровно два — написанный на wdl и пришедший от приложения.

## Отдать готовый объект

```java
scope.define("now", bridge.wrap(Instant.now()));
```

Это половина смысла моста: библиотека вернула соединение, момент времени, результат
запроса — и это надо отдать скрипту, не описывая руками. Строки, числа и коллекции
переводятся, остальное оборачивается.

**Открытый тип служит шаблоном обёртки.** Объект почти никогда не того класса,
который открывали: открыли `Connection`, а пришёл `JdbcConnection`. Обёртка ищется
по самому близкому из открытых типов, которому объект принадлежит, — поэтому схема,
написанная для интерфейса, работает для всех его реализаций.

## Что именно видно: `FromJava`

```java
FromJava.of(Counter.class)
        .method("getValue")                 // видно только это
        .methodAs("значение", "getValue")   // и под другим именем
        .bean("value")                      // getValue/setValue → свойство .value
        .readOnly("value")                  // но только для чтения
        .noConstructors()                   // new запрещён
        .factory("from")                    // Counter.from(3) — статический метод
```

```wdl
c = new Counter("s", 1)
println(c.getValue())       // 1
println(c.getAndIncrement)  // null — схема этого не открывала
```

Описание проверяется **при сборке моста**: метода с таким именем нет, поле не существует,
у пары аксессоров нет геттера, фабрика указывает в пустоту, `readOnly` названо
для несуществующего имени — исключение при старте приложения:

```
класс 'Counter': у типа ru.wds.App$Counter нет метода 'getVlaue'
```

Момент выбран не случайно: промах по члену у объекта — это `null`, а не ошибка
(правило языка), поэтому опечатка в описании без такой проверки доживала бы
до автора скрипта и выглядела бы там пропажей метода. То же обещание и тот же
момент, что у `NativeClass` с требованиями трейта.

`FromJava.of(type).all()` — «всё public»; `FromJava.everythingOf(type)` — то же
самое одной строкой. Имя в скрипте задаёт `.as("Date")`.

**Словарь один и тот же в обеих ролях.** Те же слова описывают и класс, открытый
мостом целиком, и половину членов своего класса (следующий раздел). Раньше словарей
было два — `JavaSchema` для моста и `FromJava` для источника членов — с одинаковыми
словами, одинаковыми полями и дословно повторённой проверкой. Вопрос-то один:
**что видно у этого типа**; кто соберёт класс, на ответ не влияет.

## Свои обёртки над чужим типом

`Button` в `sys.gui` — класс свой: у него свой конструктор, своё состояние
(`JButton` в `NativeInstance.state()`) и `onClick`, которого у Swing нет и быть
не может — он зовёт функцию скрипта. Мост целиком тут не годится: `new JButton()`
скрипту отдавать незачем, а половина методов Swing ему не нужна. Но текст, доступность
и `doClick()` — ровно те же, что у `JButton`, и лямбдами они писались по четыре
строки каждая.

```java
NativeClass.named("Button")
        .backing(JButton.class)                     // что лежит в state()
        .init(Params.of()                           // аргументы создания без полей
                .optional("text", "")
                .optional("enabled", true),
                (self, ctx, args, span) -> {
                    self.state(new JButton(args.string(0, "текст")));
                    return NullValue.NULL;
                })
        .members(FromJava.of(JButton.class)
                .bean("text")                       // свойство .text
                .bean("enabled")
                .method("doClick"))
        .method("onClick", ..., (self, ctx, args, span) -> ...)
        .build();
```

Член, взятый отсюда, работает с объектом из `state()` — тем самым, который положил
туда `init`. Переименование по дороге умеет и он: в Swing флажок «выбран» зовётся
`selected`, в скрипте — `checked`, и это `beanAs("checked", "selected")`,
а не переходник лямбдой.

**Одно имя — один член.** `setText`/`getText` рядом со свойством `.text` не открываются:
это было бы четыре имени на два действия, а правило «свойство или метод — по признаку
„устареет ли ответ“» ([members.md](members.md)) нарушалось бы прямо в стандартной
библиотеке. Метод остаётся там, где парой аксессоров не обойтись: `setSize(w, h)`
меняет два значения сразу, и свойства для этого нет.

**Параметр без поля.** Значение, которое живёт в чужом объекте, полем держать нельзя:
оно устареет к следующему обращению, а запись в него не дойдёт до объекта. Поэтому
пара такая: параметр объявляет аргумент создания и **не** заводит поля, а значение
за тем же именем отдаёт свойство. Значение по умолчанию при этом объявляется
**один раз** — в заголовке; `init` получает уже дополненный список аргументов
и дописывать дефолт своими руками не должен. Список параметров стоит рядом с телом
(`.init(Params.of().optional(...)..., тело)`) или собирается по одному
(`.param(имя, значение)`) — это два вида одной записи, и у обёртки, где полей нет вовсе,
первый читается лучше: имя параметра стоит первым, а дефолт пишется литералом.

**Состояние объявляется.** `.backing(JButton.class)` говорит, что экземпляры держат
в `state()`. Это не формальность: по нему `FromJava` сверяется **при сборке класса**,
`is` отвечает по живой иерархии Java, а `state(Class)` перестаёт быть слепым
приведением.

**Проверяется при сборке класса.** Нет метода, нет пары аксессоров, нет поля,
состояние не того типа — исключение при старте приложения:

```
класс 'Button': у типа javax.swing.JButton нет метода 'doClickk'
класс 'TextArea' держит в состоянии javax.swing.JScrollPane, а члены взяты
у javax.swing.JTextArea: объявите backing(JTextArea.class) либо достаньте нужный
объект через via(...)
```

**Состояние — не тот объект.** `TextArea` держит `JScrollPane`, а члены нужны
у `JTextArea` внутри него. Это `.via(...)`:

```java
.backing(JScrollPane.class)
.members(FromJava.of(JTextArea.class)
        .via(state -> ((JScrollPane) state).getViewport().getView())
        .bean("text")
        .method("append"))
```

**Чего он не делает.** Не создаёт объект — это дело `init`; не наследует за вас
иерархию.

## Правила, по которым Java превращается в язык

### Поле Java — это свойство, а не поле

У обёртки нет ни одного собственного поля: `c.name` — свойство над Java-полем.
Причина — [правило про члены](members.md): значение живёт в Java-объекте и меняется
за спиной скрипта, а поле, записанное однажды, к следующему обращению устареет.
Запись в `final` даёт «только для чтения» — тем же сообщением, что у свойства на wdl.

### Метод без аргументов остаётся методом

`getValue()` — метод, а не свойство `.value`. Автоматическое правило «начинается
на `get`» превратило бы в свойство и `getAndIncrement()`, а свойство обещает, что
за именем ничего не происходит. Поэтому свойством пара аксессоров становится
только по просьбе — `.bean("value")`.

### Перегрузки выбираются по стоимости приведения

У Java под одним именем живёт набор методов, у языка — один. Выбирается тот,
чьи аргументы приводятся дешевле всего: точное совпадение бесплатно, приведение
стоит тем дороже, чем дальше уводит от написанного, `Object` дороже всего.
`take(5)` при выборе между `take(long)`, `take(int)` и `take(Object)` уходит в первый.

**Ничья — это отказ.** Два одинаково подходящих метода означают, что вопрос задан
неоднозначно, и выбрать за автора скрипта нечем:

```
Overloaded.tie(): подходит несколько методов Java — tie(int, Object), tie(Object, int);
                  уточните типы аргументов
```

### Сужение числа не проходит молча

Число, не влезшее в `int`, — ошибка `ValueError`, а не тихо усечённое значение.
Язык держит один тип `number` затем, чтобы автор скрипта не думал про размер
машинного слова; молчаливое усечение вернуло бы ему эту заботу неверным результатом
без единого сообщения. Дробное в целое проходит, только если дроби нет: `n / 2`
даёт дробное даже там, где результат целый, и запрет ломал бы это на ровном месте.

### Коллекции копируются

Список языка становится Java-списком копией, и наоборот. Иначе скрипт правил бы
коллекцию приложения из своего потока — молча, в обход всякой синхронизации.

### `enum` — это строка

В обе стороны и по имени константы: `d.dayOfWeek == "MONDAY"` работает, а метод,
принимающий `DayOfWeek`, зовётся строкой. Обёртка вокруг константы дала бы её методы,
но отняла бы сравнение, печать и запись в файл — а этим пользуются на порядок чаще.

### Функция скрипта — это обработчик Java

Там, где Java просит интерфейс с одним методом:

```wdl
h = new Handlers()
println(h.sorted([1, 3, 2], def (a, b) => b - a))   // [3, 2, 1] — Comparator
h.repeat(2, def () => println("тик"))               // Runnable
h.keep(def () => println("из потока"))              // и живёт дольше вызова
```

Отдельного механизма для «живёт дольше вызова» не понадобилось: функция несёт свой
запуск с собой, а вход снаружи ядро считает и проверяет само ([потоки](threads.md)).
Поэтому вызов из чужого потока работает, а вызов после закрытия запуска отвечает
ошибкой. Обещание языка про время при этом не меняется: одно обращение атомарно,
выражение целиком — нет.

Интерфейс с двумя абстрактными методами одной функцией не закрыть: непонятно, какой
из них звать, а догадка в этом месте молча уходит не в тот метод.

### `is` спрашивает у самой Java

```wdl
println(d is Date)          // true
println(d is Comparable)    // true — интерфейс, открытый как трейт
```

Отвечает `isAssignableFrom` по живой иерархии, а не перебор того, что собрал мост.
Поэтому ответ верен и для предков, которых никто не открывал, и мосту не нужно
повторять у себя то, что Java знает про себя сама.

### Исключение Java — это `JavaException`

```wdl
try {
    c.fail()
} catch (e) {
    println("поймали")
}
```

Класс ошибки — `JavaException`, и он намеренно **не** под `RuntimeError`: ошибся
не движок, а код, который положило в область видимости приложение, и
`catch (e is RuntimeError)` не должен ловить чужой `NullPointerException` заодно
с делением на ноль. Исходное исключение сохраняется целиком — приложению оно нужно
в логе.

## Что закрыто

По умолчанию мост открывает **только то, что открыли явно**. Причина в том, что
открытый целиком мост — это дыра длиной в две строки: `obj.getClass().getClassLoader()`.

* **`getClass`, `wait`, `notify`, `notifyAll` не видны никогда.** Это не настройка
  и политикой не открывается;
* **чёрный список типов** — `Class`, `ClassLoader`, `System`, `Runtime`,
  `ProcessBuilder`, `Thread`, всё из `java.lang.reflect` и `java.lang.invoke`.
  Проверяется и при `expose`, и при попытке обернуть возвращённый объект: запрет,
  который обходится возвратом из метода, — не запрет;
* **только `public` члены `public` классов.** `setAccessible` не зовётся, поэтому
  `--add-opens` приложению не нужен;
* **неизвестный тип — отказ с подсказкой**, а не молчаливая обёртка:

```
нечем представить в языке объект типа ru.wds.App: откройте этот тип мосту
(JavaBridge.expose) или разрешите обёртки (JavaPolicy.wrapUnknown)
```

Приложение, открывшее `Connection`, редко имеет в виду «и всё, до чего от него можно
дойти». `JavaPolicy.builder().wrapUnknown(true)` включает обратное поведение одной
строкой — это удобно в инструментах и на отладке.

> **`wrapUnknown` — режим для доверенных скриптов, и это надо сказать прямо.**
> Открытым в нём становится всё, до чего дотягиваются методы открытых типов, а держит
> оборону один чёрный список — то есть перечень известного плохого. Такой список
> заведомо неполон: от безобидного объекта до чего-нибудь интересного обычно три-четыре
> вызова, и заранее их все не перечислить. Скрипту, который пишет не автор приложения,
> оставляйте `strict` и открывайте типы поимённо.

* **писать в статику Java-класса нельзя.** Класс собирается на запуск, а статическое
  поле Java общее на процесс: запись из скрипта меняла бы состояние всего приложения,
  и делала бы это молча, под видом обычного присваивания. По той же причине
  в `statics` попадают только `static final` поля — снимок с изменяемого устарел бы
  к следующему обращению.

## Доступ по имени: `sys.java`

```java
NativeModules natives = NativeModules.of(Map.of("sys/java", bridge::lookupModule));
JavaPolicy.builder().allowLookup("java.time").build();
```

```wdl
import sys.java as java
Date = java.type("java.time.LocalDate")
println(Date.of(2026, 8, 29))
```

**Нигде не зарегистрирован по умолчанию и без `allowLookup` отвечает отказом.**
Доступ по имени нужен инструментам — REPL, отладке, генератору, — а обычному скрипту
почти никогда: ему тип открывает приложение, зная зачем. В стандартную библиотеку
это не попало намеренно: `sys.io` есть у всех, а список доступных из скрипта
Java-пакетов — решение конкретного приложения, и его нельзя принять один раз за всех.

## Чего мост не делает

* **скрипт не наследуется от Java-класса.** Ровно по той же причине, по какой
  не наследуется от `NativeClass`: плоскую таблицу методов по Java-иерархии
  не собрать. Композиция закрывает этот случай лучше;
* **класс на wdl не реализует Java-интерфейс.** Технически это `Proxy` наизнанку
  и делается тем же способом, что обработчики; появится, когда будет кому отдавать
  такие объекты **в** Java;
* **промах по члену не ошибка, а `null`.** Это правило языка для объектов
  («ключ, положенный руками, значит больше встроенного имени»), и мост его
  не нарушает: `c.getAndIncrement` у закрытого схемой метода даёт `null`, как дало бы
  обращение к несуществующему ключу.

### Библиотека остаётся на языке движка

Java-класс, открытый мостом, вправе бросать ошибки языка — с классом, который скрипт
ловит, и с текстом, написанным для автора скрипта:

```java
public long nextInt(long limit) {
    if (limit <= 0) {
        throw new WdlRuntimeError(ErrorKind.VALUE, Span.NONE,
                "Random.int(): граница: ожидалось положительное число, а здесь " + limit);
    }
    ...
}
```

```wdl
try {
    r.int(0)
} catch (e is ValueError) {
    println(e.message)   // Random.int(): граница: ожидалось положительное число, а здесь 0
}
```

`Span.NONE` здесь не заглушка: библиотека знает, **что** не так, но не знает, на какой
строке скрипта это случилось, — место проставит граница вызова (`runtime.Foreign`).
Поэтому переписанный на обычный Java-класс `Random` не потерял ни одного сообщения.

**А чего библиотека не написала — скажет мост.** Аргумент не того типа он объясняет
сам, и при единственной перегрузке — поимённо:

```
Random.pick(): аргумент 1: ожидался массив, а здесь число (5)
Random.int(): аргумент 1: ожидалось целое число, а здесь 1.5
```

### Значения языка просят типом

Библиотеке, которой нужен массив языка целиком — без копии и без перевода
элементов, — достаточно объявить параметр:

```java
public Value pick(ArrayValue items) { ... }
```

Мост отдаёт такой аргумент как есть: `Value` и его виды он не переводит, а передаёт.
Так же принимается `MapValue`, `FunctionValue` и любое другое значение — это путь
для случаев, когда библиотека работает с языком, а не с Java-типами.

## Цена

Описание типа (`JavaShape`) — рефлексия с `MethodHandle` на каждый член — считается
один раз на процесс и кэшируется: результат от запуска не зависит. А сам класс
собирается **на запуск** — по той же причине, по которой его собирает на запуск
любой модуль: `statics` принадлежат классу, и общий на процесс класс переносил бы
состояние одного скрипта в другой.

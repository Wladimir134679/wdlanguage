# Функции

Функция в wdl — не особая сущность, а [обычное значение](types.md#функция) в обычной
переменной. Всё остальное следствия: её можно передать аргументом, вернуть из другой
функции, положить в массив и в поле объекта. Готовый пример целиком —
[`examples/functions.wdl`](../examples/functions.wdl).

```wdl
def сумма(a, b) {
    return a + b;
}
println(сумма(2, 3))        // 5
```

## Четыре формы записи, одно и то же дерево

```wdl
def сумма(a, b) { return a + b; }       // блок
def сумма(a, b) return a + b;           // одна инструкция
def сумма(a, b)
    return a + b;                       // то же самое: перенос строки ничего не значит
def сумма(a, b) => a + b                // тело-выражение
```

`=>` — это `return`, записанный короче, и в дереве он им и становится. Разница только
в том, что стрелке не нужна ни точка с запятой, ни слово `return`, поэтому короткие
функции пишутся в одну строку без служебного шума.

Форма записи сохраняется в дереве (`BodyStyle`) — не ради выполнения, а ради форматтера:
он обязан вернуть стрелку туда, где была стрелка. Тот же мотив, что у
[единого обращения](access.md), где `a.b` и `a["b"]` — один узел с пометкой о форме.

Тело без фигурных скобок — одна инструкция, и своей области видимости оно не создаёт,
как и [тело `if` без скобок](control-flow.md#блок-создаёт-область-видимости). Разницы
для функции это не делает: локальные переменные всё равно живут в области вызова.

### После `=>` фигурная скобка — это объект

```wdl
def точка(x, y) => {x: x, y: y}         // возвращает объект
def точка(x, y) { return {x: x}; }      // блок, внутри которого return объекта
```

Отдельного правила для этого не понадобилось: `{` в начале инструкции — всегда блок,
в позиции выражения — всегда [литерал объекта](types.md#объект). После `=>` ждут
выражение, значит объект.

## Анонимные функции

```wdl
удвоить = def(x) => x * 2
println(удвоить(21))                    // 42

операции = {
    плюс: def(a, b) => a + b,
    минус: def(a, b) => a - b
}
println(операции.плюс(10, 4))           // 14
```

`def имя(...)` и `def(...)` — один и тот же узел дерева; объявление отличается тем,
что ещё и **заводит** имя. Разница видна там, где одноимённая переменная есть снаружи:
объявление создаёт своё имя в текущей области, а присваивание `имя = def(...)` ищет
существующее имя наружу и меняет его.

Анонимная функция, которой присваивают переменную, забирает её имя себе — только
для сообщений об ошибках: `функция 'удвоить' принимает ровно 1 аргумент` понятнее,
чем то же про `def`.

## Значения по умолчанию

```wdl
def greet(name, greeting = "привет") => greeting + ", " + name
println(greet("мир"))                   // привет, мир
println(greet("мир", "здравствуй"))     // здравствуй, мир
```

**Значение по умолчанию вычисляется на каждом вызове, а не один раз при объявлении.**
Это то место, где wdl расходится с Python, и расходится намеренно: там значение
считается в момент `def` и живёт с функцией, отчего общий изменяемый список копит
значения между вызовами — самая известная ловушка языка. Массивы и объекты здесь тоже
изменяемые, так что модель «посчитать один раз» принесла бы ту же ловушку слово в слово:

```wdl
def box(value, holder = {}) {
    holder.value = value
    return holder;
}
println(box(1).value, " ", box(2).value)    // 1 2: свой объект на каждый вызов
```

Из этого же следует, что по умолчанию стоит **выражение**, а не литерал: в нём можно
позвать функцию, и позовут её тогда, когда значение понадобилось, — если аргумент
передали, выражение не вычисляется вовсе.

```wdl
def now() => "2026-08-08"
def log(message, at = now()) => println(at, ": ", message)
log("старт")                                // 2026-08-08: старт
```

**Значение по умолчанию видит параметры слева от себя** — оно и вычисляется в области
вызова, уже после того, как связаны предыдущие:

```wdl
def total(price, count = 1, tax = price * count * 0.2) => price * count + tax
println(total(100), " ", total(100, 2), " ", total(100, 2, 0))  // 120.0 240.0 200
```

Справа — нельзя, и это ошибка разбора, а не выполнения:

```
скрипт.wdl:1:11: ошибка: значение по умолчанию параметра 'a' ссылается на параметр 'b',
который связывается позже
  1 | def f(a = b, b = 1) => a
    |           ^
```

Иначе к моменту вычисления `a` имени `b` в области вызова ещё нет, поиск ушёл бы наружу
и мог бы подобрать одноимённую глобальную переменную — молча и не то. Язык таких подмен
не делает нигде: та же причина, по которой [`return` требует `;`](#return). Имя внутри
вложенной функции при этом своё и претензий не вызывает — `def f(a = def(b) => b, b = 1)`
законно.

**После параметра со значением по умолчанию все остальные тоже обязаны его иметь.**
Причина не эстетическая: позиционный вызов должен читаться по префиксу списка
параметров. При `def f(a = 1, b)` вызов `f(1)` — либо ошибка, либо тихая догадка,
куда пошла единица; ни того, ни другого язык не делает.

```
скрипт.wdl:1:18: ошибка: параметр 'c' без значения по умолчанию не может идти
после параметра со значением по умолчанию
  1 | def f(a, b = 10, c) => a
    |                  ^
```

Проверка вызова осталась ровно там, где была, и просто стала диапазоном:

```
скрипт.wdl:2:1: ошибка: функция 'greet' принимает от 1 до 2 аргументов, а передано 3
```

Ошибка внутри самого выражения по умолчанию указывает на объявление, а не на строку
вызова: стека вызовов скрипта в сообщениях пока нет — он появится вместе с лимитами.

## Именованные аргументы

```wdl
def greet(name, greeting = "привет", punct = "!") => greeting + ", " + name + punct

println(greet("мир"))                                   // привет, мир!
println(greet("мир", punct: "?"))                       // привет, мир?
println(greet(greeting: "здравствуй", name: "мир"))     // здравствуй, мир!
```

Ради второй строки всё и затевалось: **пропуск в середине списка** раньше записать
было нечем. Готовый пример целиком — [`examples/named-args.wdl`](../examples/named-args.wdl).

Двоеточие, а не `=`, и причина та же, по которой [`if (x = 5)`](control-flow.md)
не разбирается в принципе: присваивание в языке — инструкция, и `=` внутри выражения
не значит ничего. Форма `имя: значение` уже занята ключом [объекта](types.md#объект),
и здесь она означает ровно то же самое. Разбор при этом однозначен на два токена
вперёд — выражение никогда не начинается с имени с двоеточием следом, поэтому
`f(a ? b : c)` и `f(a: b)` не спорят.

**Позиционные аргументы идут только до первого именованного.**

```
скрипт.wdl:1:23: ошибка: после именованного аргумента 'greeting' позиционный
аргумент не имеет позиции. Укажите имя
  1 | greet(greeting: "эй", "мир")
    |                       ^^^^^
```

Позиция аргумента и есть его номер; после того как порядок нарушен, «третий по счёту»
не значит ничего. Правило объясняется одной фразой, и это дороже возможной свободы:
там, где позиционные разрешены и после именованных, читателю приходится держать
в голове, какие позиции ещё свободны.

**Значения по умолчанию считаются как обычно** — при вызове и
[видя параметры левее себя](#значения-по-умолчанию). Пропуск в середине этого
не меняет: `total(100, tax: 0)` сначала посчитает `count`, а `tax` возьмёт переданный.

**Аргументы вычисляются в порядке записи**, а не в порядке параметров: побочные
эффекты идут так, как читается строка.

```wdl
def mark(what) { print(what, " "); return what; }
def join(a, b) => a + b
println(join(b: mark("b"), a: mark("a")))    // b a ab
```

Работает это везде, где в скобках стоит список аргументов: у обычного вызова, у метода,
у создания экземпляра и у [заголовка родителя](classes.md#наследование).

### Имена есть не у всех функций

Чтобы разложить имена по позициям, имена параметров нужны у **любой** функции,
включая встроенные, — иначе своя и встроенная функция перестали бы быть одинаковыми
значениями, а на этом равенстве держатся [вызов](statements.md#вызов) и функции
высшего порядка. Поэтому контракт вызова есть у каждого значения-функции, и имена
в нём либо объявлены, либо честно отсутствуют:

```
скрипт.wdl:1:13: ошибка: функция 'len' принимает аргументы только по позиции:
имена параметров не объявлены
  1 | println(len(value: [1, 2]))
    |             ^^^^^^^^^^^^
```

У `println` имён нет и быть не может — он принимает сколько угодно аргументов.
Функции и классы, написанные на wdl, получают имена из своего заголовка; из встроенных
их объявили те, где имена дают больше всего, — модуль [`sys.gui`](gui.md)
(`grid(rows: 2, cols: 3)`, `alert("текст", title: "Ошибка")`). Как объявить имена
у своей встроенной функции — в [встраивании](embedding.md).

### Ошибки

```
функция 'greet' не принимает параметра 'greetng'
параметр 'name' функции 'greet' уже задан позиционно
обязательный параметр 'name' функции 'greet' не передан
аргумент 'name' указан дважды
```

Первые три — ошибки выполнения: какие имена у параметров, известно только от значения
слева от скобок, а вычисляется оно при выполнении. Последняя — ошибка разбора: оба
вхождения видны прямо в тексте вызова, ждать выполнения незачем.

## Вариативные параметры и раскрытие

Готовый пример целиком — [examples/variadic-args.wdl](../examples/variadic-args.wdl).

Когда функция заранее не знает число аргументов, она может собрать позиционный хвост
в массив, а неизвестные имена — в объект:

```wdl
def inspect(a, b = 10, *args, **named) {
    println(a)
    println(b)
    println(args)
    println(named)
}

inspect(1, 2, 3, 4, mode: "fast")
// a == 1
// b == 2
// args == [3, 4]
// named == {mode: "fast"}
```

`*args` и `**named` — не особые значения. Внутри функции это обычные свежие контейнеры:
массив и объект соответственно. Если остатка нет, они равны `[]` и `{}`. Структура
контейнера своя у каждого вызова; вложенные изменяемые значения, как и любые аргументы,
передаются без глубокого копирования.

### Порядок параметров

Полная форма заголовка всегда записывается в одном порядке:

```wdl
def f(required, optional = 10, *args, **named) {}
```

Сначала идут обычные параметры, затем не более одного позиционного rest и не более
одного именованного. `**named` всегда последний. У rest-параметра нет значения по
умолчанию: пустой остаток и есть его естественный дефолт.

Обычные параметры после `*args` не разрешены. Они потребовали бы отдельного понятия
«только именованный параметр», а для прозрачного проброса аргументов оно не нужно.
Такой механизм можно добавить позже без изменения этой формы.

```wdl
def good(a, b = 10, *args, **named) {}

def bad(*args, value) {}          // ошибка: обычный параметр после rest
def bad(**named, *args) {}        // ошибка: позиционный rest после именованного
def bad(*args = []) {}            // ошибка: rest не имеет значения по умолчанию
```

Все имена заголовка уникальны, включая имена rest-параметров.
Имя rest — локальная переменная, а не публичное имя одного параметра:
`good(args: value)` не задаёт `*args` целиком. Если есть `**named`, такое неизвестное
имя попадёт в него; без `**named` вызов завершится ошибкой неизвестного параметра.

### Что именно попадает в остаток

Позиционные значения сначала занимают обычные параметры слева направо. Только лишний
хвост попадает в `*args`:

```wdl
def collect(a, b = 10, *args) => args

collect(1)                 // []: b получит 10
collect(1, 2)              // []
collect(1, 2, 3, 4)        // [3, 4]
```

Известное имя всегда связывается с обычным параметром. В `**named` попадают только
имена, которых в заголовке функции нет:

```wdl
def open(path, mode = "read", **options) => options

open("data.txt", mode: "write", encoding: "utf-8")
// mode == "write"
// options == {encoding: "utf-8"}
```

Без соответствующего rest лишнее позиционное значение и неизвестное имя остаются
ошибками — функция не начинает молча принимать всё только из-за появления нового
синтаксиса.

### Раскрытие массива и объекта

Обратная операция раскрывает готовый контейнер в аргументы следующего вызова:

```wdl
def target(a, b, defC = 10) => println(a, " ", b, " ", defC)

values = [1, 2]
options = {defC: 3}

target(*values)                    // target(1, 2)
target(*values, **options)         // target(1, 2, defC: 3)
```

`*expression` принимает только массив и раскрывает его элементы позиционно.
`**expression` принимает только объект, у которого каждый ключ — строка, и раскрывает
пары по именам. Строка не считается массивом символов, а экземпляр класса — объектом
настроек: неявных вариантов раскрытия нет. Форма ключа при этом не проверяется —
совпавший с параметром сверяется с заголовком, а не совпавший уходит в `**named`,
где он обычный ключ объекта.

Выражение справа от `*` или `**` вычисляется ровно один раз. При раскрытии снимается
поверхностный снимок структуры контейнера, поэтому последующее добавление его элементов
не меняет уже начатый вызов.

Можно раскрыть несколько контейнеров:

```wdl
def collectAll(*args, **named) => [args, named]

collectAll(0, *left, *right, mode: "fast", **defaults, **options)
```

Но порядок остаётся тем же, что у обычных аргументов: позиционная группа — обычные
значения и `*array` — целиком идёт перед именованной группой — `name: value` и
`**object`.

```wdl
collectAll(1, *values, mode: "fast", **{trace: true})    // допустимо
collectAll(mode: "fast", *values)                        // ошибка разбора
collectAll(**options, 1)                                  // ошибка разбора
```

### Коллизии не перезаписывают значения

Одна позиция или одно имя могут получить значение только один раз независимо от формы
записи:

```wdl
def target(a, b, defC = 10) {}

target(1, a: 2)                    // a задан позиционно и по имени
target(*[1, 2], **{a: 3})          // та же коллизия после раскрытия
target(a: 1, **{a: 2})             // явное имя пересеклось с объектом
target(**left, **right)             // ошибка, если объекты имеют общий ключ
```

Правила «последний победил» нет: оно прятало бы опечатки и делало результат зависимым
от порядка объединения объектов.

Сначала обнаруживается дубликат уже назначенного параметра, затем проверяется наличие
обязательных. Поэтому `target(*[1], **{a: 2})` прежде сообщает коллизию `a`; после её
исправления сообщит, что не передан `b`.

Знак здесь тот же, что и в [распаковке](statements.md#распаковка-x-y--point),
и это не совпадение: `*` значит «по позициям», `**` — «по именам», и зеркалятся они
одинаково. Справа от `=`, как и в вызове, звёздочка **раскрывает** источник;
слева, как и в заголовке функции, `*rest` **собирает остаток**.

```wdl
def f(*args, **named) { }       // заголовок: собрать
f(*values, **options)           // вызов: раскрыть
x, y, *rest = *values           // распаковка: раскрыть справа, собрать слева
```

### Прозрачный проброс

Оба механизма вместе позволяют обёртке передать вызов дальше, не зная его сигнатуру:

```wdl
def proxy(fun, *args, **named) => fun(*args, **named)

proxy(target, *[1, 2], **{defC: 3})       // target(1, 2, defC: 3)
```

Значения по умолчанию при этом не упаковываются и не вычисляются в обёртке. Факт
отсутствия доходит до конечной функции, и только она вычисляет свой дефолт — на каждом
вызове и в своей области, как описано [выше](#значения-по-умолчанию).

Все выражения аргументов выполняются в порядке записи до раскладки по параметрам.
Это распространяется и на раскрытие: выражение контейнера занимает ровно своё место
в последовательности побочных эффектов.

## `_` как параметр

Параметр-дырка: позицию занимает, имени не имеет, телу не виден.

```wdl
def onClick(_, event) => "нажали: " + event
onClick("кнопка", "click")
```

Нужен там, где сигнатуру диктует не автор: обработчик события, декоратор, обратный
вызов чужой библиотеки. Придумывать таким параметрам имена вроде `unused` — значит
писать в коде неправду: имя есть, а значения за ним нет.

Дырок в заголовке бывает сколько угодно — сталкиваться им нечем, имени у них нет.
По той же причине дырке не передать аргумент по имени (`f(_: 1)` — не запись языка
вовсе) и не задать ей значения по умолчанию: значение всё равно выбрасывается.
В заголовке класса дырка занимает позицию, но **поля не заводит**:

```wdl
class Slot(_, y) { }
new Slot("забыть", "запомнить")     // Slot{"y": "запомнить"}
```

Прочитать `_` нельзя — это ошибка разбора, а не тихий `null`. Подробности и остальные
два места, где годится пропуск, — в [инструкциях](statements.md#_--пропуск-а-не-имя).

## return

**Точка с запятой обязательна.** Это второе место в языке после заголовка `for`, где
`;` не разделитель, а часть синтаксиса, и причина ровно та же, что у обязательных
скобок вокруг условия `if`: перевод строки [токена не даёт](statements.md#границы-инструкций-и-ошибки),
поэтому без терминатора эти два скрипта неразличимы:

```wdl
def f(x) {
    if (x < 0) return         // хотели выйти
    println("дальше")         // ...и напечатать всегда
}
```

`return println("дальше")` — законное возвращение результата вызова, а `println("дальше")`
отдельной инструкцией — законная инструкция. Никакое заглядывание вперёд их не разводит:
двусмысленность в самом тексте, а не в парсере. Молча выбрать одно из двух значило бы
превратить опечатку в тихую смену поведения — язык так не делает. С `;` вопрос
не возникает:

```wdl
def f(x) {
    if (x < 0) return;
    println("дальше")
}
```

Присваивание, где такая же двусмысленность возможна, обходится без терминатора именно
потому, что оно **не выражение**: `x = 5` не может оказаться значением, а вызов — может.

Остальное про `return` предсказуемо:

```wdl
def найти(значения, что) {
    for (i = 0; i < len(значения); i += 1) {
        if (значения[i] == что) {
            return i;          // выходит и из цикла, и из функции
        }
    }
    return -1;
}
```

* `return` **вне функции — ошибка разбора**, а не выполнения: парсер знает, внутри
  функции он сейчас или нет, и говорит об этом сразу.
* `return` без значения возвращает `null`. Функция, дошедшая до конца тела, — тоже.
* `break` и `continue` **не проходят через границу функции**: тело функции для парсера
  начинается вне всяких циклов, поэтому `while (true) { def f() { break } }` —
  ошибка разбора.

## Область видимости: что внутри, что снаружи

Правило одно, и оно то же, что у [блока](control-flow.md#блок-создаёт-область-видимости):
**имя, которого снаружи нет, заводится локально и наружу не выходит; имя, которое
снаружи есть, именно меняется.**

```wdl
значение = "снаружи"

def поработать() {
    локальная = "своя"          // нового имени снаружи нет — заводится здесь
    println(значение)           // внешнее читается: снаружи
    значение = "изнутри"        // внешнее меняется — это оно, а не копия
    return локальная;
}

println(поработать())           // своя
println(значение)               // изнутри
println(локальная)              // ошибка: переменная 'локальная' не определена
```

Отсюда же работает накопление без всякой возни:

```wdl
счёт = 0
def добавить(сколько) { счёт += сколько }
добавить(1)
добавить(2)
println(счёт)                   // 3
```

**Параметры всегда локальны.** Одноимённая внешняя переменная от этого не страдает —
и это единственный способ гарантированно получить локальное имя:

```wdl
x = "внешнее"
def f(x) { x = 10; println(x) } // 10
f(1)
println(x)                      // внешнее
```

**У каждого вызова свои локальные переменные**, поэтому рекурсия не путает значения
разных уровней.

О чём стоит знать: раз объявления функций живут в корневой области, глобальных имён
в скрипте много, а способа объявить локальную переменную с тем же именем у функции нет —
`счёт = 0` внутри функции изменит внешний `счёт`, а не создаст свой. Это цена языка
без объявлений; если однажды начнёт мешать, лечится либо словом объявления
(`local счёт = 0`), либо предупреждением от будущего резолвера имён.

## Замыкания

Функция помнит **область**, в которой её объявили, а не снимок значений. Поэтому
возвращённая функция продолжает видеть переменные вызова, которого уже нет:

```wdl
def счётчик() {
    сколько = 0
    return def() {
        сколько += 1
        return сколько;
    };
}

тик = счётчик()
println(тик(), тик(), тик())    // 123
другой = счётчик()              // своё замыкание, свой счёт
println(другой())               // 1
```

Два замыкания над одной переменной видят одно и то же — она общая, а не скопированная:

```wdl
def пара() {
    сколько = 0
    прибавить = def() { сколько += 1 }
    прочитать = def() => сколько
    прибавить()
    прибавить()
    return прочитать();         // 2
}
```

**Переменная перебора захватывается своя на каждый проход** — она и заводится в области
прохода, а не одна на весь цикл. Те самые грабли, на которых JavaScript стоял
до появления `let`:

```wdl
хранилище = [null, null, null]
i = 0
for (x in [1, 2, 3]) {
    хранилище[i] = def() => x
    i += 1
}
println(хранилище[0](), хранилище[1](), хранилище[2]())     // 123, а не 333
```

## Объявление существует со своей строки

Никакой стадии между разбором и выполнением нет: инструкции выполняются подряд, сверху
вниз, и `def` заводит имя тогда, когда до него дошло выполнение. Правило то же, что
у переменной, у [`const`](statements.md#const--имя-которое-нельзя-перезаписать),
у `import` и у класса — одно на весь язык.

```wdl
println(сумма(2, 3))            // ошибка: 'сумма' объявлена ниже, на строке 2
def сумма(a, b) => a + b
```

Сообщение при этом называет причину, а не симптом: движок ищет имя по дереву файла
уже после того, как поиск в области видимости не удался, и говорит, где объявление
стоит на самом деле.

**Это ограничивает только код верхнего уровня.** Тело функции выполняется позже своего
объявления, поэтому оно спокойно видит всё, что объявлено ниже:

```wdl
def main() => helper(2)         // helper ещё не существует — и это неважно
def helper(n) => n * 2
println(main())                 // 4: к этому моменту существуют обе
```

Отсюда же и взаимная рекурсия, без приёмов вроде `local function` в Lua: имя ищется
в области **в момент вызова**, а замыкание — ссылка на область, а не снимок её значений.

```wdl
def чётное(n) => n == 0 ? true : нечётное(n - 1)
def нечётное(n) => n == 0 ? false : чётное(n - 1)
println(нечётное(7))            // работает: к вызову объявлены обе
```

Практически из этого следует одно: строчка запуска переезжает вниз файла — сначала
объявления, потом работа. Так же устроены Python, Ruby и Lua; полный подъём объявлений
есть у JavaScript и PHP, но и JavaScript от него ушёл, положив `let`, `const` и `class`
в «мёртвую зону» до строки объявления.

Объявление внутри блока или внутри другой функции принадлежит своей области видимости
и наружу не выходит:

```wdl
if (true) { def внутренняя() => 1 }
println(внутренняя())           // ошибка: 'внутренняя' объявлена внутри вложенной области
```

Поэтому выбор реализации по условию делается присваиванием, а не `def`: имя заводится
на верхнем уровне, а что в него попадёт — решает ветка.

```wdl
log = null
if (debug) { log = def(msg) => println("[отладка] ", msg) }
else       { log = def(msg) => println(msg) }
```

## Функция высшего порядка

Вызывается [значение, а не имя](statements.md#вызов), поэтому ничего специального
для этого не нужно:

```wdl
def удвоить(x) => x * 2
def дважды(f, значение) => f(f(значение))
println(дважды(удвоить, 5))                 // 20

def прибавлятель(сколько) => def(x) => x + сколько
прибавить10 = прибавлятель(10)
println(прибавить10(5))                     // 15

обработчики = [def(x) => x + 1, удвоить]
println(обработчики[1](21))                 // 42
```

Встроенные функции здесь ничем не отличаются от своих:

```wdl
def применить(f, значение) => f(значение)
применить(println, "эхо")                   // эхо
```

Обёртка над функцией — частный случай того же самого, и у него есть своя запись:
[декоратор](decorators.md) применяет функцию к объявлению прямо на строке объявления.

```wdl
@[timer]
def command(a, b = 10) => a + b
```

Ничего нового в язык это не добавляет — `command = timer(m.of(command))` делает то же, —
но обвес виден там, где объявление, а не двадцатью строками ниже.

Рядом с декоратором объявлению можно приписать **данные** — [аннотацию](annotations.md).
Она ничего не делает: лежит в значении и ждёт того, кто спросит. Аннотировать можно
и параметр:

```wdl
@{command: "deploy", help: "выкатить сборку на стенд"}
def deploy(@{help: "имя стенда"} env, @{help: "версия"} version = "latest") { }

println(deploy.annotations["help"])             // выкатить сборку на стенд
println(deploy.params[0]["annotations"]["help"]) // имя стенда
```

## Ошибки

Число аргументов проверяется **до входа** в функцию, поэтому сообщение одинаково
для всех функций, а сама функция начинается с дела, а не с проверок:

```
скрипт.wdl:2:1: ошибка: функция 'f' принимает ровно 1 аргумент, а передано 2
  2 | f(1, 2)
    | ^^^^^^^
```

У функции со [значениями по умолчанию](#значения-по-умолчанию) сообщение то же, только
про диапазон: `принимает от 1 до 2 аргументов`.

**Бесконечная рекурсия — ошибка скрипта, а не падение приложения.** Движок считает
вложенные вызовы и на 256-м останавливается сам:

```
скрипт.wdl:1:17: ошибка: слишком глубокая рекурсия: вложенных вызовов больше 256.
Проверьте условие выхода из 'вечно'
```

Число выбрано с запасом вниз: один вызов wdl стоит около десятка кадров стека Java,
но сколько именно — зависит от формы тела, а сколько кадров вообще влезет — от размера
стека потока, которым движок не распоряжается. Поэтому есть и вторая линия: если стек
кончился раньше счётчика, `StackOverflowError` всё равно превращается в ошибку скрипта.
Предел станет настраиваемым вместе с остальными лимитами — шагами и таймаутом.

## `synchronized`: модификатор перед `def`

Слово перед `def` меняет не тело функции, а правила её вызова: вызовы
`synchronized`-функции не идут одновременно.

```wdl
count = 0

synchronized def bump() {
    count = count + 1        // атомарно относительно других вызовов bump
}
```

Нужно это потому, что `count = count + 1` — **два** обращения: прочитать и записать.
Атомарно в языке одно, поэтому два потока, прочитавшие одно и то же значение, запишут
одно и то же, и один инкремент пропадёт. Модификатор склеивает обращения в неделимое
целое.

Ставится он у всех форм — у объявления, у метода класса, у фабрики и у анонимной
функции:

```wdl
handler = synchronized def (event) { log = log + [event] }
```

Два правила, которые стоит помнить:

* **Замок принадлежит значению-функции, а не имени.** Замыкание, созданное дважды, даёт
  два значения и два замка — у них разное захваченное состояние, и общий замок заставлял
  бы два независимых счётчика ждать друг друга.
* **У метода класса замок — экземпляр.** Два `synchronized`-метода одного объекта
  взаимно исключаются, два разных объекта не мешают друг другу вовсе.

Подробно, вместе с моделью памяти и модулем `sys.thread`, — в [потоках](threads.md).

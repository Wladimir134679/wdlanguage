# Функции

Функция в wdl — не особая сущность, а [обычное значение](types.md#функция) в обычной
переменной. Всё остальное следствия: её можно передать аргументом, вернуть из другой
функции, положить в массив и в поле объекта. Готовый пример целиком —
[`examples/functions.wdl`](../examples/functions.wdl).

```wdl
fun сумма(a, b) {
    return a + b;
}
println(сумма(2, 3))        // 5
```

## Четыре формы записи, одно и то же дерево

```wdl
fun сумма(a, b) { return a + b; }       // блок
fun сумма(a, b) return a + b;           // одна инструкция
fun сумма(a, b)
    return a + b;                       // то же самое: перенос строки ничего не значит
fun сумма(a, b) => a + b                // тело-выражение
```

`=>` — это `return`, записанный короче, и в дереве он им и становится. Разница только
в том, что стрелке не нужна ни точка с запятой, ни слово `return`, поэтому короткие
функции пишутся в одну строку без служебного шума.

Форма записи сохраняется в дереве (`BodyStyle`) — не ради выполнения, а ради форматтера:
он обязан вернуть стрелку туда, где была стрелка. Тот же мотив, что у
[единого обращения](access.md), где `a.b` и `a["b"]` — один узел с пометкой о форме.

Тело без фигурных скобок — одна инструкция, и своей области видимости оно не создаёт,
как и [тело `if` без скобок](control-flow.md#блок-создаёт-область-видимости). Разницы
для функции это не делает: локальные переменные всё равно живут в области вызова.

### После `=>` фигурная скобка — это объект

```wdl
fun точка(x, y) => {x: x, y: y}         // возвращает объект
fun точка(x, y) { return {x: x}; }      // блок, внутри которого return объекта
```

Отдельного правила для этого не понадобилось: `{` в начале инструкции — всегда блок,
в позиции выражения — всегда [литерал объекта](types.md#объект). После `=>` ждут
выражение, значит объект.

## Анонимные функции

```wdl
удвоить = fun(x) => x * 2
println(удвоить(21))                    // 42

операции = {
    плюс: fun(a, b) => a + b,
    минус: fun(a, b) => a - b
}
println(операции.плюс(10, 4))           // 14
```

`fun имя(...)` и `fun(...)` — один и тот же узел дерева; объявление отличается тем,
что ещё и **заводит** имя. Разница видна там, где одноимённая переменная есть снаружи:
объявление создаёт своё имя в текущей области, а присваивание `имя = fun(...)` ищет
существующее имя наружу и меняет его.

Анонимная функция, которой присваивают переменную, забирает её имя себе — только
для сообщений об ошибках: `функция 'удвоить' принимает ровно 1 аргумент` понятнее,
чем то же про `fun`.

## return

**Точка с запятой обязательна.** Это второе место в языке после заголовка `for`, где
`;` не разделитель, а часть синтаксиса, и причина ровно та же, что у обязательных
скобок вокруг условия `if`: перевод строки [токена не даёт](statements.md#границы-инструкций-и-ошибки),
поэтому без терминатора эти два скрипта неразличимы:

```wdl
fun f(x) {
    if (x < 0) return         // хотели выйти
    println("дальше")         // ...и напечатать всегда
}
```

`return println("дальше")` — законное возвращение результата вызова, а `println("дальше")`
отдельной инструкцией — законная инструкция. Никакое заглядывание вперёд их не разводит:
двусмысленность в самом тексте, а не в парсере. Молча выбрать одно из двух значило бы
превратить опечатку в тихую смену поведения — язык так не делает. С `;` вопрос
не возникает:

```wdl
fun f(x) {
    if (x < 0) return;
    println("дальше")
}
```

Присваивание, где такая же двусмысленность возможна, обходится без терминатора именно
потому, что оно **не выражение**: `x = 5` не может оказаться значением, а вызов — может.

Остальное про `return` предсказуемо:

```wdl
fun найти(значения, что) {
    for (i = 0; i < len(значения); i += 1) {
        if (значения[i] == что) {
            return i;          // выходит и из цикла, и из функции
        }
    }
    return -1;
}
```

* `return` **вне функции — ошибка разбора**, а не выполнения: парсер знает, внутри
  функции он сейчас или нет, и говорит об этом сразу.
* `return` без значения возвращает `null`. Функция, дошедшая до конца тела, — тоже.
* `break` и `continue` **не проходят через границу функции**: тело функции для парсера
  начинается вне всяких циклов, поэтому `while (true) { fun f() { break } }` —
  ошибка разбора.

## Область видимости: что внутри, что снаружи

Правило одно, и оно то же, что у [блока](control-flow.md#блок-создаёт-область-видимости):
**имя, которого снаружи нет, заводится локально и наружу не выходит; имя, которое
снаружи есть, именно меняется.**

```wdl
значение = "снаружи"

fun поработать() {
    локальная = "своя"          // нового имени снаружи нет — заводится здесь
    println(значение)           // внешнее читается: снаружи
    значение = "изнутри"        // внешнее меняется — это оно, а не копия
    return локальная;
}

println(поработать())           // своя
println(значение)               // изнутри
println(локальная)              // ошибка: переменная 'локальная' не определена
```

Отсюда же работает накопление без всякой возни:

```wdl
счёт = 0
fun добавить(сколько) { счёт += сколько }
добавить(1)
добавить(2)
println(счёт)                   // 3
```

**Параметры всегда локальны.** Одноимённая внешняя переменная от этого не страдает —
и это единственный способ гарантированно получить локальное имя:

```wdl
x = "внешнее"
fun f(x) { x = 10; println(x) } // 10
f(1)
println(x)                      // внешнее
```

**У каждого вызова свои локальные переменные**, поэтому рекурсия не путает значения
разных уровней.

О чём стоит знать: раз объявления функций живут в корневой области, глобальных имён
в скрипте много, а способа объявить локальную переменную с тем же именем у функции нет —
`счёт = 0` внутри функции изменит внешний `счёт`, а не создаст свой. Это цена языка
без объявлений; если однажды начнёт мешать, лечится либо словом объявления
(`local счёт = 0`), либо предупреждением от будущего резолвера имён.

## Замыкания

Функция помнит **область**, в которой её объявили, а не снимок значений. Поэтому
возвращённая функция продолжает видеть переменные вызова, которого уже нет:

```wdl
fun счётчик() {
    сколько = 0
    return fun() {
        сколько += 1
        return сколько;
    };
}

тик = счётчик()
println(тик(), тик(), тик())    // 123
другой = счётчик()              // своё замыкание, свой счёт
println(другой())               // 1
```

Два замыкания над одной переменной видят одно и то же — она общая, а не скопированная:

```wdl
fun пара() {
    сколько = 0
    прибавить = fun() { сколько += 1 }
    прочитать = fun() => сколько
    прибавить()
    прибавить()
    return прочитать();         // 2
}
```

**Переменная перебора захватывается своя на каждый проход** — она и заводится в области
прохода, а не одна на весь цикл. Те самые грабли, на которых JavaScript стоял
до появления `let`:

```wdl
хранилище = [null, null, null]
i = 0
for (x in [1, 2, 3]) {
    хранилище[i] = fun() => x
    i += 1
}
println(хранилище[0](), хранилище[1](), хранилище[2]())     // 123, а не 333
```

## Объявления помечаются до выполнения

Перед первой инструкцией движок проходит по объявлениям **верхнего уровня** и заводит
их имена в корневой области запуска. Поэтому порядок в файле свободный:

```wdl
println(сумма(2, 3))            // работает: объявление уже помечено
fun сумма(a, b) => a + b

fun чётное(n) => n == 0 ? true : нечётное(n - 1)
fun нечётное(n) => n == 0 ? false : чётное(n - 1)
println(нечётное(7))            // взаимная рекурсия
```

Только верхний уровень, и это решение, а не упрощение: объявление внутри блока или
внутри другой функции принадлежит своей области видимости, и поднимать его в корень
значило бы протаскивать имя наружу — ровно то, чего область видимости не должна
допускать.

```wdl
if (true) { fun внутренняя() => 1 }
println(внутренняя())           // ошибка: переменная 'внутренняя' не определена
```

Помечаются именно объявления. `f = fun(...)` — присваивание, оно выполняется в свой
черёд, и вызвать `f` выше этой строки нельзя.

## Функция высшего порядка

Вызывается [значение, а не имя](statements.md#вызов), поэтому ничего специального
для этого не нужно:

```wdl
fun удвоить(x) => x * 2
fun дважды(f, значение) => f(f(значение))
println(дважды(удвоить, 5))                 // 20

fun прибавлятель(сколько) => fun(x) => x + сколько
прибавить10 = прибавлятель(10)
println(прибавить10(5))                     // 15

обработчики = [fun(x) => x + 1, удвоить]
println(обработчики[1](21))                 // 42
```

Встроенные функции здесь ничем не отличаются от своих:

```wdl
fun применить(f, значение) => f(значение)
применить(println, "эхо")                   // эхо
```

## Ошибки

Число аргументов проверяется **до входа** в функцию, поэтому сообщение одинаково
для всех функций, а сама функция начинается с дела, а не с проверок:

```
скрипт.wdl:2:1: ошибка: функция 'f' принимает ровно 1 аргумент, а передано 2
  2 | f(1, 2)
    | ^^^^^^^
```

Значения по умолчанию (`fun f(a, b = 10)`) появятся позже — тогда проверка станет
диапазоном, а место её не изменится.

**Бесконечная рекурсия — ошибка скрипта, а не падение приложения.** Движок считает
вложенные вызовы и на 256-м останавливается сам:

```
скрипт.wdl:1:17: ошибка: слишком глубокая рекурсия: вложенных вызовов больше 256.
Проверьте условие выхода из 'вечно'
```

Число выбрано с запасом вниз: один вызов wdl стоит около десятка кадров стека Java,
но сколько именно — зависит от формы тела, а сколько кадров вообще влезет — от размера
стека потока, которым движок не распоряжается. Поэтому есть и вторая линия: если стек
кончился раньше счётчика, `StackOverflowError` всё равно превращается в ошибку скрипта.
Предел станет настраиваемым вместе с остальными лимитами — шагами и таймаутом.

# Ветвления и циклы

Скрипт перестаёт быть списком действий сверху вниз: появляются `if`, `while`, `for`,
перебор `for ... in` и `match`. Готовый пример целиком —
[`examples/control-flow.wdl`](../examples/control-flow.wdl), а по `match` — свой:
[`examples/match.wdl`](../examples/match.wdl).

```wdl
if (температура > 25) {
    println("жарко")
} else if (температура > 10) {
    println("нормально")
} else {
    println("холодно")
}
```

## Условие в скобках, тело — блок или одна инструкция

Скобки вокруг условия обязательны. Это не дань привычке к Си: перевод строки в wdl
[токена не даёт](statements.md#границы-инструкций-и-ошибки), поэтому без скобок
`if x { ... }` было бы неотличимо от `if` с [литералом объекта](types.md#объект)
в условии. Скобки решают это без единого правила-исключения.

Тело — либо блок, либо одна инструкция:

```wdl
if (готово) println("да")               // одна инструкция
if (готово) { println("да"); выйти() }  // блок
```

**`else` достаётся ближайшему `if`.** `if (a) if (b) x() else y()` — это `else` от
внутреннего `if`, как в любом знакомом языке. Отдельного узла для `else if` в дереве
нет: цепочка `if / else if / else` — это `IfStmt`, у которого в иначе-ветви лежит
следующий `IfStmt`.

**В условие не вписать присваивание.** `if (x = 5)` не разберётся вообще, потому что
`x = 5` в языке [инструкция, а не выражение](statements.md#присваивание--инструкция-а-не-выражение).
Классическая опечатка отсекается по построению, а не проверкой в парсере.

**Условие смотрит на истинность, а не на тип.** Ложны только `null` и `false`;
ноль, пустая строка и пустой массив истинны — [почему именно так](types.md#истинность).

## Блок создаёт область видимости

Это главное правило, из которого следует всё остальное поведение имён:

```wdl
if (true) { внутренняя = 1 }
println(внутренняя)          // ошибка: переменная 'внутренняя' не определена

счёт = 0
while (счёт < 3) { счёт += 1 }
println(счёт)                // 3 — счёт заведён снаружи, блок его не копирует
```

Правило то же самое, что и раньше — «имя заводится там, где ему присвоили впервые», —
просто теперь «там» бывает блоком.

[`const`](statements.md#const--имя-которое-нельзя-перезаписать) подчиняется тому же
правилу, потому что это объявление: константа из блока снаружи не существует, а
одноимённая внешняя от неё не страдает — блок её затеняет, а не переопределяет.

Отсюда же следствие, о котором стоит помнить: тело **без** скобок своей области
не создаёт, потому что в нём нет блока. Константа, объявленная в таком теле, заводится
в объемлющей области — ровно как это делает `def` без скобок.

```wdl
if (true) новая = 1
println(новая)               // 1 — блока не было, имя завелось снаружи
```

Фигурная скобка в начале инструкции — всегда блок, в позиции выражения — всегда
литерал объекта. Разводятся они местом, а не заглядыванием вперёд, так что
`{a: 1}` в начале строки — не объект, а блок с ошибкой внутри; чтобы получить объект,
его надо кому-то отдать: `x = {a: 1}`.

## while

```wdl
остаток = 3
while (остаток > 0) {
    println("осталось ", остаток)
    остаток -= 1
}
```

Условие проверяется перед каждым проходом, поэтому тело может не выполниться ни разу.

## for со счётчиком

```wdl
сумма = 0
for (i = 1; i <= 5; i += 1) сумма += i
println(сумма)               // 15
println(i)                   // ошибка: переменная 'i' не определена
```

Счётчик живёт в собственной области цикла: наружу он не выходит и не мешает следующему
циклу с таким же `i`.

Инициализатор и шаг — инструкции, а не выражения, и это ровно та проверка, которая
нужна: в них допустимы присваивание и вызов, то есть только то, что имеет эффект.

**Любая из трёх частей может отсутствовать.** Пропущенное условие означает «повторять
всегда»:

```wdl
for (;;) {
    if (готово()) break
}
```

Пропущенной части нет и в дереве — там `null`, а не подставленный литерал `true`.
Интерпретатору разницы никакой, а форматтер обязан напечатать ровно то, что человек
написал.

## Перебор: for ... in

```wdl
for (товар in корзина) {
    println(товар.имя, " — ", товар.цена)
}
```

Отдельного слова `foreach` нет: незачем резервировать второе ключевое слово ради
конструкции, которую и так ни с чем не спутать. Форму парсер различает по тому, что
стоит до `in`: список имён и `in` — перебор, что угодно другое — счётчик.

| Что перебираем | Что попадает в переменную |
|---|---|
| массив | элементы по порядку |
| строка | символы, по одному |
| объект | **ключи**, а не значения |
| [диапазон](types.md#диапазон) | целые от нижней границы до верхней включительно |

Ключи, а не значения, потому что значение по ключу всегда рядом — `настройки[ключ]`, —
а обратной операции не существует:

```wdl
for (ключ in настройки) println(ключ, " = ", настройки[ключ])
```

Перебрать что-то другое — ошибка выполнения с указанием типа: `перебрать можно массив,
строку, объект или диапазон, а здесь число (5)`.

Диапазон перебирается шагом в единицу, поэтому границы у него обязаны быть целыми:
у `0.5..2.5` нет ответа на вопрос, какие числа он содержит «по одному». Пустой
диапазон даёт ноль проходов — ради этого `5..1` и [пуст, а не идёт
вниз](types.md#диапазон):

```wdl
for (i in 1..5) print(i, " ")       // 1 2 3 4 5
for (i in 0..n - 1) ...             // при n == 0 — ни одного прохода
```

**Переменная перебора своя на каждый проход**, а не одна общая на весь цикл. Разница
видна там, где тело создаёт [замыкание](functions.md#замыкания): оно захватывает
значение своего прохода, а не последнее — ровно те грабли, на которых JavaScript стоял
до появления `let`.

**Перебираемое можно менять прямо в цикле.** По массиву движок идёт по индексу
с заранее снятой длиной, по объекту — по снимку ключей: добавленное во время перебора
в этот проход не попадёт, удалённое ничего не сломает. Получить
`ConcurrentModificationException` из внутренностей Java автор скрипта не должен
никогда — это ошибка о чужой реализации, а не о его скрипте.

### Второе имя: ключ и значение

```wdl
for (i, tile in row) ...            // массив: индекс и элемент
for (k, v in config) ...            // объект: ключ и значение
for (name, value in player) ...     // экземпляр: имя поля и значение
for (i, ch in text) ...             // строка: индекс и символ
for (_, v in config) ...            // ключ не нужен
```

**Первое имя — всегда то, чем обращаются**: `row[i]`, `config[k]`, `text[i]`. Одно
это правило и объясняет всю таблицу выше: массив и строка читаются по номеру,
объект и экземпляр — по ключу. Второе имя — то, что по этому ключу лежит.

Отсюда же и то, чего второе имя **не** делает: оно не распаковывает элемент.
Разложить сам элемент — [распаковка](statements.md#распаковка-x-y--point), и пишется
она отдельной строкой в теле:

```wdl
for (p in points) {
    x, y = *p
    draw(x, y)
}
```

Так один и тот же список имён нигде не значит двух разных вещей. Будь второе имя
распаковкой, `for (a, b in pairs)` и `for (a, b in config)` делали бы совсем разное
при одинаковом виде, а `for (k, v in config)` — самая частая из этих записей —
перестала бы существовать вовсе.

У **диапазона** ключа нет: читать `RangeValue` по индексу нельзя, у него только
члены, а номер прохода там и есть значение. Поэтому два имени — ошибка, а не
«индекс и число»:

```
for (i, n in 0..10)
  у диапазона нет ключа: номер прохода здесь и есть значение —
  оставьте одно имя, 'n'
```

Больше двух имён — ошибка разбора, всегда, и место у неё на лишнем имени. Не «лишние
получают `null`»: три имени в `for` значат, что автор ждал распаковки, и молчаливая
подстановка спрятала бы это до первого неверного результата.

```
for (a, b, c in items)
  в 'for' бывает одно имя (значение) или два (ключ и значение), а здесь больше
```

Пропуск `_` годится в любой из двух позиций и имени не заводит — см.
[«`_` — пропуск, а не имя»](statements.md#_--пропуск-а-не-имя).

## break и continue

```wdl
for (товар in корзина) {
    if (товар.цена < 5) continue        // дешёвое пропускаем
    if (товар.имя == "болт") break      // нашли — дальше не ищем
}
```

`break` выходит из ближайшего цикла, `continue` заканчивает текущий проход. Из двух
вложенных циклов `break` прерывает только внутренний; меток у циклов пока нет.

**Через границу функции они не проходят.** Тело функции для парсера начинается вне
всяких циклов, поэтому `while (true) { def f() { break } }` — ошибка разбора: выйти
из цикла, объемлющего объявление, функция не может. Выйти из самой функции —
это [`return`](functions.md#return).

**`break` вне цикла — ошибка разбора, а не выполнения.** Парсер знает, внутри цикла
он сейчас или нет, и говорит об этом сразу — а не в тот день, когда до этой ветки
наконец дойдёт выполнение.

**`continue` в `for` не пропускает шаг.** `for (i = 0; i < 100; i += 1) continue`
конечен. Пропуск шага — самый простой способ превратить обычный цикл в вечный,
и язык так делать не станет.

## match

Ветвление по **одному предмету**. Готовый пример целиком —
[`examples/match.wdl`](../examples/match.wdl).

```wdl
level = match (cpu) {
    case > 90 => "критично"
    case > 70 => "высоко"
    else      => "тихо"
}
```

**`match`, а не `switch`.** `switch` в наследственности C/Java значит «переключатель
с провалом»: метки, `break` в каждой ветке, значения не даёт. Взяв это имя,
конструкция пообещала бы читателю то, чего делать не будет.

### После `case` идёт хвост выражения

Подлежащее этой фразы — предмет из заголовка: `case > 90` читается как
«предмет `>` 90», `case is Circle` — «предмет `is Circle`». Голый образец — тот же
хвост с неявным `==`: `case 1` значит «предмет `== 1`».

Отсюда весь набор возможностей берётся из [уже существующих
операторов](expressions.md#приоритеты), а не изобретается заново:

```wdl
match (value) {
    case is Number     { println("число") }        // проверка типа или класса
    case in admins     { println("свой") }         // принадлежность
    case in 18..65     { println("работает") }     // диапазон
    case !in ["guest"] { println("не гость") }     // отрицание
    case > 90, < 10    { println("край") }         // перечисление образцов
}
```

Своей «системы образцов» у `match` нет и не нужно. Заведи её — и рядом с
`runtime.Operations` появилась бы вторая реализация сравнений, которая однажды
разойдётся с `if`; ровно тот же довод, по которому `len(x)` и `x.size` берут ответ
из одной таблицы.

**Перечисление заменяет провал.** В Си группировка вариантов делается пустой меткой,
которая проваливается в следующую. Здесь провала нет вовсе, а `case 1, 2, 3` читается
прямее.

**Полное выражение в образце — ошибка разбора.** `case score > 90` по правилу «после
`case` идёт хвост» значило бы «предмет `== (score > 90)`», то есть тихое «никогда».
Отсекается по построению, как и `if (x = 5)`:

```
ошибка: слева от '>' не нужен операнд: предмет уже назван в 'match (...)' —
напишите 'case > ...'
```

Скобки снимают запрет: `case (a > b)` — осознанное сравнение предмета с логическим.

### Условие в ветке

`if` после образцов добавляет то, что от предмета не зависит:

```wdl
match (cpu) {
    case > 90 if !throttled { alarm() }
    case if throttled       { println("придержано") }
}
```

Ветка из одного условия законна: предмет при этом по-прежнему один и назван в одном
месте. Если условиями оказались *все* ветки — автору был нужен `if`, но это замечание
линтера, а не запрет парсера.

### `=>` даёт значение, `{ }` делает — а `yield` отдаёт

Стрелка значит здесь то же, что в [`def f(a) => a + 1`](functions.md): «дальше
значение». Фигурные скобки — обычный блок со своей областью видимости.

Блок годится в обеих позициях, и разница в том, чем он обязан кончиться. Инструкцией —
просто делает. Выражением — обязан отдать значение словом `yield`:

```wdl
invoice = match (order.items.size) {
    case 0 => "пустой заказ"
    case > 0 {
        total = 0
        for (price in order.items) total += price
        if (order.vip) total = total * 0.9
        yield "к оплате: " + total
    }
    else => "не бывает"
}
```

**Слово, а не «последнее выражение блока — результат».** Неявный результат читатель
обязан вычислить сам — пробежать блок до конца и вспомнить правило, — а ошибку
в таком чтении не видно: дописали строку после результата, и ветка молча стала
отдавать другое. `yield` стоит ровно там, где значение отдают, и не заметить его
нельзя. Заодно снимается вопрос «а что если последняя строка — `if`»: он просто
не возникает.

**`yield` заканчивает ветку**, как `return` заканчивает функцию, и работает из любой
глубины — из ветвления, из цикла:

```wdl
def firstBig(values) => match (values) {
    case is Array {
        for (value in values) {
            if (value > 100) yield value
        }
        yield 0
    }
    else => 0
}
```

**Точка с запятой не нужна.** Значение у `yield` есть всегда, поэтому «есть оно или
нет» решать не приходится — в отличие от [`return`](functions.md#return), где `;`
обязателен именно из-за необязательного значения. Тот же довод, что у `throw`
и у стрелочного тела функции.

**Ветка, не дошедшая до `yield`, — ошибка, а не тихий `null`.** Тот же довод, по
которому обязателен `else`: значение обязано быть у любого предмета. Разделение труда
такое: ветку, где `yield` не написан вовсе, ловит разбор; ветку, где `yield` стоит
под условием и условие не выполнилось, — выполнение. Доказывать, что условие
выполнится, язык не берётся: стадии для этого у него нет ни одной.

```
ошибка: ветка не отдаёт значения: здесь 'match' стоит в позиции выражения,
и блок обязан отдать значение словом 'yield выражение'
```

**Ветке, которая уходит через `return`, `throw`, `break` или `continue`, `yield`
не нужен** — управление уходит мимо `match` целиком, и требовать от неё значение
значило бы требовать недостижимую строку.

**`yield` не проходит через границу функции и не выходит за свою ветку.** `yield`
внутри `def`, объявленной в ветке, — ошибка разбора; `yield` в ветке
`match`-инструкции — тоже, потому что такой ветке нечего отдавать. Вложенный `match`
забирает свой `yield` первым: «значение этого `case`» читается однозначно, и молча
уводить его во внешнюю ветку язык не станет.

Из всего этого следуют оба различия между позициями:

| | `match` выражением | `match` инструкцией |
|---|---|---|
| ветка в одну строку | `case X => выражение` | `case X => вызов` |
| ветка в несколько строк | блок, оканчивающийся `yield` | блок |
| `else` | обязателен | не обязателен |
| результат | значение выбранной ветки | ничего |

**`else` обязателен там, где нужно значение.** Исчерпаемость в динамическом языке
не доказать, а тихий `null` из непопавшего `match` — ровно тот класс ошибок, который
язык обещает ломать там, где написано. Одной фразой: значение обязано быть, действие
может не потребоваться.

**«Иначе» — это `else`, а не `default`.** Слово уже есть и значит ровно это; заводить
второе ключевое слово ради конструкции, которую не с чем спутать, язык уже отказывался
(`foreach`).

**Позицию определяет место, а не заглядывание вперёд.** `match` в начале инструкции —
инструкция, `match` там, где ждут значение, — выражение; тем же приёмом решается
`{` в начале инструкции (всегда блок) против `{` в позиции выражения (всегда объект).
Побочно и бесплатно решается `case 1 => {a: 1}` (объект) против `case 1 {a: 1}` (блок).

### Что происходит при выполнении

**Предмет вычисляется один раз** — это и есть главное отличие от цепочки `if`:
`match (order.total())` не зовёт `total()` на каждую ветку.

**Образцы вычисляются лениво**, сверху вниз, до первого совпадения. Порядок веток —
часть смысла, движок их не переставляет. Побочный эффект в образце случится, только
если до этой ветки дошла очередь.

**Ветка, не дошедшая до `yield`, останавливает выполнение** — вместо того чтобы
подсунуть дальше пустое значение:

```
ошибка: ветка 'case' закончилась, не отдав значение: 'match' стоит в позиции
выражения, и значение обязано быть у любого предмета
```

**Провала нет, и `break` в ветке относится к объемлющему циклу**, а не к `match`.
В Си иначе, поэтому сказать надо вслух:

```wdl
for (i in 1..5) {
    match (i) {
        case 3 { break }        // выходит из for, а не из match
        else   { println(i) }
    }
}
```

### Чего у `match` нет

**Формы без предмета** (`match { case cpu > 90 => ... }`). Она почти всегда
оказывается `match`, у которого поленились вынести заголовок, — предмет виден
повтором в каждой ветке; а когда предмет в ветках действительно разный, это
`if / else if`, и второго лица под чужим именем ему не нужно.

**Структурного сопоставления с извлечением имён** (`case {type: "click", x, y}`).
Это отдельный проект: оно вводит **второй способ завести имя** помимо присваивания,
а «имя существует с той строки, где его завели» — одно из немногих правил языка
без единого исключения.

**«Последнее выражение блока — результат».** Отвергнуто в пользу `yield`: неявный
результат читатель обязан вычислить сам, и дописанная после него строка молча меняет
значение ветки. Слово стоит своей цены именно тем, что его нельзя не заметить.

## Условное выражение — не ветвление

Там, где нужно не действие, а значение, ветвление не нужно:

```wdl
знак = температура > 0 ? "плюс" : "минус"
```

Это [выражение](expressions.md#условное-выражение), а не инструкция: у него есть
значение, и его можно вложить куда угодно — в аргумент, в поле объекта, в другое
условное выражение.

## Когда что-то пошло не так

Ошибка внутри блока не уносит с собой ни остаток блока, ни файл: разбор
восстанавливается по границам инструкций и — это важно для блоков — не заходит
за `}` и за слова, начинающие следующую конструкцию.

```
скрипт.wdl:1:10: ошибка: это выражение ничего не делает: инструкцией может быть вызов функции или присваивание
  1 | if (x) { a + 1 }
    |          ^^^^^
```

Вторая строка файла после такой ошибки разберётся как ни в чём не бывало.

**Зациклившийся скрипт можно остановить снаружи.** Циклы проверяют прерывание потока,
поэтому обычный `thread.interrupt()` со стороны приложения завершает выполнение
ошибкой `выполнение прервано`, а не оставляет висеть навсегда. Полноценные лимиты
(шаги, таймаут) придут в `ExecutionContext` позже.

## Что дальше

`do ... while` и метки циклов — когда появится необходимость. Из большого —
структурное сопоставление в `match` (`case {type: "click", x, y}`): оно ждёт ответа
на вопрос, как в языке заводится имя, и потому идёт отдельным проектом, а не
дополнением к ветке.

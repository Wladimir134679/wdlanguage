# Перегрузка операторов: что перегружается в wdl

> **Сделано и сверено с реализацией.** Описание для читателя языка — в
> [docs/expressions.md](../docs/expressions.md#перегрузка-операторов), рабочий пример —
> [`examples/operators.wdl`](../examples/operators.wdl). Этот документ остаётся
> таблицей приёмки: он говорит, **что и почему**, а не как этим пользоваться.

Рабочая таблица проекта. Соседний [over_operation_tables.md](over_operation_tables.md) —
обзор операторов **вообще, во всех языках**; он остаётся справочником и списком работ
не является. Здесь — только то, что есть в wdl, и решение по каждому оператору
с причиной.

## Правило, из которого следует вся таблица

**Ядро важнее. Оператор спрашивают только тогда, когда ядро не справилось.**

`2 + 2` не делает ни одного поиска члена: сложение чисел считает `Operations.binary`,
и перегрузка в этот путь не вмешивается. Член ищется на том шаге, где сегодня
выбрасывается ошибка типов, и если члена нет — выбрасывается та же ошибка.

Причин у правила три, и все три весомые:

* **Цена.** Перегрузка не стоит ничего на горячем пути. Спрашивай мы член первым,
  каждое сложение двух чисел начиналось бы с поиска имени по цепочке областей.
* **Безопасность.** Арифметику чисел нельзя сломать ни из какого модуля.
  Таблица членов принадлежит **запуску целиком**, не файлу и не модулю: разрешив
  подмену, мы разрешили бы одной библиотеке испортить умножение всей программе,
  включая stdlib и код, который об этой библиотеке не знает.
* **Простота.** Приоритетов не существует. Правила «оператор объекта важнее
  локального, локальный важнее глобального» нет и не нужно, потому что нет конфликта.

Следствие, которое надо знать: **переопределить операцию, которую ядро уже умеет,
невозможно.** `extend Number` с оператором `*` объявить можно, но сработает он только
там, где второй операнд — не число. Это не ограничение реализации, это и есть смысл
правила.

## Контракт: обычный оператор и `mirror`

Оператор — обычный член. Получатель — **левый** операнд, единственный параметр —
правый:

```wdl
class Point(x, y) {
    def `/`(right) {
        if (right is Number) return new Point(x / right, y / right)
        return new Point(x / right.x, y / right.y)
    }
}
```

`mirror` — тот же метод для случая, когда получатель оказался **справа**:
параметром приходит левый операнд.

```wdl
    mirror def `/`(left) {
        if (left is Number) return new Point(left / x, left / y)
        return new Point(left.x / x, left.y / y)
    }
```

**Тело `mirror` возвращает ответ всего выражения так, как оно написано** —
значение `left op this`, а не «своё, а мы перевернём». Одно предложение на весь
контракт, и оно одинаково для арифметики, сдвигов и сравнений.

Порядок поиска, когда ядро не справилось:

1. оператор у левого операнда;
2. `mirror`-оператор у правого;
3. ошибка типов — та же, что и сегодня, но с указанием, какого оператора не хватило.

Унарный оператор отличается **арностью**, а не именем: `def` с именем `-` без
параметров — унарный, с одним параметром — бинарный. У унарного `mirror` не бывает.

## 1. Перегружаемые бинарные операторы

| Оператор | Имя члена | `mirror` | Когда спрашивается |
| :--- | :--- | :--- | :--- |
| `+` | `+` | да | ни оба числа, ни строка в операнде, ни два массива |
| `-` `*` | `-` `*` | да | хоть один операнд не число |
| `/` `%` | `/` `%` | да | хоть один операнд не число |
| `&` `\|` `^` | `&` `\|` `^` | да | хоть один операнд не целое |
| `<<` `>>` `>>>` | `<<` `>>` `>>>` | да | хоть один операнд не целое |
| `..` | `..` | да | границы не числа |
| `==` `!=` | `==` | да | см. оговорку ниже — ядро тут не падает |
| `<` `<=` `>` `>=` | `<=>` | да | не два числа и не две строки |
| `in` `!in` `has` `!has` | `in` | **нет**, см. ниже | контейнер — экземпляр класса (см. оговорку) либо не массив, не строка, не объект и не диапазон |

Имя члена всюду пишется в обратных кавычках: `` def `+`(right) ``.

## 2. Перегружаемые унарные операторы

| Оператор | Объявление | Когда спрашивается |
| :--- | :--- | :--- |
| `-a` | `` def `-`() `` | операнд не число |
| `+a` | `` def `+`() `` | операнд не число |
| `~a` | `` def `~`() `` | операнд не целое |

## 3. Не перегружается — и почему

| Оператор | Причина |
| :--- | :--- |
| `&&` `\|\|` | Ленивые. Перегрузка обязала бы вычислить оба операнда, то есть отняла бы у оператора ровно то, ради чего он существует. |
| `!a` | Ядро на нём не падает никогда: `!x` — это отрицание достоверности, а достоверность есть у любого значения. Перегрузка потребовала бы второго исключения из правила запасного пути ради инверсии, которой почти никто не пишет. Достоверность экземпляра — отдельный вопрос и отдельный проект. |
| `is` `!is` | Вопрос принадлежит **правому** операнду, и отвечает на него `ClassValue.matches` — механизм расширения там уже есть, свой класс от приложения отвечает на `is` по-своему. Второго механизма заводить незачем. |
| `!=` `!in` `!has` | Выводятся отрицанием. Объяви их отдельно — и однажды `a == b` и `a != b` окажутся истинны одновременно. |
| `=` `+=` `-=` `*=` … | Присваивание — инструкция, а не выражение, это решение языка. При этом `p += q` **уже** зовёт член `+`: составное присваивание проходит через ту же `Operations.binary`. Отдельного члена для него не бывает и не надо. |
| `?:` `??` `?.` | Управление, а не операция над значениями. |

## 4. Нет в языке (и в этом проекте не заводятся)

`**`, `//`, `<=>` как **оператор выражения**, `++`, `--`, `===`, `!==`, `<>`,
`::`, `->`, `=>` как перегружаемые, `[]`, `()`.

Индексация `[]` и вызов `()` — не «ещё две строки в таблицу», а столкновение
с двумя решениями языка: `x.name` ≡ `x["name"]` (у экземпляра `[]` — это уже поиск
члена) и «функция — обычное значение». Каждое из них — отдельный проект.

Символ `<=>` в языке отсутствует как оператор и живёт **только именем члена**.
Так сделано нарочно: обычное имя вроде `compare` столкнулось бы с методом, который
пользователь завёл сам, а `` `<=>` `` не столкнётся ни с чем и сразу читается как
«группа сравнений». Появится когда-нибудь оператор — он уже реализован.

## Оговорки, о которые спотыкаются

**Строка съедает `+`.** `"total: " + point` — это конкатенация, а не ошибка:
ядро превращает в строку что угодно. Значит член `+` у класса **никогда** не увидит
строку справа, и переопределить это нельзя. Хотите своё представление — это
`display`, а не оператор.

**Исключений из правила запасного пути ровно два, и оба об одном.** Ядро не падает
ни на равенстве, ни на принадлежности — оно молча отвечает **не о том**, потому что
экземпляр класса это объект. Поэтому у обоих операторов член спрашивается раньше ядра,
когда слева (для `==`) или в контейнере (для `in`) стоит не «простое» значение.

**`==` не падает, поэтому у него исключение из правила.** Ядро сравнивает по ссылке
и молча отвечает `false`, а не бросает ошибку, — запасному пути нечего ловить.
Правило поэтому такое: **для `==` и `!=` ядро отвечает само, только когда оба
операнда — числа, строки, логические или `null`; во всех прочих случаях сперва
спрашивается член `==`, и лишь если его нет — сравнение по ссылке, как сегодня.**
Это единственное исключение во всей таблице. Упорядочивание (`<` и прочие) исключения
не требует: `Operations.order` на паре экземпляров честно бросает ошибку.

**Четыре сравнения — один член.** `<=>` возвращает число (отрицательное, ноль,
положительное) и кормит `<`, `<=`, `>`, `>=`, **`a.sort()`** и **`a.sorted`**: сортировка ходит в ту же
`Operations.order`, что и оператор. Требуй язык четыре отдельных метода — они однажды
разошлись бы между собой, а `a.sort()` разошёлся бы с `a[0] < a[1]`, и объяснить такое
расхождение нечем.

**`in` и `has` — один член и без `mirror`.** Это две записи одного отношения
(`x in c` ≡ `c has x`), и в ядре у них одна реализация — `Operations.contains`.
Член объявляется **на контейнере** и принимает предмет, а какой стороной написано
выражение, значения не имеет:

```wdl
class Deck(cards) {
    def `in`(card) => card in cards
}

d = new Deck(["ace", "king"])
if ("ace" in d) ...       // зовёт член 'in' у Deck
if (d has "ace") ...      // зовёт его же
if ("joker" !in d) ...    // и его же, ответ отрицается
```

`mirror` здесь запрещён именно потому, что обе стороны уже есть в грамматике:
второй способ записать то же самое породил бы два разных ответа на один вопрос.

**`in` у экземпляра спрашивается раньше ядра** — по той же причине, что и `==`:
экземпляр это объект, и ядро молча ответило бы, есть ли у него такое **поле**.
Ловить тут нечего, а молчаливый ответ не о том хуже ошибки. Поэтому пример с `Deck`
выше работает, хотя формально «контейнер — объект». Тем же членом отвечает и
`d.has(x)`.

**Перегрузка `in` не делает класс перебираемым.** `for (x in deck)` — протокол
перебора, отдельная вещь; экземпляр в нём по-прежнему идёт по своим полям.

**Расширение работает так же, как объявление в классе.**

```wdl
extend Point {
    def `*`(right) => new Point(x * right, y * right)
    mirror def `*`(left) => new Point(left * x, left * y)
}

p = new Point(1, 2)
a = p * 23          // член '*' у Point
b = 23 * p          // зеркальный '*' у Point: 23 не умеет умножаться на точку
c = 24 * 23         // 552: ядро справилось само, ничего не спрашивалось
```

Последняя строка — и есть правило запасного пути в одной строке кода.

## Что ещё оказалось важным при реализации

* **Ключ члена мангленный у двух видов операторов**: зеркало — `"+@"`, унарный —
  `"+()"`. Написать такие имена нельзя (белый список отвергнет), а таблица методов
  ключуется строкой — значит и зеркальность, и арность обязаны попасть в ключ.
  Собирает их одна функция, `ast.op.Overloads.key`.
* **Равенство массива берёт тот же член.** `a.contains(p)` и `a.indexOf(p)` сравнивают
  элементы через `==` класса — иначе `p in points` и `p == points[0]` разошлись бы.
* **Операторы у классов от приложения работают сами.** Метод `NativeClass` с именем
  `"+"` (или `"<=>"`, или мангленным ключом зеркала) становится оператором без единой
  строки в ядре: поиск идёт по той же таблице методов. См. `docs/embedding.md`.

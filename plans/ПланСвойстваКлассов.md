# План: свойства классов и трейтов

Рабочий журнал реализации. Замысел — в [`Основные идеи.md`](../Основные%20идеи.md),
раздел «Свойства классов».

Отметки: `[ ]` не начато, `[~]` в работе, `[x]` сделано и проверено сборкой.

---

## Решения, принятые до начала

Замысел оставляет их открытыми; без ответа этап 2 не пишется.

1. **`property` — контекстное слово, не ключевое.** Член тела класса иначе может
   начаться только с `def` или `synchronized`, поэтому двусмысленности нет,
   а `property` остаётся законным именем переменной в чужих скриптах.
2. **`field` — имя, которое заводит область аксессора**, как `this`. Лексер и парсер
   не трогаются вовсе. Причина не только в чистоте: `field` уже используется обычным
   именем в `examples/classes.wdl` и `examples/hello.wdl`, и ключевое слово сломало бы их.
3. **Скрытое поле лежит вне карты пар экземпляра.** Иначе правило «сначала собственное
   поле» побеждает и геттер не вызывается никогда, а `x` попадает в перебор, в `len`
   и в печать. Отдельное хранилище на экземпляре — под своим замком, по инварианту 3.
4. **Свойство и поле — одна ячейка имени**, побеждает последний, как и во всех плоских
   таблицах. **Свойство и метод — конфликт**, ошибка связывания: это разные виды членов,
   и молчаливый выбор одного из двух здесь ничем не оправдан.
5. **`obj["area"]` зовёт геттер.** Инвариант «`x.name` ≡ `x["name"]`» сильнее удобства;
   цена — обращение по вычисленному ключу может выполнить чужой код.
6. **Голое имя внутри метода работает через свойство** и на чтение, и на запись:
   `size` ≡ `this.size`, одно правило на обе записи.
7. **Аксессоры без модификаторов и без декораторов.** `def get()` — ровно ноль
   параметров, `def set(value)` — ровно один, без значений по умолчанию и без остатка.
   `synchronized` на аксессоре запрещён: замок экземпляра берётся `synchronized`-методом,
   а свойство читают внутри выражения, где он всё равно ничего не склеит.
8. **Свойство без геттера запрещено.** Значение, которое нельзя прочитать, в скриптовом
   языке — приглашение к опечатке. Только сеттер — ошибка разбора.
9. **Свойство перебором не видно.** Его нет среди пар, поэтому `for (k in obj)`, `len`,
   печать и равенство его не показывают — ровно как не показывают метод.
10. **Атомарность на свойство не распространяется.** Обращение к свойству — вызов кода,
    и обещание «одно обращение атомарно» здесь не действует.

## Этап 1. Дерево и разбор

- [x] 1.1 `ast/stmt/PropertyDecl` — `record`, а не `Stmt` (образец: `ast/expr/Decorator`):
      имя, `nameSpan`, `initial` (`Expr` или `null`), `getter`, `setter`, `style`, `span`
- [x] 1.2 `PropertyDecl.Accessor` — `record(FunctionExpr function, Span span)`;
      `function == null` значит требование трейта. Отдельный вид по той же причине,
      по которой отдельно живёт `TraitDeclStmt.Requirement`: функции без тела в языке нет
- [x] 1.3 `ast/stmt/PropertyStyle` — `ARROW` / `BLOCK`, для форматтера (образец `AccessStyle`)
- [x] 1.4 `ClassDeclStmt` и `TraitDeclStmt` — поле `List<PropertyDecl> properties`
- [x] 1.5 `TypeParser.member` — ветка на контекстное слово `property`; короткая форма
      `property area => выражение` и блочная с `def get()` / `def set(value)`
- [x] 1.6 `TypeParser` — начальное значение `property x = 0 { ... }` разбирается
      выражением до `{`
- [x] 1.7 Диагностика разбора: параметры у `get`, не один параметр у `set`, остаток
      или значение по умолчанию у аксессора, `synchronized` перед `property`, декоратор
      на свойстве, свойство без `get`, требование без тела в классе, повтор имени
      (тот же `Members.taken`, что у методов), пустое тело `property x { }`
- [x] 1.8 Тесты: `ClassParserTest` — форма дерева через `SExprPrinter`;
      `ErrorParserTest` — каждое сообщение из 1.7

## Этап 2. Форма (`resolve`)

- [x] 2.1 `resolve/PropertySlot` — имя, объявление, владелец, есть ли геттер, сеттер,
      скрытое поле
- [x] 2.2 `Shape.properties()` — третья плоская таблица; реализация в `ClassShape`,
      `ScriptTraitShape`, `NativeTraitShape`
- [x] 2.3 `ClassShape` — сборка в том же порядке «родитель → трейты → сам класс»
- [x] 2.4 `ClassShape` — правило одной ячейки: свойство вытесняет одноимённое поле
      из `fields()` и наоборот; порядок печати остаётся от первого вхождения
- [x] 2.5 `Linker` — `LinkError` на «свойство и метод под одним именем»
- [x] 2.6 Тесты `ClassTest`: свойство поверх поля родителя, поле поверх свойства
      родителя, конфликт с методом

## Этап 3. Значение и выполнение

- [x] 3.1 `value/Property` — интерфейс: `readable()`, `writable()`,
      `read(InstanceObjectValue, CallContext, Span)`, `write(...)`.
      В `value`, потому что реализаций две и вторая живёт в `embed`
- [x] 3.2 `ClassValue.property(String name)` — новый метод интерфейса; реализуют
      `WdlClass` и `NativeClass`
- [x] 3.3 `InstanceObjectValue` — хранилище скрытых полей отдельно от `entries`,
      под собственным коротким замком; у вида `super` — то же самое хранилище,
      как и карта пар
- [x] 3.4 `runtime/WdlProperty` — геттер и сеттер как `UserFunction` поверх
      `InstanceScope`; кадр называется `Rect.area (get)`, чтобы трассировка показывала
      свойство, а не пустоту
- [x] 3.5 `runtime/PropertyScope` (или флаг в `Method`) — имя `field` внутри аксессора
      свойства со скрытым полем; вне такого свойства имени нет
- [x] 3.6 `Interpreter.read` — ветка `InstanceObjectValue` **до** `MapValue`:
      поле → свойство → метод → `null`
- [x] 3.7 `Interpreter.write` — ветка `InstanceObjectValue` **до** `MapValue`:
      поле → сеттер → ошибка «только для чтения» (`ErrorKind.DECLARATION`) →
      обычная запись
- [x] 3.8 `InstanceScope.lookup` и `InstanceScope.assign` — свойство между полем
      и методом; запись без сеттера — та же ошибка, что и через точку
- [x] 3.9 Проверка, что составное `window.width += 100` даёт ровно один вызов геттера
      и один сеттера: `ContainerPlace` разрешает место один раз, поэтому нужен тест,
      а не правка
- [x] 3.10 Тесты `PropertyTest`: чтение, запись, только чтение, скрытое поле,
      `obj["имя"]`, голое имя в методе, `super.свойство`, наследование, рекурсия
      геттера, побочный эффект геттера один раз на обращение

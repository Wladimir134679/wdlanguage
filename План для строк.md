# План: многострочные строки и интерполяция

Три порции, строго по порядку: `"""` самодостаточна, интерполяция опирается
на новый узел дерева, `'''` собирается из готового.

Отметка `[x]` ставится, когда шаг сделан и сборка зелёная.

---

## План A. Многострочные строки `"""`

Новых токенов, узлов и посетителей нет: `Token.text` для `STRING` и так несёт
развёрнутое значение, поэтому вся фича живёт в лексере.

- [x] **A1. `lexer/TextBlocks.java`** — снятие отступа чистыми статическими
      функциями (по образцу `Nodes`: без состояния, годно для любого потока).
- [x] **A2. Разбор блока в `Lexer.string()`** — развилка `peek(1)=='"' && peek(2)=='"'`
      → `textBlock()`. Три фазы, и порядок принципиален (он же в спецификации Java):
      1. чтение сырого текста до закрывающих `"""`, нормализация `\r\n` и `\r` → `\n`;
         собирается список строк со смещениями в исходнике — они нужны третьей фазе;
      2. снятие отступа: минимум по непустым строкам и по строке с закрывающим
         разделителем, срез хвостовых пробелов;
      3. разворот escape — **последним**, тем же `escape()`, что и у обычной строки.
         Слить фазы нельзя: написанный автором `\n` не должен влиять на отступ.
         Плюс `\` перед переводом строки = склейка, `\s` = защищённый от среза пробел.
- [x] **A3. Диагностика** — незакрытый блок до конца файла (`UNCLOSED_STRING`,
      прецедент `BLOCK_COMMENT`); нет перевода строки после открывающих `"""`;
      предупреждение на смешение табов и пробелов в отступе.
- [x] **A4. Тесты** — `TextBlocksTest` на алгоритм отступа, `LexerTest` на значение,
      CRLF, escape, склейку и обе ошибки.
- [x] **A5. `examples/strings.wdl`** — новый пример; он же втягивает блок
      в `LosslessLexerTest` и `AstInvariantTest` через `Corpus.examples()`.
- [x] **A6. `docs/types.md`** — раздел «Строка»: запись, правило отступа,
      нормализация переводов строк и её причина (Windows-чекауты); строка в таблице
      литералов.

Готово, когда: `./gradlew build` зелёный, `--tokens examples/strings.wdl` показывает
один `STRING` с экранированным значением.

## План B. Интерполяция `'...'` с `${...}`

- [x] **B1. Токены** — `STRING_START`, `STRING_PART`, `STRING_END` (`Kind.VALUE`).
      Текст — развёрнутый кусок, span — исходное написание. Разделители `${` и `}`
      входят в span соседних кусков, своих токенов не образуют.
      Строка без единой дырки выдаёт обычный `STRING` — тогда `import 'lib/math'`
      и `'ключ': 1` работают, а интерполяция в таких позициях даёт внятную ошибку.
- [x] **B2. Лексер со стеком кадров** — `ArrayDeque<Frame>`, `Frame(multiline, braces)`.
      `{`/`}` внутри дырки ведут счётчик, поэтому объект в дырке разбирается верно.
      Перевод строки внутри дырки однострочной строки — ошибка: иначе одна опечатка
      съедает остаток файла. Вложенность получается даром.
- [x] **B3. Узел `InterpolationExpr(List<Expr> parts, Span span)`** — части однородны,
      текстовые куски лежат как `LiteralExpr`, пустые не хранятся. Цепочкой `+`
      разложить нельзя: `'${a}${b}'` на двух числах дало бы сложение.
      Правится `permits` в `Expr`, `ExprVisitor`, `Nodes.collect`.
- [x] **B4. Посетители** — `Interpreter.visitInterpolation` (`display()` каждой части,
      новой семантики не заводим), `DefaultValues.findUse` (обход частей),
      `AstDumper`, тестовый `SExprPrinter` (форма `(str "Привет, " name "!")`).
      Без компиляторной проверки одно место: `ReceiverResolver.resolve` — там `default`,
      и без ветки `'...'.upper` перестанет дополняться.
- [x] **B5. Парсер** — `case STRING_START` в `prefix()`, части до `STRING_END`,
      между ними обычный `expression(0)`. Битая дырка не съедает остаток строки.
      `TokenCursor.describe` — русские названия трёх новых видов.
- [x] **B6. Диагностика промаха между кавычками** — `${` внутри `"..."` даёт
      предупреждение с кодом `LITERAL_INTERPOLATION`: у кода сразу есть потребитель —
      быстрая правка «заменить кавычки».
- [x] **B7. Инструменты** — `Highlights.styleOf` (три вида → `TokenStyle.STRING`),
      `TokenDumper.displayValue` (экранированная ветка). LSP и плагин не трогаются.
- [x] **B8. Тесты** — `LexerTest` (поток, объект в дырке, вложенная строка, строка
      без дырок = `STRING`, обе ошибки, предупреждение), `ParserTest` (форма дерева),
      интерпретатор (числа, `null`, массив, экземпляр со своим `display`, вызов).
- [x] **B9. Документация и пример** — основной раздел лёг в `docs/types.md`, рядом
      с многострочной строкой (там же живёт «Строка»), а в `docs/expressions.md`
      осталась ссылка из абзаца про `+`: почему `'`, почему `${}`,
      что вставка это `display`, почему литеральные позиции её не принимают;
      дополнение `examples/strings.wdl`.

Готово, когда: сборка зелёная, внутри `${...}` работают переход к определению
и подсветка имени по роли — это и есть проверка, что выбран лексерный путь.

## План C. `'''` — многострочная с подстановкой

- [x] **C1. Флаг `multiline` в кадре** — включить для `'''`; перевод строки
      не завершает строку, закрывают её `'''`.
- [x] **C2. Отступ** — `TextBlocks` из плана A, но в подсчёте участвуют **только
      строки текстовых кусков**: выражение, записанное в дырке «в столбик»,
      не должно сдвигать весь блок.
- [x] **C3. Escape** — по каждому текстовому куску отдельно, после снятия отступа.
- [x] **C4. Тесты** — блок с дыркой, отступ при дырке в начале строки, дырка
      с переносом внутри.
- [x] **C5. Пример и документация** — третий фрагмент в `examples/strings.wdl`,
      абзац в `docs/types.md` со ссылкой на правило отступа.

## Что вышло по факту

Три порции сделаны, `./gradlew build` зелёный.

* **A.** `lexer/TextBlocks` плюс путь `textBlock()` в лексере; ни токенов, ни узлов
  не добавилось — контракт «текст токена уже развёрнут» это позволил.
* **B.** Три вида токенов, стек подстановок в лексере, узел `InterpolationExpr`
  и разбор в `Parser.interpolation()`. Компилятор провёл по `Nodes`, `ExprVisitor`,
  `Interpreter`, `DefaultValues`, `AstDumper` и `SExprPrinter`; вручную добавлена
  только ветка в `ReceiverResolver` — там `default`.
* **C.** Куски многострочной строки ставятся в поток пустыми, а текст получают
  на закрывающих кавычках: отступ до них неизвестен. Отсюда `Block`/`Chunk`
  в лексере и второй `TextBlocks.indent(lines, lastIsClosing)`.

Два уточнения к анализу, всплывшие при работе:

* **Своей печати у экземпляра класса пока нет** — `display()` у значения чистая
  и метода не спрашивает (`docs/classes.md`). Поэтому подстановка обещает не
  «уважает display класса», а «вставляет ровно то же, что конкатенация», и тест
  проверяет именно равенство `'${p}'` и `"" + p`.
* **Ключ объекта с подстановкой работает** — ключ там любое выражение. Литерал
  обязателен только в пути `import`, и об этом сказано в `docs/types.md`.

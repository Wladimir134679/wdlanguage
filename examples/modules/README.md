# Пробы модулей

Сценарии по одному на файл: каждый запускается отдельно и показывает одну грань
`import`. Правила языка описаны в [docs/modules.md](../../docs/modules.md).

```bash
./gradlew :wdl-cli:installDist
wdl-cli/build/install/wdl/bin/wdl examples/modules/plain.wdl
```

Путь модуля считается **от корня проекта (по умолчанию каталога главного скрипта)**, поэтому
запускать примеры можно откуда угодно — не только из корня репозитория.

## Что работает

| Файл | О чём |
|---|---|
| [plain.wdl](plain.wdl) | развёрнутый импорт: имена модуля становятся своими |
| [named.wdl](named.wdl) | именованный импорт, `typeof`, обращение точкой и скобками, `new g.Point(...)` |
| [scoped.wdl](scoped.wdl) | импорт внутри функции и внутри блока — и его исчезновение на выходе |
| [once.wdl](once.wdl) | модуль выполняется один раз за запуск; общее живое состояние; `is` между двумя импортами |
| [nested.wdl](nested.wdl) | модуль импортирует соседа по короткому имени |
| [inherit.wdl](inherit.wdl) | наследование и трейты через файлы: `: Shape`, `: s.Shape`, `with s.Countable`, `super`, `is`, родитель выражением (`s.kinds["shape"]`, `s.kindFor("shape")(...)`), наследник внутри функции |
| [late.wdl](late.wdl) | модуля нет на диске, и скрипт всё равно работает; плагин с классом и трейтом загружается по требованию |
| [mutate.wdl](mutate.wdl) | модуль изменяем снаружи: запись видят его функции и обе формы импорта |

Модули лежат в [lib/](lib): `geometry` (константа, функция, класс), `counter`
(состояние и побочный эффект при загрузке), `strings` (сам импортирует `geometry`),
`shapes` (класс и трейт, от которых наследуются), `plugin` (наследуется от `shapes`
и реализует его трейт — грузится по требованию), `faulty` (нужен для сценария
с ошибкой).

## Что должно падать

Каждый файл в [errors/](errors) останавливается ровно на одной ошибке — это и есть
проверяемый результат. Код возврата `1`.

| Файл | Ожидаемое сообщение |
|---|---|
| [errors/missing.wdl](errors/missing.wdl) | `модуль 'lib/nothing' не найден` |
| [errors/cycle.wdl](errors/cycle.wdl) | `циклический импорт: ring/a → ring/b → ring/a` |
| [errors/unknown-member.wdl](errors/unknown-member.wdl) | `в модуле '../lib/geometry' нет имени 'aria'` |
| [errors/const.wdl](errors/const.wdl) | `'PI' нельзя присвоить: это константа` — изменять модуль можно, `const` в нём остаётся `const` |
| [errors/unknown-assign.wdl](errors/unknown-assign.wdl) | `в модуле '../lib/geometry' нет имени 'aria'` — присваивание не заводит новых имён |
| [errors/inside-module.wdl](errors/inside-module.wdl) | `деление на ноль` — **с местом в `lib/faulty.wdl`**, а не в запущенном файле |
| [errors/inherit-before-import.wdl](errors/inherit-before-import.wdl) | `неизвестный класс 'Shape'` — тип из модуля виден только ниже своего `import` |

Все они находятся **при выполнении**, на своей строке: и ненайденный модуль, и ошибка
внутри модуля, и неизвестный родитель. Строки выше успевают отработать — в двух файлах
это видно прямо в выводе. Иначе и быть не может: `import` читает файл тогда, когда
до него доходит очередь, а класс связывается с родителем тогда, когда объявляется.

Файлы из `errors/` добираются до `lib/` через `"../lib/имя"` — заодно видно, как
выглядит путь вверх. В обычном коде так лучше не писать: ключ модуля тогда содержит
`..`, и тот же файл, найденный из другого места коротким путём, окажется для движка
другим модулем.

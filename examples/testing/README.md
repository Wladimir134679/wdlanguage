# Тесты на самом языке

Движок тестов, написанный на wdl, и наборы проверок на нём. Ничего особенного
от языка он не требует: **проверка — это обычная функция, которая бросает ошибку,
а набор — обычный класс, который её ловит.** Всё, на чём это держится, уже есть:
функция как значение, класс, `throw`/`catch` и то, что у пойманной ошибки есть
текст, место и путь по скрипту.

```bash
./gradlew :wdl-cli:run --args="examples/testing/basics.wdl"
./gradlew :wdl-cli:run --args="examples/testing/errors.wdl"
./gradlew :wdl-cli:run --args="examples/testing/resources.wdl"
```

| Файл | О чём |
|---|---|
| [lib/test.wdl](lib/test.wdl) | сам движок: проверки, набор `Suite`, отчёт |
| [basics.wdl](basics.wdl) | как им пользоваться: все проверки по очереди и как выглядит провал |
| [errors.wdl](errors.wdl) | 33 проверки по обработке ошибок: иерархия, `catch`, `finally`, `try?`, `cause`, трассировка |
| [resources.wdl](resources.wdl) | 19 проверок по ресурсам: `defer`, `use`, `Closeable`, потоки `sys.io` |

## Как это выглядит

```wdl
import lib.test as t

suite = new t.Suite("арифметика")

suite.test("деление на ноль — ошибка, а не inf", fun() {
    e = t.assertThrows(ArithmeticError, fun() => 1 / 0)
    t.assertContains(e.message, "деление на ноль")
})

suite.run()
```

```
── арифметика
  ok   деление на ноль — ошибка, а не inf
  итого: 1 ok
```

## Три исхода, а не два

Набор различает «проверка не сошлась» и «тест сломался по дороге», и это не
формальность: первое — результат, второе — дефект самого теста, и лечатся они
по-разному. Поэтому у ошибки проверки свой класс:

```wdl
class AssertionError(message) : Exception(message)
```

`Suite.run` ловит его отдельным `catch`, а всё остальное — общим, и для второго
печатает место и путь по скрипту:

```
  FAIL сумма считается верно
       значение: ожидалось 4, получено 5
  ERR  разбор не падает на пустом вводе
       IndexError: индекс 9 вне границ массива размером 2
       в examples/testing/basics.wdl:105:13
         в fun (examples/testing/lib/test.wdl:179:13)
         в runOne (examples/testing/lib/test.wdl:171:13)
```

## Что проверяется значением, а что ссылкой

`assertEquals` сравнивает **по значению**, обходя массивы и объекты вглубь
(`deepEquals` в движке). Язык сравнивает их по ссылке — и правильно делает, —
но тесту нужно другое: ожидаемое значение в тесте всегда новое. Когда важна
именно ссылка, есть `assertSame`.

## Чего движок не умеет

* **Не считает время и не сортирует наборы** — это не нужно, пока наборы
  запускаются глазами.
* **Не даёт кода возврата процессу**: `run()` возвращает признак успеха значением,
  а сделать из него `exit code` скрипт пока не может. Для проверки на сборке
  этого хватит, когда у языка появится способ сказать хосту «я не прошёл».
* **Не различает «поля нет» и «поле равно null»** при сравнении объектов —
  честная цена за пятнадцать строк `deepEquals`.

## Что не ловится

Прерывание потока, исчерпание стека и слишком глубокая рекурсия — не `Exception`,
и обработчик их не видит. Проверить это набором нельзя по построению: тест,
который «поймал» остановку выполнения, тем самым доказал бы обратное. Поэтому
такие случаи лежат в [fatal/](fatal) — эти два файла **обязаны падать**:

| Файл | Чем кончается |
|---|---|
| [fatal/recursion.wdl](fatal/recursion.wdl) | `слишком глубокая рекурсия` — `catch` не сработал, `finally` выполнился |
| [fatal/forced.wdl](fatal/forced.wdl) | `здесь ошибки быть не должно ('try!')` — рядом видно, что `try?` на том же месте даёт `null` |

# Примеры

Каждый файл запускается отдельно и показывает одну тему целиком. Всё, что здесь
написано, **работает**: примеры прогоняются как есть, а строки, которые должны падать,
оставлены закомментированными вместе с текстом ошибки.

Файлы сгруппированы по темам в подкаталоги — так проще ориентироваться, чем
в одном списке из четырёх десятков файлов.

```bash
./gradlew :wdl-cli:installDist
wdl-cli/build/install/wdl/bin/wdl examples/language/hello.wdl

# или без сборки дистрибутива
./gradlew :wdl-cli:run --args="examples/language/hello.wdl"
```

## [language/](language) — язык

| Файл | О чём |
|---|---|
| [hello.wdl](language/hello.wdl) | переменные, объекты, массивы, вывод — с чего начать |
| [types.wdl](language/types.wdl) | типы значений: `typeof` возвращает дескриптор, `is` по всем типам, `typeof(x) == Тип` против `is`, дескриптор как обычное имя |
| [strings.wdl](language/strings.wdl) | строки: экраны, многострочный литерал и снятие отступа, подстановка `${...}` в одинарных кавычках, многострочная с подстановкой |
| [expressions.wdl](language/expressions.wdl) | шпаргалка по выражениям: числа, биты, сравнения, принадлежность `in`/`has`, диапазоны, обращение |
| [control-flow.wdl](language/control-flow.wdl) | `if`, `while`, `for`, перебор (в том числе по диапазону и с ключом), `break`/`continue`, области блока |
| [match.wdl](language/match.wdl) | `match` выражением и инструкцией: образцы, перечисление, условия в ветках, `else`, значение ветки через `yield`, что бывает ошибкой |
| [unpack.wdl](language/unpack.wdl) | распаковка `x, y = *point` и `host, port, **rest = **config`, остатки, пропуск `_`, перебор с ключом |
| [slices.wdl](language/slices.wdl) | срез `a[1..3]` и отрицательный индекс `a[-1]`: включительные границы, подрезка, копия, ключ-диапазон у объекта |
| [const.wdl](language/const.wdl) | `const`: заморожено имя, а не содержимое |
| [functions.wdl](language/functions.wdl) | объявления, `return`, `=>`, анонимные функции, замыкания |
| [defaults.wdl](language/defaults.wdl) | значения параметров по умолчанию и когда они вычисляются |
| [named-args.wdl](language/named-args.wdl) | `f(name: value)`: пропуск в середине, свободный порядок, имена в `new` |
| [variadic-args.wdl](language/variadic-args.wdl) | `*args` и `**named` в заголовке, раскрытие `f(*array)` и `f(**object)`, проброс вызова |

## [classes/](classes) — классы и трейты

Три файла по возрастанию: сначала один класс, потом цепочка, потом контракты.

| Файл | О чём |
|---|---|
| [members.wdl](classes/members.wdl) | члены значений: свойства и методы у массива, строки, числа и объекта |
| [introspection.wdl](classes/introspection.wdl) | что значение рассказывает о себе: параметры функции, состав класса, трейты |
| [extend.wdl](classes/extend.wdl) | `extend`: свои члены у типа и у класса, и четыре запрета вокруг него |
| [operators.wdl](classes/operators.wdl) | перегрузка операторов: `` `+` ``, `mirror`, группы `` `==` ``/`` `<=>` ``/`` `in` ``, унарные, оператор в трейте и в `extend` |
| [classes.wdl](classes/classes.wdl) | поля и методы, `this`, конструктор, фабрики, класс как значение, класс внутри функции |
| [properties.wdl](classes/properties.wdl) | вычисляемое свойство: `get`/`set`, только чтение, скрытое поле за именем |
| [inheritance.wdl](classes/inheritance.wdl) | `: Родитель(...)`, `super`, виртуальные вызовы, цепочка из трёх уровней, полиморфизм, `is` |
| [traits.wdl](classes/traits.wdl) | трейт-контракт, готовые реализации, состояние в трейте, несколько трейтов, «побеждает последний», момент проверки требований |
| [class-varargs.wdl](classes/class-varargs.wdl) | остаток в заголовке `*args`/`**named`, переброска родителю, почему остаток не поле |

Правило, вокруг которого построен файл про трейты: **требование трейта проверяется
при объявлении класса**, а не при создании экземпляра. Объявлен класс — значит,
он уже проверен.

## [metaprogramming/](metaprogramming) — декораторы и аннотации

| Файл | О чём |
|---|---|
| [decorators.wdl](metaprogramming/decorators.wdl) | `@[...]` на функции и классе, метаданные, регистрация и обёртка, порядок применения, `like`, `sys.meta` |
| [annotations.wdl](metaprogramming/annotations.wdl) | `@{...}` на объявлении, методе, свойстве и параметре, роутинг с декоратором, валидация и отчёт по одним данным, `Cls.method`/`Cls.property` |

Правило, которое стоит унести из декораторов: **применяются снизу вверх**, поэтому
не оборачивающие декораторы ставятся ближе к `def`, чем оборачивающие.

Правило, которое стоит унести из аннотаций: **аннотация — данные, а не действие**.
Один потребитель в момент объявления — это декоратор; несколько и потом —
это аннотация.

## [errors/](errors) — ошибки и ресурсы

| Файл | О чём |
|---|---|
| [errors.wdl](errors/errors.wdl) | `throw`, `try`/`catch`/`finally`, короткие формы `try?` и `try!`, ловля по классу и по трейту, цепочка `cause`, путь по скрипту |
| [resources.wdl](errors/resources.wdl) | `defer`, `use`, трейт `Closeable`, потоки `sys.io` |

Правило, вокруг которого построены оба файла: **освобождение пишется рядом
с захватом**. Отложенное действие записывается после успешного захвата, поэтому
проверок «а был ли ресурс» не нужно — в отличие от `finally`, который существует
независимо от того, дошло ли дело до `open`.

## [concurrency/](concurrency) — потоки

| Файл | О чём |
|---|---|
| [threads.wdl](concurrency/threads.wdl) | `th.spawn`, `join`, `interrupt`, `sleep`, `synchronized def`, `th.counter` |
| [threads_pool.wdl](concurrency/threads_pool.wdl) | пул и `use`, `pool.map`, `pool.submit` с таймаутом и ошибкой, канал, замок, защёлка |

Правило, вокруг которого построены оба файла: **атомарно одно обращение, а не
выражение**. `count = count + 1` из двух потоков теряет обновления, и склеивают
эти два обращения `synchronized def`, `th.lock()` или `th.counter()` — см.
[docs/threads.md](../docs/threads.md).

Чат [chat_server.wdl](concurrency/chat_server.wdl)/[chat_client.wdl](concurrency/chat_client.wdl) — тот же приём на живом примере:
клиенты обслуживаются в своих потоках, а общий список защищён `synchronized`.
Сервер не прогоняется на сборке — занимает порт.

## [tooling/](tooling) — профиль и отладка

| Файл | О чём |
|---|---|
| [profiling.wdl](tooling/profiling.wdl) | рекурсия, цикл, функция-раздатчик и создание экземпляра — то, что по-разному выглядит в `--profile` |
| [debugging.wdl](tooling/debugging.wdl) | скрипт, по которому удобно шагать: кадры и локальные переменные, вложенные вызовы, поля экземпляра, ошибка и второй поток |

`profiling.wdl` стоит запускать с флагом: `wdl --profile examples/tooling/profiling.wdl`.
Смысл примера в различии «всего» и «сам» — у `report` первое велико, а второе почти
нулевое: время ушло в то, что он позвал. См. [docs/profiling.md](../docs/profiling.md).

Своего синтаксиса у отладки нет — точки останова ставит тот, кто отлаживает
(приложение через `script.debugger()`), поэтому `debugging.wdl` просто выполняется
как есть. Что где смотреть, написано в его комментариях; правила — в
[docs/debugging.md](../docs/debugging.md).

## [embedding/](embedding) — то, что дала сторона Java

| Файл | О чём |
|---|---|
| [stdlib.wdl](embedding/stdlib.wdl) | `pow`, `sqrt`, классы `File` и `Random`, фабрика `File.temp()`, поле класса; два способа написать библиотеку — построитель и мост |
| [embedding.wdl](embedding/embedding.wdl) | трейт-контракт от модуля (`json.Serializable`), иерархия нативных классов (`io.Stream`), ошибки библиотек по классам, изоляция запусков |
| [sys.wdl](embedding/sys.wdl) | встроенные модули: `sys.json` и `sys.io` — библиотеки на Java, приходящие через `import` |
| [java-time.wdl](embedding/java-time.wdl) | мост в Java: `sys.time` — семь чужих типов `java.time` без единого описанного метода |

Правило, вокруг которого построены первые два файла: **скрипт не видит разницы**.
Класс на Java — такой же класс, трейт — такой же трейт, требование проверяется
на строке `class`, ошибка ловится обычным `catch` по классу. Разницу видно ровно
в одном месте — в том, что состояние этих классов не переживает свой запуск.

`sys.net.http` в примерах не показан намеренно: они прогоняются на сборке,
а сеть в ней может быть недоступна. Как он выглядит — в [docs/modules.md](../docs/modules.md).

## Игра

Примера игры здесь нет, и это нарочно: пинг-понг — не скрипт, который запускают,
а приложение, внутри которого скрипты живут. Игра написана на Java в модуле
`wdl-game`, её правила — четыре файла в ресурсах этого модуля
(`wdl-game/src/main/resources/ru/wds/wdl/game/pong/`), и играются они запуском

```bash
./gradlew :wdl-game:run
```

Читать их стоит именно там: `rules.wdl` — подача и отскок, `rival.wdl` — соперник,
`hud.wdl` — счёт и надписи. Подробности — в [docs/game.md](../docs/game.md).

## Тесты на самом языке

Отдельная папка со своим описанием: [testing/](testing) — движок тестов,
написанный на wdl, и полсотни проверок на нём. Заодно это самый плотный пример
работы с ошибками: проверка — обычная функция, которая бросает, а набор —
обычный класс, который ловит.

## Модули

Отдельная папка со своим описанием: [modules/](modules) — `import` в обеих формах,
области видимости, наследование через файлы, загрузка плагина по требованию
и набор сценариев, которые должны падать.

## [lexer/](lexer) — лексер

Эти два файла — единственные, которые не запускаются: они написаны для `--tokens`,
а не для выполнения.

```bash
wdl --tokens examples/lexer/lexer-check.wdl
wdl --tokens examples/lexer/lexer-errors.wdl
```

| Файл | О чём |
|---|---|
| [lexer-check.wdl](lexer/lexer-check.wdl) | все виды литералов и имён, включая кириллические |
| [lexer-errors.wdl](lexer/lexer-errors.wdl) | как выглядят сообщения лексера: разбор не прерывается на первой ошибке |

Идентификаторы в примерах английские, комментарии и строки — русские. Кириллица
в именах языком поддерживается (это видно в `lexer-check.wdl`), но в примерах
её не демонстрируют.
